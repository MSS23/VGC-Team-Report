# R6 — SEO Audit, 22 May 2026

Scope: code-level audit of `src/app/sitemap.ts`, `src/app/layout.tsx`, `public/llms*.txt`, and per-page `metadata` blocks. Goal: identify quick wins (<2h of code each, no new content, no DB changes) that are NOT already in production, and pinpoint keyword gaps vs Pikalytics / PokePaste / VGCpastes.

## What's already in prod (so we don't repeat past audits)

Recent SEO ship list (from `ChangelogContent.tsx` and direct file inspection):

- `sitemap.ts` covers `/`, `/explore`, `/champions`, `/faq`, `/tournaments`, `/changelog`, `/privacy`, `/terms`, `/feedback`, all `/champions/[mega-slug]` pages, top-5000 public `/s/[id]`, and every `/creator/[name]` with public shares.

- `llms.txt` + `llms-full.txt` (full content audit done — both files are well-structured per llmstxt.org spec).
- Root `layout.tsx` ships `OrganizationJsonLd`, `WebSiteSchema` (with SearchAction), and a combined `WebApplication`+`SoftwareApplication` graph node.
- Per-page schema already in place: `FAQPage` (home + /faq + every mega page), `HowTo` (home), `ItemList` (/champions), `SportsEvent` (/tournaments, 2 events), `CollectionPage` (/explore), `BreadcrumbList` + `WebPage` + `FAQPage` (mega pages), `CreativeWork` + `Person` author (/s/[id] when public), `ProfilePage` (/creator/[name]).
- `robots: { index: false, follow: false }` already on `/dashboard`, `/dashboard/profile` (via layout), `/dashboard/privacy` (via layout), `/dashboard/notifications`, `/notifications`, `/embed/[id]`. Private/unlisted shares get conditional noindex via `generateMetadata`.

- OG/Twitter Card metadata present on every primary surface; FAQ uses `/opengraph-image`, Explore has its own dedicated `/explore/opengraph-image`.

So the obvious low-hanging fruit from previous audits is already shipped. Below are gaps that remain.

## TOP 5 QUICK WINS NOT YET IN PRODUCTION

### Win #1 — Noindex edit-collab URLs (`/s/[id]?key=...`)  *[15 min, HIGH leverage]*

**Issue.** `src/app/s/[id]/page.tsx` line 88 only sets `noindex/nofollow` when the share is private. For a PUBLIC share, the same page is served to both viewers (`/s/abc123`) and collab editors (`/s/abc123?key=SECRET_EDIT_TOKEN`). The `?key=` URL is currently indexable. If a creator ever posts the edit URL in Discord, X, or a Reddit reply, search engines can crawl + cache it. That **leaks the edit token in SERP snippets** (security + privacy regression). It also creates a duplicate-content variant for every public share that ranks.

**Fix.** In `generateMetadata`, accept `searchParams` and force `robots: { index: false, follow: false }` whenever `key` is present, regardless of `isPublic`. Same change for the default page export (`SharePage`) already reads `searchParams.key`, so plumbing the value into `generateMetadata` is one line.

**Why this is leverage #1:** it's a latent prod security/privacy bug masquerading as an SEO finding. Every other item in this report is pure ranking optimization; this one prevents a real harm.

---

### Win #2 — Add `/compare` to the sitemap  *[5 min, MEDIUM]*

**Issue.** `/compare` has full metadata (title, description, canonical, OG, Twitter Card), is `index: true` by default, and is a tool page with clear search intent ("compare VGC teams", "VGC team diff tool"). It is **not in `sitemap.ts`** (only `/feedback`, `/changelog`, `/privacy`, `/terms` plus core pages are listed as static entries). The page exists at `src/app/compare/page.tsx` and renders to HTML.

**Fix.** Add one entry to the `staticPages` array in `src/app/sitemap.ts`:
```ts
{ url: `${BASE}/compare`, changeFrequency: "monthly", priority: 0.5, lastModified: now },
```

---

### Win #3 — Footer / persistent-nav internal-link gaps  *[20 min, MEDIUM]*

**Issue.** `PageFooter.tsx` (`src/components/layout/PageFooter.tsx`) links to: Home, Explore, FAQ, Changelog, Privacy, Terms, Cookie Settings. **Missing: `/champions`, `/tournaments`, `/compare`.** These are exactly the high-search-intent landing pages we built for SEO. Every page in the site reaches the footer; missing footer links lose internal PageRank to the three pages we most want to rank.

`PersistentNavbar` / `PageNavbar.tsx` includes `/champions` and `/compare` in the desktop nav row but does NOT include `/tournaments` despite it being a tier-1 indexable surface (only Home, Explore, Champions, Compare, Updates, Feedback are in the nav). On mobile, several primary pages aren't reachable from the persistent nav at all.

**Fix.**
1. Add `/champions`, `/tournaments`, `/compare` to `PageFooter.tsx`'s `NAV_LINKS` (and keep the current `hideFeedback` logic).
2. Add `/tournaments` to the `NAV_LINKS` array in `PageNavbar.tsx` (between Champions and Compare). Both pages already have icons we can reuse.

Adds three permanent internal links from every page on the site → ~10–15× total link equity boost for `/champions/[mega-slug]` cluster and `/tournaments` cluster.

---

### Win #4 — Footer BreadcrumbList + nav semantic markup  *[30 min, MEDIUM]*

**Issue.** Mega Pokemon pages (`/champions/[pokemon]`) already emit a 2-step BreadcrumbList (`Champions` → `<species>`). No other tier-1 page does, including high-value surfaces like `/tournaments`, `/faq`, `/explore`, and `/creator/[name]`. Google specifically uses breadcrumb structured data for both SERP appearance ("Home > Tournaments > VGC 2026") and crawl prioritization.

**Fix.** Add a shared `<BreadcrumbList>` JSON-LD helper (extend `src/components/seo/JsonLd.tsx`) and emit it on `/faq` (Home → FAQ), `/tournaments` (Home → Tournaments), `/explore` (Home → Explore), `/changelog`, `/creator/[name]` (Home → Creators → Name), and `/compare`. Three lines per page, no content changes.

---

### Win #5 — Canonical on `/dashboard` + add OG to `/privacy` and `/terms`  *[15 min, LOW–MEDIUM]*

**Issue (a).** `/dashboard` correctly has `robots: { index: false, follow: false }` but lacks `alternates.canonical`. Even though it's noindex, Google can still treat URL-parameter variants (`?utm_source=...` from Discord/email) as distinct unless a canonical is asserted. Cheap defence-in-depth.

**Issue (b).** `/privacy` and `/terms` have canonical but **no `openGraph` or `twitter` metadata**. When the privacy URL is shared (in cookie banners, GDPR replies, or our own Discord), the unfurl falls back to the root layout's site-wide OG card, which says "Build & Share Pokémon VGC Teams" — confusing on a legal-page link. Cheap fix; reuses the existing `/opengraph-image`.

**Fix.** Three metadata exports updated with a few extra lines each. No new content needed; everything reuses existing OG assets.

## Notable items deliberately NOT in the top 5

- **Home page BreadcrumbList** — Google's documentation says you don't need a BreadcrumbList on a root URL. Skipped.
- **`totalTime` on HowToSchema** — covered in a previous audit, the marginal lift is in the "rich-snippet eligibility" bucket which doesn't move actual rankings. Defer.
- **Adding more `keywords` arrays** — the `keywords` meta tag has been ignored by Google since 2009 and by Bing since 2014. Some past audits recommended this; it's noise. Skip.
- **OG image alt text on share unfurls** — already present where OG images render (FAQ, Explore, etc). The `/s/[id]` pages intentionally suppress OG images (see comments at `s/[id]/page.tsx:96–103`) so an alt isn't applicable.
- **`/dashboard/notifications` is auth-gated server-side** — already redirects unauthenticated users, plus carries noindex via `metadata`. No further action.
- **Adding the `/api/cron/*` routes to robots disallow** — `robots.txt` already blocks `/api/`. No-op.

## TOP 3 KEYWORD GAPS VS COMPETITORS

Competitors are Pikalytics (`pikalytics.com`), PokePaste (`pokepast.es`), VGCpastes (`vgcpastes.com`), and increasingly Limitless TCG / Trainerhill. We don't (and shouldn't) chase their core entity queries — Pikalytics owns "Pikalytics" and we won't take "PokePaste" from PokePaste. The gaps are at the **long-tail intent** layer where we have a structurally better answer than they do but no page targeting the query.

### Gap #1 — "[Species] EV spread VGC" / "[Species] best moveset"

**Examples:** *"flutter mane ev spread 2026"*, *"calyrex ice ev spread reg h"*, *"chien-pao best moveset vgc"*, *"urshifu rapid strike spread"*.

**Why it's a gap:** Pikalytics ranks for these because their species pages aggregate usage. PokePaste doesn't try. Our `/champions/[pokemon]` template only covers the ~40 Reg M-A Megas — the universe of "VGC species" queries is closer to 200+ (every Reg G/H/I-legal species, plus restricted legendaries that aren't Megas). The data already exists in the `shares` table — every public report's paste contains the species + spreads — and we ALREADY render community Mega pages from this data. Extending the same template to the broader VGC roster is mechanically straightforward.

**Quick-win-shaped subset:** Just the 12 highest-search-volume restricted legendaries for Reg H/I — Calyrex-Ice, Calyrex-Shadow, Miraidon, Koraidon, Zamazenta, Zacian, Terapagos, Groudon, Kyogre, Rayquaza, Lunala, Solgaleo. One per species, same template, ~2h of code reuse to ship the route prefix `/pokemon/[species]`. Each new page is a candidate to outrank Pikalytics for `"[species] ev spread"` because we surface **explained spreads with author notes**, not just usage histograms.

**Capture page:** new dynamic route `/pokemon/[species]`, parallel to `/champions/[pokemon]`, reusing `MegaLandingContent` minus the Mega-stone framing.

### Gap #2 — "VGC Regulation H teams" / "Reg H sample teams" / "Reg I teams"

**Examples:** *"reg h vgc teams"*, *"regulation h sample teams"*, *"VGC 2025 Reg G top teams"*, *"reg i teams"*.

**Why it's a gap:** VGCpastes is the de facto answer here (alongside Limitless TCG's tournament pages), but their UX is a wall of pastes. Our `/explore` page can already filter by `?regulation=H`, but we don't have a **landing page per regulation set**. A search engine sees "VGC Reg H teams" → there's no page on our site titled or `<h1>`-headed with that exact phrase. Pikalytics ranks here via their format-specific usage pages; VGCpastes ranks via topical authority.

**Capture page:** new static routes `/format/reg-h`, `/format/reg-i`, `/format/reg-g`, `/format/reg-ma`. Each is a thin server component that renders the existing `ExploreContent` with the regulation filter pre-applied, plus a regulation-specific intro paragraph, an `ItemList` schema of the top 9 public reports for that regulation, and a `BreadcrumbList`. Title pattern: `"VGC Regulation H Teams — Top Reg H Team Reports & Builds"`. Content is auto-generated from the shares table; zero manual upkeep.

This is 2h tops because all of `ExploreContent` already accepts a `regulation` URL param.

### Gap #3 — "Open Team Sheet generator" / "VGC OTS generator"

**Examples:** *"vgc open team sheet generator"*, *"pokemon ots generator"*, *"open team sheet template vgc"*, *"how to make an open team sheet"*.

**Why it's a gap:** We literally **have an OTS generator** (`OTSSheetModal` at `src/components/ui/OTSSheetModal.tsx`, deep-linked from the share menu) that exports a clean PNG with sprites + QR code. PokePaste does NOT have this. Pikalytics does NOT have this. Nobody on the first SERP page does. The product is built — we just don't surface it at a discoverable URL.

**Capture page:** new static route `/ots-generator` (or `/open-team-sheet`). Static page that:
- Has `<h1>Pokemon VGC Open Team Sheet Generator</h1>`
- Explains what an OTS is (the FAQ already has this copy — link it in)
- Has a paste input that, on submit, opens the OTS sheet modal flow with that paste pre-loaded
- Lives in the sitemap with priority 0.8
- Has `SoftwareApplication` JSON-LD specifically for the generator tool

The functional implementation reuses `OTSSheetModal` 1:1; new code is the wrapper page + a paste-to-modal handoff. Currently a search for "VGC OTS generator" returns mostly forum threads. We can take that #1 in <2 months because the SERP has no real competitor and we have a literal generator.

## Implementation order (if all five quick wins shipped)

1. **Win #1 (edit-key noindex)** — ship first, it's the security regression
2. Win #3 (footer + nav links) — biggest sitewide internal-PageRank shift
3. Win #2 (compare in sitemap)
4. Win #4 (breadcrumbs)
5. Win #5 (dashboard canonical, OG on legal pages)

Total budget for the five: ~90 minutes of code. Each is a localized metadata change with no test-suite risk.

For the keyword gaps, the priority is **#3 → #2 → #1**:
- Gap #3 (OTS generator landing) is highest-leverage because we own a unique tool that ranks competitors can't easily reproduce.
- Gap #2 (per-regulation landing pages) is next — pure programmatic SEO, infinite scaling, no manual upkeep.
- Gap #1 (per-species pages) is biggest absolute traffic but needs the most care to not look thin/spammy.
