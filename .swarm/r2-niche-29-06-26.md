## The single proposal — **Restricted-Duo team label** ("Caly-Shadow / Miraidon")

### Problem

Limitless VGC's primary way of categorizing teams is by their **restricted-Pokémon pair** — "Calyrex-Shadow / Miraidon", "Kyogre / Groudon", "Solo Zacian", etc. This is **the** canonical community language for talking about Reg G / Reg I / Reg M-B teams. WebSearch confirms Limitless tracks "team archetypes through the combination of restricted Pokémon," updates per-duo records each round, and now (Reg M-B, 17 Jun 2026 launch) is the de-facto place to see "which restricted duo is winning Champions events." Pikalytics also leans on this framing for Reg M-B.

VGC Team Report has all the data to do this — `RESTRICTED_BASE_NAMES` already exists in `src/lib/validation/champions-legality.ts`, and `detectArchetypes` already runs weather/trick-room/tailwind tags. But the report header surfaces only the abstract archetype ("Trick Room", "Tailwind", "Mega Offense"). The restricted-duo identifier — the thing a VGC player actually says out loud — is nowhere on the card, in the report header, in OG images, or in `explore` filters.

This is a real gap, not a vanity tag: when a player shares a Champions Reg M-B report on Discord, the embed currently reads "Mega Offense · Tailwind." A reader can't tell whether it's a Kyogre team or a Calyrex team without opening the link. That's friction VGCpastes/Limitless don't have.

### Proposal

Add a `detectRestrictedDuo(pokemon)` helper that returns one of:
- `"Solo <Name>"` (1 restricted: "Solo Miraidon")
- `"<A> / <B>"` (2 restricted, alphabetized for stability: "Calyrex-Shadow / Miraidon")
- `null` (open-format / 0 restricted — Reg A/B/H-style)

Display the result in three places:
1. **Top of `TeamOverview` header**, above existing archetype chips — big, bold, primary identifier.
2. **OG share image** (`src/app/api/team-graphic/route.tsx`) — replace/augment the archetype line so Discord/Twitter embeds read "Calyrex-Shadow / Miraidon — Tailwind".
3. **`ReportCard`** in `explore` — small chip under the title so users browsing the gallery scan by duo (matches Limitless mental model).

Also add a string filter to `ExploreFilters` for "restricted duo" once it exists on cards. Keep this minimal — string-contains is fine for v1.

### Why this and not something fancier

- **Reuses existing data.** Restricted list and form-normalization are already in the codebase. No new dex, no scraping.
- **No backend / DB changes.** Pure derivation on the report shape. Works for all existing shared reports without migration.
- **Differentiates on the community's vocabulary.** This is how VGC players talk; matching that lowers cognitive load when they land on a shared link.
- **No conflict with main.** `main-changed-files.md` shows recent work on legality/regulation/champions-dex, all of which are *upstream* of this change — we'd be a consumer, not an editor, of those files (modulo the one export tweak).
- **Defers the harder Limitless feature** (per-duo win-rate aggregation across tournaments) which would need event ingestion and a data pipeline — explicitly out of scope tonight.

### Risk / open question

- Form casing: "Calyrex-Shadow" vs "Calyrex-Shadow Rider" vs "calyrex-shadow" — `getRestrictedBase` normalizes to the base, but the *display* needs the canonical pretty name. Use a small lookup map: `{ calyrex: { shadow: "Calyrex-Shadow", ice: "Calyrex-Ice" }, kyurem: { white: "Kyurem-White", black: "Kyurem-Black" }, kyogre: { primal: "Kyogre-Primal", "": "Kyogre" }, … }`. ~20 lines, no external data.
- Reg M-B teams may pair a Mega with a single restricted — make sure "Solo Miraidon" still triggers when the second slot is a Mega, not another restricted. The detection is on `RESTRICTED_BASE_NAMES` hits, so Megas are naturally excluded — fine.
