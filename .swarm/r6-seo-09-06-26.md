## 1. Sitemap Audit — `src/app/sitemap.ts`

### BUG (high impact): `/compare` is listed twice
Lines 16 and 18 both add `${BASE}/compare`:

```ts
{ url: `${BASE}/compare`, changeFrequency: "monthly", priority: 0.6, lastModified: now },
...
{ url: `${BASE}/compare`, changeFrequency: "monthly", priority: 0.5, lastModified: now },
```

Two consequences:
1. Duplicate URL in the XML — sitemap validators flag this; Google Search Console will throw a warning.
2. `/compare` page itself has `robots: { index: false, follow: true }` (see `src/app/compare/page.tsx:10`). It SHOULD NOT BE IN THE SITEMAP AT ALL. Including a noindex URL in sitemap.xml is a [documented anti-pattern](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap) and dilutes crawl budget.

**Fix:** Delete BOTH `/compare` entries from the static array. The page does not need sitemap inclusion if it's noindexed.

## 2. Robots Audit — `public/robots.txt`

**No `src/app/robots.ts` exists.** A static `public/robots.txt` is used instead — fine, but means it can't be programmatically tied to env (e.g., noindex on preview deploys).

```
User-agent: GPTBot      → Allow: /
User-agent: ClaudeBot   → Allow: /
User-agent: PerplexityBot → Allow: /
User-agent: OAI-SearchBot → Allow: /
```

**AI bots: confirmed allowed.** Changelog claim verified.

### Missing AI bots worth adding
- `Google-Extended` — Google Bard/Gemini training; separate from Googlebot.
- `Applebot-Extended` — Apple Intelligence training.
- `CCBot` — Common Crawl (powers many smaller LLMs).
- `Amazonbot` — Alexa+ training.
- `Bytespider` — TikTok / Doubao.
- `Meta-ExternalAgent` — Meta AI.

All currently default to "Allow: /" via `User-agent: *`, but explicit blocks/allows are best practice and resilient to LLM crawler config changes that some have made (Bing's AI crawler now distinguishes from Bingbot, for example).

### Other recommendations
- Add `Crawl-delay: 1` for `User-agent: *` (the share-list / champions endpoints are DB-backed; an aggressive crawler can hammer Neon).
- Consider blocking `/api/` for AI bots explicitly (currently they are also covered by the `*` rule's `Disallow: /api/`, but explicit beats implicit).
- Sitemap URL is present and correct.

### Cross-cutting issue: OG image strategy
Root layout sets `images: [opengraph-image, /og-default.png]` (two images). Many sub-pages override with the static `/opengraph-image` literal. **`opengraph-image.tsx` exists at root** — this is the dynamic SVG/JSX route. The `/og-default.png` is a static fallback. This double-image array is harmless but most crawlers only use the FIRST one; the fallback never gets selected. Consider removing the duplicate to simplify and avoid sending Discord/X a dynamic edge-rendered image (which has been flaky per code comments in `s/[id]/page.tsx`).

### Present (good)
| Page | Schema types |
|---|---|

| `/tournaments` | SportsEvent (array), BreadcrumbList |
| `/changelog` | BreadcrumbList |
| `/s/[id]` | CreativeWork |

### Missing opportunities

1. **`/changelog` → no `Article` / `BlogPosting` schema for each entry.** Each release note is essentially a mini blog post. Adding `@type: TechArticle` per entry would qualify for Google's "Updated" badge in search and surface in "What's new" answers.

2. **`/champions/[pokemon]` → no `VideoGame` linkage.** Each Mega is a character in the Pokemon Champions video game. Adding `mainEntity` of type `VideoGameCharacter` (or `Thing` with `gameItem`) would strengthen entity disambiguation for "Mega Charizard Y VGC" vs. other contexts.

3. **`/s/[id]` → CreativeWork is generic.** Could upgrade to `@type: ["CreativeWork", "Guide"]` and add `genre: "Esports Strategy"`, `audience: { @type: "Audience", audienceType: "Competitive Pokemon Player" }`, and `keywords` derived from species list. Helps for "[species] VGC team" queries.

4. **`/tournaments` → SportsEvent missing `subEvent`s for past results.** Currently only lists upcoming. When tournament archives are added, each tournament should be its own SportsEvent with `award` (winning team report URLs) — high AEO yield.

5. **No `SiteNavigationElement` schema.** Adding a single SiteNavigationElement listing the primary nav items in root layout helps Google understand site structure for sitelinks.

6. **`/explore` `CollectionPage` doesn't enumerate items.** Adding `mainEntity: ItemList` with the first 20 share URLs would help Google understand the list contents server-side (currently relies on JS-rendered cards).

7. **No `Review` or `AggregateRating` schema.** If user reactions / view counts can be surfaced, adding `interactionStatistic` to share-page CreativeWork would unlock star ratings in SERPs for popular shares. (Requires real data, not faked.)

## 6. Top 5 Keyword Gaps Found

Based on competitive set analysis (Pikalytics, PokePaste, VGCPastes, Trainerhill, Limitless), the codebase is missing these high-intent queries:

1. **"VGC EV calculator" / "VGC SP calculator" / "VGC damage calculator"** — site has these tools but no page targets the keyword. Standalone landing pages or anchored sections on `/` with `<h2>` text are needed. Pikalytics ranks #1 for some of these.
2. **"Pokemon VGC sets" / "VGC moveset database"** — `/explore` could double as a sets database with filters per species; metadata doesn't claim this. Add "VGC sets database" to explore description/keywords.
3. **"[Tournament name] team list" / "Regional Championships results"** — `/tournaments` currently is event-list. No long-tail title targeting per tournament. Future: `/tournaments/[slug]` pages.
4. **"PokePaste viewer" / "convert PokePaste to team report"** — homepage doesn't claim PokePaste-viewer territory; PokePaste's keyword authority is strong but they offer no analysis. Adding "PokePaste viewer" + "PokePaste to Showdown converter" to home metadata captures intent.
5. **"VGC tier list" / "Pokemon VGC usage stats"** — Pikalytics dominates this. We have aggregate share data; a `/meta` or `/usage` page synthesizing public-share usage stats would be a flanking move with original data Pikalytics doesn't have (community team reports vs. tournament rip).

Minor additional gaps:
- "Open team sheet generator" — only present in FAQ body, not in any title/description.
- "Showdown team to image" — embed/OG generators are unindexed; no landing page targets it.
- "Pokemon VGC team builder for iPhone / Android" — PWA support exists; no metadata mentions mobile.
