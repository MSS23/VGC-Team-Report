### S5 — The EV↔SP contradiction (VGC-266 / VGC-330): exact current wording

`public/llms-full.txt:92`, verbatim and complete:

> **SP (Stat Points)** is *not* another name for EVs. It is the stat-investment system that Pokémon Champions (Regulations M-A, M-B and the current M-C) uses **in place of** EVs: each Pokémon has 66 SP total to distribute across the six stats, with a maximum of 32 SP per stat. The conversion is not 1:1 — the first SP in a stat costs 4 EVs and every SP after that costs 8 (so 32 SP = 248+ EVs). In formula terms, SP = ceil(EVs / 8), with a floor of 1 SP for any non-zero investment, giving the ladder 4 EVs = 1 SP, 12 EVs = 2 SP, 20 EVs = 3 SP … 248 EVs = 32 SP (the per-stat cap, which a maxed 252-EV stat also hits).

The single sentence beginning *"In formula terms"* states two incompatible things, and the sentence
before it states a third:

1. `SP = ceil(EVs / 8)` ⇒ `ceil(248 / 8)` = **31 SP**, not 32.
2. `248 EVs = 32 SP` — stated explicitly in the same sentence.
3. *"the first SP in a stat costs 4 EVs and every SP after that costs 8"* ⇒ 32 SP = 4 + 8×31 = **252 EVs**, not 248.

The ladder's first three rungs (4/12/20 → 1/2/3) are consistent with `ceil(EV/8)`; only the final
rung is not.

**What the code actually does** — `src/lib/analysis/stat-calculator.ts:139-143`:

```ts
export function evToChampionsSp(ev: number): number {
  if (ev <= 0) return 0;
  if (ev >= 248) return CHAMPIONS_MAX_SP_PER_STAT;
  return Math.min(CHAMPIONS_MAX_SP_PER_STAT, Math.max(1, Math.ceil(ev / 8)));
}
```

A hard `>= 248` clamp sits **in front of** the `ceil(ev / 8)` formula, so the implementation agrees
with claim 2 and disagrees with claims 1 and 3 above 240 EVs. The doc's prose presents the clamp as
if it fell out of the formula, which it does not. The same two statements appear in the code's own
doc comment at `:136-137`.

Third and fourth variants of the same fact elsewhere in the repo:

- `public/llms.txt:29` and `public/llms-full.txt:116` — *"(so 32 SP = 248+ EVs)"*, without the `ceil` formula, so those two lines are not self-contradictory but still conflict with the "4 then 8 each" ladder in the same sentence.
- `src/app/faq/page.tsx:93` — *"the first SP in a stat costs 4 EVs and each SP after that costs 8, so **32 SP corresponds to a fully invested 252-EV stat** in traditional VGC."* This is the only phrasing that is internally consistent **and** true of the code (`evToChampionsSp(252) === 32`).

**Important constraint on any fix:** `src/lib/analysis/__tests__/sp-docs-drift.test.ts` pins the
docs to the contradictory wording. `:74-76` asserts both files contain the literal
`"32 SP = 248+ EVs"`; `:111-119` asserts `llms-full.txt` contains `"248 EVs = 32 SP"`; `:104-107`
acknowledges the exception in a comment (*"the per-stat cap is hit at CAP_EV_COST EVs rather than at
the 4 + 8 x 31 the ladder would otherwise predict, which is why the docs write '248+ EVs'"*). So the
docs cannot be corrected without editing the test that enforces them. **Per instruction, not
resolved here — this needs a human ruling on whether the 32-SP cap is reached at 248 or 252 EVs,
and the clamp at `stat-calculator.ts:141` is the thing that decides it.**

Everything else in the SP docs checks out against the code: 66 total (`CHAMPIONS_TOTAL_SP`,
`stat-calculator.ts:124`), 32 per stat (`CHAMPIONS_MAX_SP_PER_STAT`, `:123`), 252 EV per-stat cap
(`MAX_EV_PER_STAT`, `:127`), "8 EVs is worth one point of a stat at level 50"
(`llms-full.txt:90`, matches `calculateStat` at `:14-20`), "510 total, only 508 reachable"
(`llms-full.txt:90`, standard and consistent with the 4-EV stepping used at `:157`), the Champions
stat formulas (`llms-full` does not restate them; `calculateChampionsStat` at `:29-42` is
documented correctly in-file), and the M-C window "Sep 9 – Dec 2 2026" (`llms.txt:30`,
`llms-full.txt:78`, matching `champions-dex.ts:~301` and `ChampionsContent.tsx:64`).

### S6 — There is no AI-crawler allow-list in this repo

The task premise is that `llms.txt` / `llms-full.txt` are "served to allow-listed AI crawlers."
No such mechanism exists in the repository:

- No `src/app/robots.ts` — robots is the static `public/robots.txt`, one `User-agent: *` group.
- No `middleware.ts` / `src/middleware.ts` anywhere in the repo.
- `next.config.ts` has no user-agent-keyed `headers()`, `rewrites()` or `redirects()` (`:37-52` is PostHog ingest, `:53-96` is `sw.js` / `manifest.json` caching plus global security headers).
- No `GPTBot` / `ClaudeBot` / `PerplexityBot` string anywhere in `src/` or the config.

Both files are ordinary public static assets, reachable by anything that obeys the wildcard group,
and discoverable only because `src/app/sitemap.ts:30-31` lists them (nothing in the app links to
them — no `<link rel>`, no footer entry). That is a defensible posture, but it is not
allow-listing, and VGC-272's consolidation into one wildcard group removed the only place a
per-bot rule could have lived. Flagging so the premise is not carried forward as fact.
