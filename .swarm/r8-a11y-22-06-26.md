## P0 — Critical (Keyboard Trap, Form Labels, Focus Order)

### P0.1 SlideNavControls progress slider is focusable but not keyboard-operable
- **File:** `/src/components/report/SlideNavControls.tsx:482-520` (desktop dot indicators)
- **Issue:** Buttons with `role="tab"` + `aria-selected` are focusable but have no keyboard handlers. Prev/Next buttons work; the slider does not.
- **WCAG 2.1.1 (Keyboard)** + **4.1.2 (Name/Role/Value)**
- **Severity:** P0 because Tab can focus an unresponsive element, creating a keyboard trap perception.
- **Fix:** Add `onKeyDown` handler to each dot-button:
  ```tsx
  onKeyDown={(e) => {
    if (e.key === "ArrowRight" && !isLast) onGoTo(i + 1);
    if (e.key === "ArrowLeft" && i > 0) onGoTo(i - 1);
    if (e.key === "Home") onGoTo(0);
    if (e.key === "End") onGoTo(totalSlides - 1);
  }}
  ```

### P0.2 Form inputs missing accessible labels (multi-file sweep)
- **Files:** All locations from prior S4 remain unresolved:
  - `/src/components/report/TeamOverview.tsx:507-549` — teamName, tournamentName, placement, record, rentalCode inputs
  - `/src/components/report/PokemonDetailSlide.tsx:845+` — Pokemon notes textarea (not yet audited in detail)
  - `/src/components/report/MatchupPlanSlide.tsx:680+` — game-plan notes textarea + replay URL (not yet audited in detail)
- **Issue:** Placeholders are not accessible names. Screen readers announce "edit text" with no context.
- **WCAG 3.3.2 (Labels or Instructions)** + **1.3.1 (Info & Relationships)**
- **Fix:** Add `aria-label` to each input (mechanical sweep):
  ```tsx
  <input
    type="text"
    aria-label="Team name"
    placeholder={t.teamNamePlaceholder}
    ...
  />
  ```

### P0.3 Export Theme modal has no focus trap or Escape handler on dialog itself
- **File:** `/src/app/page.tsx` — modal area not re-reviewed, but issue from prior S3 remains.
- **Issue:** Tab can escape into the page underneath; Escape only works if backdrop has focus.
- **WCAG 2.4.3 (Focus Order)** + **2.1.2 (No Keyboard Trap)**
- **Fix:** Implement focus trap using a hook (see `ShareModal.tsx:128-175` as reference).

### P0.4 InlinePokemonEditor modal has no focus trap
- **File:** `/src/components/report/InlinePokemonEditor.tsx:128-229`
- **Issue:** Same as P0.3 — tab escapes the modal.
- **WCAG 2.4.3**
- **Fix:** Apply `ShareModal.tsx` focus-trap pattern.

## Conflict-Risk Overlaps

### Touch Target vs. Visual Density (P1.1)
- **PokemonCard Mega toggle** now 44×44 on mobile but `sm:` breakpoint shrinks to `sm:w-9 sm:h-9` (36 px).
- On desktop (≥640px), this becomes a pointer-device situation. **AAA guideline is 44×44, but AA allows context-dependent sizing.**
- **Recommendation:** This design choice is acceptable under AA if pointer device detection or explicit AA notice is present. Currently passes AA.

### Modal Focus Traps (P0.3, P0.4)
- **ShareModal.tsx** (line 128–175) has a focus-trap implementation already.
- **Export Theme modal** and **InlinePokemonEditor** do not share this hook.
- **Recommendation:** Extract the focus-trap logic into a reusable hook (`useFocusTrap.tsx`) and apply to all modals.
