## CRITICAL

### C1. Export Theme modal — Light/Dark "buttons" are a radio group in disguise; no role, no aria-pressed, no keyboard radio semantics
- File: `src/app/page.tsx:1755-1795`
- Two visual radio cards (Light / Dark) — exactly one is active, selection styled with `border-accent bg-accent/5 shadow-md` — but they are plain `<button type="button">` with no `role="radio"`, no `aria-checked`, and no surrounding `role="radiogroup"`. Keyboard users hear "Light, button" / "Dark, button" with no indication that one is selected, no Arrow-key navigation between them, and no relation to the heading "Export Theme".
- WCAG 4.1.2 (Name, Role, Value) — failure; 1.3.1 (Info & Relationships).
- This is the same modal flagged in r8-22-05-26 S3 for focus trap (still missing); it's a true critical because the dialog ships a meaningful selection state that's entirely invisible to AT.
- Fix:
  ```tsx
  <div role="radiogroup" aria-labelledby="export-theme-modal-title" className="grid grid-cols-2 gap-3">
    <button role="radio" aria-checked={exportTheme === "light"} type="button" ...>Light</button>
    <button role="radio" aria-checked={exportTheme === "dark"}  type="button" ...>Dark</button>
  </div>
  ```
  Plus arrow-key handling (Left/Right cycles, Space/Enter selects) and `tabIndex={exportTheme === "light" ? 0 : -1}` on each per ARIA APG radiogroup pattern.

### C2. SlideNavControls overflow sheet is a `role="dialog"` with no focus trap
- File: `src/components/report/SlideNavControls.tsx:419-435`
- The sheet has `role="dialog"` and `aria-label="Slide options"` and Escape closes it (line 155-161 — good). However, **Tab can escape the dialog** into the page beneath while it's open, and on close focus is NOT restored to the overflow trigger button. Same defect class as the InlinePokemonEditor modal (S10 last cycle, still open) and the ExportTheme modal (still open).
- WCAG 2.1.2 (No Keyboard Trap — inverse failure: focus leaks out of an open dialog) + 2.4.3 (Focus Order — return to trigger).
- High frequency: this sheet opens on every report view that has creator tools or a Mega toggle (i.e. on `/s/[id]` for any Mega-capable team).
- Fix: lift `ShareModal.tsx:140-186` focus-trap effect into a shared hook (`useFocusTrap(ref, onClose)`) and apply here + in InlinePokemonEditor + ExportTheme modal. Also stash `document.activeElement` on open, restore on close (the prior audit's S10 recommended the same thing — this is a copy-paste opportunity).

### C3. Comments toggle (`role="switch"`) has no visible focus indicator
- File: `src/components/ui/ShareModal.tsx:891-916`
- The button is `role="switch"` with proper `aria-checked` — but has zero `focus`, `focus-visible`, or `focus:ring` classes. Keyboard users tabbing into the ShareModal hit this control and get no visible focus ring at all (the toggle track has its own styling for the *checked* state but nothing for keyboard focus). The `cursor-pointer` styling is the only affordance and it's mouse-only.
- WCAG 2.4.7 (Focus Visible) — clear failure.
- Same pattern affects the 3-state visibility radio group at `ShareModal.tsx:744-817`: none of the three radio buttons have `focus:` or `focus-visible:` classes either. That's three buttons in the same modal with no keyboard focus indicator.
- Fix:
  ```tsx
  className="… focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2 focus-visible:ring-offset-surface …"
  ```
  applied to the switch + each of the three radio buttons. (Project pattern: see `PokemonDetailSlide.tsx:197-201` for the same idiom already used.)

## SERIOUS

### S1. CollapsibleCalcGroup disclosure button is missing `aria-controls` and target panel has no id
- File: `src/components/report/PokemonDetailSlide.tsx:271-316`
- Header `<button>` has `aria-expanded={effectiveOpen}` (good) but no `aria-controls`. The grid panel it toggles (line 294-297) has no `id`. Screen readers can't programmatically tie the button to the panel.
- Also: the header `<button>` lacks `type="button"` (line 271) — it defaults to `type="submit"`. The slide isn't currently inside a `<form>`, but the CalcInput component below uses an internal form-like submission flow and the calc list is rendered in the same React tree; if either tree is ever wrapped, the Enter-key inside a textarea will collapse a calc group.
- WCAG 4.1.2 (Name/Role/Value) + 3.2.2 (On Input — collapse on accidental submit).
- Fix:
  ```tsx
  <button
    type="button"
    aria-expanded={effectiveOpen}
    aria-controls={`calc-panel-${category}`}
    onClick={() => setIsOpen(!isOpen)}
    ...
  >
  ...
  <div id={`calc-panel-${category}`} className={...}>
  ```

### S2. SlideNavControls section tabs and dot tabs are `role="tab"` with no `aria-controls`
- File: `src/components/report/SlideNavControls.tsx:179-196` (segment tabs), `:492-518` (desktop dot tabs)
- Both sets of buttons declare `role="tab"` and `aria-selected`, but neither sets `aria-controls` on each tab nor `role="tabpanel"` + `aria-labelledby` on the slide content rendered inside `page.tsx:1219-1274`. Without that pairing, the `tablist` semantics are decorative — VoiceOver/NVDA can't jump from a tab to its content with the documented tablist commands.
- WCAG 4.1.2 (Name/Role/Value); 1.3.1.
- Compounded by the fact that there are **two** sibling `role="tablist"` elements ("Report sections" and "Slides") covering overlapping navigations; if we keep both, each needs distinct controls + labelling.
- Fix: either (a) wire `aria-controls={"slide-content-" + currentSlide}` on every tab and put `id="slide-content-N" role="tabpanel"` on the report content wrapper, or (b) downgrade one of the tablists to plain navigation buttons. (b) is cheaper and arguably more honest — these aren't classical tabs, they're keyboard shortcuts into a paginated linear flow.

### S3. Light/Dark theme buttons inside the modal have no aria-pressed and no `type="button"`
- File: `src/app/page.tsx:1757-1795`
- See C1 for the radiogroup framing. Independent issue: the buttons also lack `type="button"`. If the modal is ever rendered inside a `<form>` (it isn't today, but `<dialog>` portals + Clerk modal forms are nearby concerns), they will submit on Enter and discard the selection.
- WCAG 3.2.2.
- Fix: add `type="button"` even if applying C1's radio refactor.

### S4. OTSSheetModal "Save as PNG" spinner is animate-spin with no `prefers-reduced-motion` respect and the loading state is not announced
- File: `src/components/ui/OTSSheetModal.tsx:259-271`
- During PNG export, the button swaps its icon for an `animate-spin` ring. The button is `disabled` (good), but: (a) the spinner ignores `motion-reduce`/`prefers-reduced-motion: reduce` — vestibular users get an unwanted rotation; (b) screen readers get no announcement that the long-running PNG generation has started (`html2canvas` on a 6-Pokemon sheet takes 1–3 s on mid-range mobile). Same pattern in the rental-code Copy button at `ShareModal.tsx:454-468` (visual-only state change).
- WCAG 2.3.3 (Animation from Interactions — AAA, but project policy in CLAUDE.md UI standards calls out reduced-motion compliance) + 4.1.3 (Status Messages).
- Fix:
  ```tsx
  <button aria-busy={downloading} aria-live="polite" ...>
    {downloading
      ? <span className="motion-safe:animate-spin w-3.5 h-3.5 border-2 border-white/30 border-t-white rounded-full" />
      : <svg .../>}
    {downloading ? "Saving…" : "Save as PNG"}
  </button>
  ```

### S5. Welcome-back / logged-out / fork attribution / hidden-slide / URL-warning banners — decorative SVGs missing `aria-hidden="true"`
- File: `src/app/page.tsx:960-963, 1024-1029, 1064-1068, 1152-1158, 1200-1204, 1418-1422, 1340-1355`
- A sweep across the home page surface. Each banner has a leading SVG that is purely decorative (its meaning is fully conveyed by the adjacent heading + body text). None have `aria-hidden="true"`. While most browsers' default tree-walk ignores untitled SVGs, the codebase explicitly tags every other decorative SVG (good consistency) — and a couple of these SVGs have `<title>`-less child elements that JAWS will read out as "Image". The visibility-cycle button at `1340-1355` renders one of three SVGs based on state, all unlabelled — the button text ("Public" / "Unlisted" / "Private") carries meaning, but the icon should still be hidden.
- WCAG 1.1.1 (Non-text Content).
- Fix: mechanical sweep — `aria-hidden="true"` on each listed SVG.

### S6. TeamReport "Some fields hidden by the creator" notice has decorative SVG without `aria-hidden`
- File: `src/components/report/TeamReport.tsx:183-186`
- The padlock SVG conveys the same meaning as the bold "Some fields hidden by the creator" text that follows — duplicating it to AT users. Bigger problem: the listed redacted fields render as `{redactedFields.includes("evs") && "EV/SP spreads, "}` etc., producing trailing-comma grammar like "EV/SP spreads, IVs, are not shown" — readable but rough for screen readers that announce punctuation. Lower priority but the SVG fix is one line.
- WCAG 1.1.1.
- Fix: add `aria-hidden="true"` to the `<svg>`. (Grammar fix is separate — render the field list with `Intl.ListFormat` or a join + final "and".)

### S7. Welcome-back banner inner buttons ("Get my link" / "Dismiss") have no min touch size on mobile
- File: `src/app/page.tsx:973-989`
- `px-3 py-1.5 text-[11px]` — effective height ~28 px. Below the 44 px floor stated in CLAUDE.md UI standards. The corresponding outer X dismiss button (`page.tsx:992-1012`) is correctly `min-w-[44px] min-h-[44px]` — these two inline buttons are the mismatch. Same pattern at the logged-out banner `1039-1053` (`px-3 py-1.5 text-[11px]`).
- WCAG 2.5.5 (Target Size — project floor).
- Fix: add `min-h-[44px]` (or bump padding to `py-2.5`) to each of the four inline pill buttons. These ship to every signed-out user with an in-progress draft, so the impact surface is broad.

### S8. SlideNavControls overflow sheet "Move earlier / Move later" buttons render without text on mobile when the parent flexbox squeezes, but the *icon* has no aria-hidden and there's no `aria-label`
- File: `src/components/report/SlideNavControls.tsx:359-384`
- Both buttons render `<svg> + "Move earlier"` / `<svg> + "Move later"` text. They have `min-h-[44px]` (good) and visible text labels (good) — but the chevron SVGs lack `aria-hidden`, and the buttons themselves have no fallback `aria-label`. If the text node ever truncates (long i18n strings — these are user-facing English-only strings today, but `tRaw` translation pattern is in use elsewhere), the button degrades to "Image, button".
- WCAG 1.1.1 + 4.1.2.
- Fix: `aria-hidden` on each chevron + `aria-label="Move slide earlier"` / `aria-label="Move slide later"` on each button as a belt-and-braces fallback.

### M3. ShareModal "URL display" row's small-text contrast: `text-[10px]` URL fallback at OTS QR caption
- File: `src/components/ui/OTSSheetModal.tsx:237` (`text-[9px] text-text-tertiary`) and `:250` (`text-[10px] text-text-tertiary`)
- 9 px and 10 px text in `text-text-tertiary` (≈ #6E6E8A on `#FAF9F6` per the export theme defaults) — contrast ratio ~4.8:1, which **passes for 18 px+ but fails for body text at 9–10 px**. The 9 px caption "Scan for full report" and the 10 px share URL strip both fall under WCAG 1.4.3 large-text limit and need 4.5:1 *minimum* at this size.
- WCAG 1.4.3 (Contrast — Minimum).
- Fix: bump to `text-text-secondary` (#4A4A68, ratio ~9.7:1) or raise size to `text-xs` (12 px).
