# PWA Research: Install Prompt & Offline UX Patterns
**Research Date:** 2026-05-15
**Researcher:** Swarm Agent (r-pwa — overnight wave 15-05-26)
**Scope:** Current PWA state audit + improvement opportunities for VGC Team Report

---

## Current PWA State

### What Is Implemented (solid foundation)

**Service Worker (`public/sw.js` — v23/share-cache-v5/api-cache-v6)**
- Install: pre-caches 12 routes including `/`, `/explore`, `/champions`, `/compare`, `/compare`, `/changelog`, `/feedback`, `/dashboard`, `/dashboard/profile`, `/privacy` plus icons and manifest
- Offline fallback: custom `/_offline` HTML page (well-designed, on-brand)
- Caching strategies per route type:
  - Static assets (`/_next/static/`, `.js/.css/fonts/images`): cache-first
  - Share API (`/api/share/[8-char-id]`): cache-first with background revalidation — specifically designed for offline tournament access
  - Explore/spotlight/user API routes: stale-while-revalidate (30-entry LRU)
  - `/s/*` and `/embed/*` share pages: network-first with cache fallback
  - All other pages: network-first with cache fallback to `/_offline`
- `skipWaiting()` called at install (immediate activation), plus `clients.claim()` at activate
- Periodic update check every 30 minutes via `reg.update()`
- SKIP_WAITING message handler for controlled updates

**`ServiceWorkerRegistration.tsx`**
- Registers `/sw.js` with `updateViaCache: "none"`
- Detects waiting workers (handles already-waiting on registration + updatefound events)
- Shows update-available toast with "Refresh" button (bottom-right, mobile-safe positioning)
- Uses `waitingWorkerRef` to safely postMessage SKIP_WAITING (guards against `redundant` state crash)
- Auto-reload on `controllerchange`
- Silent fail on registration error (SW as progressive enhancement)

**`InstallPrompt.tsx`**
- Captures `beforeinstallprompt` and defers it (correct pattern)
- 14-day dismiss cooldown via `localStorage`
- Checks `(display-mode: standalone)` to skip if already installed
- Android/Chrome: reveals bottom sheet after **15-second delay** post-event capture
- iOS Safari detection: shows manual Add-to-Home-Screen instructions after **45-second delay**
- Bottom sheet UI: handle bar, app icon, descriptive copy, primary "Install App" / secondary "Maybe Later"
- iOS path shows Share icon + "Add to Home Screen" instruction text (no animation/GIF)

**`ConnectivityStatus.tsx`**
- Transient toast on online/offline transitions (suppressed on initial page load)
- Persistent amber "Offline — viewing cached version" banner on `/s/*` share pages when offline
- No initial-load flash for already-offline state (uses `initialRef` pattern)

**`manifest.json`**
- All required installability fields present: `name`, `short_name`, `start_url`, `scope`, `display`, `icons`
- `display_override: ["window-controls-overlay", "standalone", "minimal-ui"]` — modern
- `launch_handler: { client_mode: "navigate-existing" }` — prevents duplicate windows
- 5 shortcuts (Create, Explore, Champions, Compare, Dashboard)
- `share_target` configured for paste-from-share
- Screenshots: 4 entries (2 wide, 2 narrow) — all using icon images, NOT real screenshots
- Maskable icon: only one entry (`icon-512.png` with `purpose: "maskable"`) — the same file is also listed without purpose, which is correct
- Missing: a separate `icon-192.png` with `purpose: "maskable"` (Lighthouse will flag this)

**`layout.tsx` wiring**
- All four PWA components rendered globally: `<InstallPrompt />`, `<ConnectivityStatus />`, `<ServiceWorkerRegistration />`, `<ChunkErrorReloader />`
- `appleWebApp` metadata: `capable: true`, `statusBarStyle: "black-translucent"` — correct
- `manifest: "/manifest.json"` linked in metadata
- Viewport: `viewportFit: "cover"` for notch/safe-area support

### What Is Missing or Suboptimal

1. **Install prompt timing is time-based, not engagement-based.** The 15-second timer fires regardless of what the user is doing — they could be mid-read. Best practice (Google, web.dev) is to trigger after a meaningful completed action, not an arbitrary timeout.

2. **No in-menu persistent install entry point.** The only path to install is the bottom sheet (which disappears after dismiss for 14 days). There is no low-pressure, always-available "Install App" option in the navbar or settings — users who dismiss once have no obvious way to install later.

3. **Manifest screenshots are not real screenshots.** The `screenshots` array uses `icon-192.png` and `icon-512.png` as screenshot `src` values. Chrome's enhanced install dialog (shown for PWAs with valid screenshots) requires actual UI screenshots at minimum 320px wide. Using icons here means the richer install dialog is never shown.

4. **iOS install instructions have no visual guide.** The iOS path shows text only ("Tap [share icon] then 'Add to Home Screen'"). Industry standard is to include an animation or still image showing the Safari Share button location — iOS users often don't know where to look.

5. **No `rel="canonical"` or install tracking.** There is no analytics event fired when the install prompt is shown, accepted, or dismissed. Without this, there is no data to optimize timing or messaging.

6. **`/api/share/` cache only matches 8-char slugs without query params.** The regex `^\/api\/share\/[A-Za-z0-9]{8}$` correctly excludes versioned/keyed requests but may miss slugs that evolve to longer IDs if the format changes. Low risk, worth noting.

7. **No background sync or IndexedDB for draft offline editing.** Users who start a team report offline have no persistence path — drafts are lost on connectivity loss. This is a medium-complexity gap but high-value for the core use case (tournament day editing).

## Top 3 Improvements

### Improvement 1: Engagement-Based Install Prompt Trigger

**Problem:** The current 15-second timer shows the install prompt regardless of user engagement. Research shows early prompts get ~1-3% acceptance; post-completed-action prompts achieve 1.8-2.2x higher acceptance (Google/web.dev data). For VGC players at tournaments specifically, the most persuasive moment is when they've just built or viewed a full team.

**Recommended trigger moments (priority order):**
1. After a user adds all 6 Pokemon to a team (highest intent — they've committed)
2. After viewing a second team in the same session (return pattern confirmed)
3. After saving a report to their account (post-conversion — already bought in)
4. After the user has been on-site for 3+ minutes total (session depth proxy)

**Never show on:** first page load, shared link landing (`/s/*`), or during active damage calc/editing flow.

**Implementation approach:**
- Keep the existing `beforeinstallprompt` capture in `InstallPrompt.tsx`
- Replace the `setTimeout(() => setDismissed(false), 15000)` with a context/event-based trigger
- Expose a `triggerInstallPrompt()` function via a lightweight React context (`InstallPromptContext`)
- Call `triggerInstallPrompt()` from relevant action handlers (team completion, save success, etc.)
- Add a `sessionStorage` "session-team-views" counter; trigger after count reaches 2

**Effort:** ~2 hours. The existing prompt UI and logic is already correct — only the trigger mechanism changes.

**Copy enhancement for VGC context:**
- Current: "Get instant access from your home screen with offline support"
- Improved: "Works offline at tournaments — instant access, no internet needed"

### Improvement 2: Real Screenshots in Manifest + 192px Maskable Icon

**Problem:** Chrome's enhanced PWA install dialog (introduced mid-2023, now widely shown) shows actual app screenshots when the manifest `screenshots` array contains valid images. Currently, the app uses icon PNGs as screenshot `src` values — Chrome ignores these and falls back to the minimal install UI. Additionally, Lighthouse flags the absence of a `purpose: "maskable"` icon at 192x192, which affects Android icon rendering.

**Recommended manifest changes:**

```json
"screenshots": [
  {
    "src": "/screenshots/mobile-team-report.png",
    "sizes": "390x844",
    "type": "image/png",
    "form_factor": "narrow",
    "label": "Build and share VGC team reports with damage calcs and matchup plans"
  },
  {
    "src": "/screenshots/mobile-explore.png",
    "sizes": "390x844",
    "type": "image/png",
    "form_factor": "narrow",
    "label": "Browse community VGC team reports on the go"
  },
  {
    "src": "/screenshots/desktop-team-report.png",
    "sizes": "1280x800",
    "type": "image/png",
    "form_factor": "wide",
    "label": "Full-featured team report builder with EV spreads and damage calcs"
  }
],
"icons": [
  { "src": "/favicon.svg", "sizes": "any", "type": "image/svg+xml" },
  { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
  { "src": "/icon-192-maskable.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
  { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" },
  { "src": "/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
]
```

**Screenshot creation:** Take real browser screenshots at 390x844 (iPhone viewport) and 1280x800 (desktop). Capture the team report view and explore page — these show the core value proposition. Use DevTools device mode for consistent sizing.

**Note on maskable icons:** The maskable safe zone is the inner 80% of the icon. Ensure the Pokeball mark fits within a centered circle at 60% of the image width. Keep outer 20% as safe bleed area (transparent or brand background color `#0B0B1A`).

**Effort:** ~1.5 hours (screenshot capture + image prep + manifest edit). Zero code changes to components.

### Improvement 3: Persistent Low-Pressure Install Entry Point in Nav

**Problem:** Once a user dismisses the install bottom sheet, the 14-day cooldown means they have no way to install the app until the cooldown expires — even if they change their mind 5 minutes later. There is no persistent install path in the UI. Industry pattern (Starbucks, Twitter/X, Notion) is to keep a low-prominence "Install App" option in the menu/settings as a permanent fallback.

**Implementation approach:**
- In `PersistentNavbar` or a Settings/Profile dropdown, add an "Install App" menu item
- Wire it to the same `InstallPromptContext.triggerInstallPrompt()` from Improvement 1
- Show only when: `deferredPrompt !== null` (Android) OR iOS Safari detected and not standalone
- On click: fire `deferredPrompt.prompt()` immediately (no bottom sheet needed — user explicitly chose)
- For iOS: show a small inline popover with the Share button instruction (since no native prompt available)

**Visibility logic:**
```tsx
// Show install menu item when installable but not yet installed
const showInstallOption = !isStandalone && (hasNativePrompt || isIOSSafari);
```

**UX note:** Label it "Install App" not "Add to Home Screen" — the latter is too technical. Place it at the bottom of the user menu, below account options, with a download icon. It should feel like a convenience option, not a sales pitch.

**Effort:** ~1 hour once the context from Improvement 1 exists (or ~2 hours standalone).

## Quick Wins Implementable Tonight (< 2 Hours Total)

### QW1: Manifest Screenshots (~45 min)
Take real screenshots of the app (team report page + explore page) at mobile and desktop sizes. Replace the icon-based `src` entries in `manifest.json`. No component changes needed. Immediately unlocks Chrome's rich install dialog.

**Steps:**
1. Open app in Chrome DevTools, set device to "iPhone 14 Pro" (390x844)
2. Navigate to a team report page — screenshot with `Cmd+Shift+3` or DevTools capture
3. Repeat for Explore page and desktop (1280x800)
4. Save to `public/screenshots/`
5. Update `public/manifest.json` `screenshots` array with real paths and dimensions

### QW2: Add 192px Maskable Icon Entry (~15 min)
If a `icon-192-maskable.png` exists or the 512px maskable works at 192 (it does — browsers downsample), add the explicit 192px maskable entry to `manifest.json`. This resolves the Lighthouse "Does not have a maskable icon" warning.

```json
{ "src": "/icon-512.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" }
```

Quickest fix: add this as an additional entry. Browsers will use the closest size.

### QW3: iOS Install Instructions — Add Visual Indicator (~30 min)
In `InstallPrompt.tsx`, the iOS path currently shows text only. Add a simple animated CSS arrow pointing upward (toward the Safari toolbar) alongside the share icon:

```tsx
{/* Animated pulse arrow toward browser chrome */}
<div className="mt-3 flex items-center gap-2 text-xs text-text-tertiary animate-pulse">
  <svg ...upward-arrow... />
  <span>The share button is at the bottom of Safari</span>
</div>
```

No external dependency. Pure CSS + inline SVG. Reduces iOS install friction meaningfully.

### QW4: Fire Analytics on Install Prompt Events (~20 min)
Add PostHog event tracking to `InstallPrompt.tsx` for `pwa_install_prompt_shown`, `pwa_install_accepted`, `pwa_install_dismissed`. This costs nothing and creates the data needed to optimize timing in future iterations.

```tsx
import { usePostHog } from "posthog-js/react";
const posthog = usePostHog();

// On prompt reveal:
posthog.capture("pwa_install_prompt_shown", { trigger: "timer", platform: deferredPrompt ? "android" : "ios" });

// On accept:
posthog.capture("pwa_install_accepted", { platform: "android" });

// On dismiss:
posthog.capture("pwa_install_dismissed", { platform: "android" });
```

## Summary Assessment

The PWA foundation is genuinely strong — custom service worker with thoughtful caching strategies per route type, share-page offline support specifically designed for tournament use, a well-crafted offline fallback page, proper update lifecycle management, and a polished install bottom sheet UI. This is above average for a Next.js app.

The three gaps that matter most are: (1) the prompt timing mechanism (15-second timer is a blunt instrument — engagement-based triggers would meaningfully improve acceptance), (2) manifest screenshots (a 45-minute fix that unlocks the richer Chrome install dialog), and (3) the lack of a persistent install path for users who dismissed the prompt. All three are low-risk, no-regression changes.

The bigger longer-term opportunity is IndexedDB-backed offline draft editing (letting players build/edit teams with no connection), but that is a multi-day project, not a quick win.
