## TOP 5 SEO QUICK WINS — Wave 2 (29 Jun 2026)

### Win #1 — Fix duplicate `/compare` entry in `sitemap.ts` *[XS, MEDIUM]*

**File:** `/home/user/VGC-Team-Report/src/app/sitemap.ts` lines 16 and 18.

**Current state:**
```ts
{ url: `${BASE}/compare`, changeFrequency: "monthly", priority: 0.6, lastModified: now },   // line 16 (commit 484fa50, 29 May)
{ url: `${BASE}/changelog`, changeFrequency: "monthly", priority: 0.3, lastModified: now },
{ url: `${BASE}/compare`, changeFrequency: "monthly", priority: 0.5, lastModified: now },   // line 18 (commit 1d6c3def, 29 May)
```
`/compare` is listed **twice** in the static URL array, 7 minutes apart in two separate commits, with different priorities (0.6 and 0.5). The second add happened during a different patch session and clearly missed the first. Google will accept the duplicate but you're (a) sending mixed signals about priority on the same canonical URL and (b) shipping a sitemap that fails strict XSD validators (and Google Search Console's "issues" tab will surface it as a duplicate). Easiest fix in this entire audit, and the kind of thing that erodes trust in a sitemap audit log.

**Proposed change:** Delete line 18. Keep line 16 (priority 0.6 — slightly higher matches `/feedback` and is closer to `/compare`'s actual user value as a tool page).

**Impact:** Medium — keeps GSC clean and avoids confusing crawl-budget signal. Five-second fix.

**Effort:** XS (one line delete).

---

### Win #2 — Add `/api/` and `/sign-in*` to robots.txt explicitly, drop trailing slash ambiguity *[XS, LOW-MEDIUM]*

**File:** `/home/user/VGC-Team-Report/public/robots.txt`.

**Current state:**
```
User-agent: *
Allow: /
Disallow: /api/
```
Three concrete gaps:

1. **`Disallow: /api/`** disallows `/api/*` but NOT bare `/api`. Tighten to `Disallow: /api`. While the impact is small (no canonical `/api` URL exists), modern bot guidance prefers the prefix form.
2. **No `Disallow: /dashboard`, `/notifications`, `/embed/`.** These are noindexed at the page level via `metadata.robots`, but a robots.txt disallow is what stops a bot from spending crawl budget hitting them in the first place. `/embed/[id]` in particular is a hot path the OG unfurlers may try to index. Belt-and-braces hardening that costs three lines.
3. **No `Host:` directive.** Adding `Host: pokemonvgcteamreport.com` reinforces the `vercel.app → custom domain` canonical chain already enforced at the middleware level (301 in `middleware.ts:90-101`). Yandex honors `Host:`; Google ignores it but won't penalize.

**Proposed change:** See draft file.

**Impact:** Low–Medium. The `/api/` tightening + dashboard/embed disallow saves crawl budget; the explicit canonical signal is defense-in-depth.

**Effort:** XS (`public/robots.txt` is a static file, no rebuild needed).

### Win #3 — Add `BreadcrumbListJsonLd` to `/explore` and `/compare` (last two unbreadcrumbed primary surfaces) *[S, MEDIUM]*

**Files:**
- `/home/user/VGC-Team-Report/src/app/explore/page.tsx`
- `/home/user/VGC-Team-Report/src/app/compare/page.tsx`

**Current state:** `/explore` already emits a `CollectionPage` with a nested `BreadcrumbList` (lines 61-77 of `explore/page.tsx`), but as an **inline property** of the CollectionPage node, not a separate top-level `BreadcrumbList` graph. Google's BreadcrumbList rich-result eligibility prefers a standalone `application/ld+json` script with `@type: BreadcrumbList`. `/compare` has no breadcrumb at all.

The shared helper `BreadcrumbListJsonLd` is already in use on `/champions`, `/tournaments`, `/changelog`, `/faq`. Adding it to these two final primary surfaces brings the breadcrumb story to full sitewide coverage (excluding home, which Google specifically doesn't need a BreadcrumbList for).

**Proposed change:** Two-line addition to each page (see draft).

**Impact:** Medium. BreadcrumbList drives SERP breadcrumb display ("Home › Explore"), which lifts CTR ~5-15% in typical click-tracking experiments. Both pages are at #2+ in our internal-link map and the SERP appearance compounds.

**Effort:** S (two pages, two imports, three lines each).

### Win #4 — Wire `og:locale` and `twitter:creator` on root layout *[XS, LOW-MEDIUM]*

**File:** `/home/user/VGC-Team-Report/src/app/layout.tsx` (root metadata, lines 37-91).

**Current state:** Root `openGraph` block lacks `locale` and `localeAlternate`. `twitter` block has `card`, `title`, `description`, `images` but no `site` or `creator` handle. This means:

- Facebook / WhatsApp / iMessage previews on the root URL have no locale hint — they fall back to the page `<html lang="en">` attribute, which is fine, but explicit `og:locale = en_US` makes the unfurl more predictable across locale-aware platforms.
- Twitter Cards do not attribute the site to a Twitter account, so when someone tweets a `pokemonvgcteamreport.com` link the card has no author byline. The footer already links to `https://x.com/Manny64Official`, so the handle is known. Adding `twitter.creator: "@Manny64Official"` and `twitter.site: "@Manny64Official"` gets the author handle into every share card on the platform where VGC creators live.

**Proposed change:** Add four lines to root layout metadata. See draft.

**Impact:** Low–Medium. Twitter authorship signal is the bigger of the two — when a card has a `creator`, Twitter renders the @handle inline on the card itself, which is a discoverable link back to the build's author. Locale is housekeeping.

**Effort:** XS (single file, four lines).

### Win #5 — Drop redundant `BreadcrumbJsonLd` helper, alias to `BreadcrumbListJsonLd` *[XS, LOW]*

**File:** `/home/user/VGC-Team-Report/src/components/seo/JsonLd.tsx` lines 153-191.

**Current state:** Two functions emit byte-identical JSON-LD:
```ts
export function BreadcrumbJsonLd({ items }: { items: BreadcrumbItem[] }) { /* same body */ }
export function BreadcrumbListJsonLd({ items }: { items: BreadcrumbItem[] }) { /* same body */ }
```
`BreadcrumbJsonLd` is only used in `creator/[name]/page.tsx:56`; `BreadcrumbListJsonLd` is used everywhere else. Strict SEO impact is nil — but maintainability is real: two future devs will edit one and not the other. Consolidate.

**Proposed change:** Replace the body of `BreadcrumbJsonLd` with `return BreadcrumbListJsonLd({ items });`, OR delete the duplicate entirely and update the import in `creator/[name]/page.tsx`. The "delete" path is one line shorter; the "alias" path keeps backwards compatibility for any future copy-paste.

**Impact:** Low (code hygiene). Listed because (a) it's a real SEO-file cleanup that fits the XS budget and (b) the symbol confusion is an active footgun: I almost recommended one over the other multiple times during this audit before noticing they were identical.

**Effort:** XS (one file, one usage site).
