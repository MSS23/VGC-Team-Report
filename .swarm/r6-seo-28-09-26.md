## 1. Concrete defects — ranked, zero-conflict first

### D1. `/champions` hub is titled and schema'd for a dead regulation — CONFLICT-RISK: no
`src/app/champions/page.tsx`
- `title: "Pokemon Champions Format | Reg M-B & M-A Mega Teams"`, `HUB_DESCRIPTION`, all 10 `keywords`,
  and the `ItemList` JSON-LD `name`/`description` say **M-B / M-A only**. No M-C token anywhere, so the
  hub cannot rank for the only regulation anyone is searching in September.
- The file's own header comment documents this exact failure mode one rotation ago
  (“It used to be pinned to ‘Regulation M-A’, which went stale the moment the format rotated to M-B and
  left the hub page invisible for every ‘Reg M-B’ query (VGC-258)”). The regression has recurred; nothing
  prevents it structurally.

### D2. Six M-C Megas have no landing page at all — CONFLICT-RISK: no
`src/lib/data/mega-pokemon.ts`
- Missing entirely from `MEGA_POKEMON_LIST`: **Mega Salamence, Mega Golisopod, Mega Baxcalibur**, and the
  three brand-new **Z Mega Evolutions** (Absol Z, Garchomp Z, Lucario Z).
- Mega Salamence was deliberately *deleted* as illegal (see `changelog/data.ts` v5.7: “Mega Salamence,
  Mega Metagross, and Mega Mawile have been removed… Their `/champions/{slug}` landing pages now return
  **404**”). Metagross and Mawile were restored for M-B; **Salamence was not**, and M-C has now made it
  legal again. Pikalytics already ranks a dedicated
  `pikalytics.com/pokedex/gen9championsvgc2026regmc/Salamence-Mega` page.
- Z Mega Evolution is an entirely new mechanic with zero coverage anywhere on the site — highest-value
  land-grab available, because almost nobody has published on it yet.

### D3. `/champions` ItemList JSON-LD advertises 3 URLs the site never builds — CONFLICT-RISK: no
`src/app/champions/page.tsx` L43 vs `src/app/champions/[pokemon]/page.tsx` L28
- Schema is built from `getRegMBMegas()` (**75** entries); `generateStaticParams` and `sitemap.ts` both use
  `getRegMBMegasWithSprites()` (**72**).
- Net effect: the `ItemList` emits `url`s for `meowstic-mega`, `raichu-mega-x`, `raichu-mega-y` — never
  prerendered, never sitemapped, never linked, and by the codebase's own comment they “would render as a
  broken-image page.” Structured data that points at pages the site refuses to link is a quality signal
  against the hub. Filter the schema with `getRegMBMegasWithSprites()` (or whatever the M-C successor is).

### D4. Seven shipped translations, zero indexable localized URLs — CONFLICT-RISK: no
`src/lib/i18n/translations/{en,es,fr,it,ja,ko,zh}.ts`
- Full UI translations exist for 7 languages, but there are **no locale route segments, no
  `alternates.languages`, and no `hreflang`** anywhere in `src/app/` (grep: zero hits). Localization is
  client-side only, so every non-English string is invisible to search.
- Pikalytics monetizes exactly this with indexable localized variants
  (e.g. `…/pokedex/gen9championsvgc2026regmc/Mr.%20Mime?l=fra`). This is 7× the addressable index for
  content already written and paid for.

### D5. `/embed/[id]` sets `robots` via a raw `<meta>` in the component tree — CONFLICT-RISK: no
`src/app/embed/[id]/page.tsx` L29
- Every other private route uses `export const metadata = { robots: { index: false, follow: false } }`
  (`dashboard/page.tsx`, `dashboard/profile/layout.tsx`, `dashboard/privacy/layout.tsx`,
  `dashboard/notifications/page.tsx`, `notifications/page.tsx`). This one hand-rolls
  `<meta name="robots" content="noindex, nofollow" />` inside returned JSX, which Next.js does not hoist
  into `<head>`. It lands in `<body>`, where honoring it is at the crawler's discretion, and it is
  invisible to the App Router metadata merge. Convert to the `metadata` export for parity.

### D6. `/api/oembed` exists but is undiscoverable — CONFLICT-RISK: no
`src/app/api/oembed/route.ts`
- The endpoint is implemented and returns a `thumbnail_url`, but **no page emits
  `<link rel="alternate" type="application/json+oembed" …>`** (grep across `src/**/*.tsx`: zero hits).
  No consumer (Discord, Notion, WordPress, Slack) can ever find it, so the whole route is dead weight.
  Also note `robots.txt` `Disallow: /api/` covers it.

### D7. All 72 Mega guide pages publish a stale legality claim — CONFLICT-RISK: **yes** (`champions/[pokemon]/page.tsx`, 2 open PRs)
`src/app/champions/[pokemon]/page.tsx` L38-50, `regulationCopy()`
- `legalIn` resolves to `"Regulation M-B"` or `"Regulation M-A and M-B"`, and that string is injected into
  the `<meta description>` of every guide page. Since M-C keeps all prior-reg Pokémon legal, **all 72
  pages now understate legality** and none carries the `"Regulation M-C"` keyword. Same class of bug the
  function's docstring warns about (“would publish a factually false legality claim”).
- Sibling instance, same cluster: `src/app/tools/ev-to-sp/page.tsx` L20 — `DESCRIPTION` says
  “Pokémon Champions **Regulation M-A**”, two regulations stale. CONFLICT-RISK: yes.

### D8. `s/[id]` error + not-found paths inherit `canonical → homepage` and `index: true` — CONFLICT-RISK: **yes** (2 open PRs)
`src/app/s/[id]/page.tsx` L29 and L143
- `src/app/layout.tsx` L82-88 sets root `alternates.canonical = "https://pokemonvgcteamreport.com"` and
  `robots: { index: true, follow: true }`. App Router **merges** layout metadata into pages, so any return
  path that omits both fields silently inherits them.
- Two paths do exactly that: `if (rows.length === 0) return { title: { absolute: "VGC Team Report" } }`
  (share deleted/never existed) and the bare `catch { return { title: { absolute: "VGC Team Report" } } }`
  (DB blip). Both emit `<link rel="canonical" href="https://pokemonvgcteamreport.com">` on a `/s/<id>`
  URL while remaining indexable. Since `sitemap.ts` submits **up to 5,000** `/s/` URLs, one Neon hiccup
  during a crawl window makes a large batch of share URLs all claim the homepage as canonical —
  a genuine mass-duplicate-canonical event. Fix: return explicit `robots: { index: false, follow: false }`
  plus a self-canonical on both branches.

### D9. `/explore` has no filtered/paginated-variant handling — CONFLICT-RISK: no
`src/app/explore/page.tsx`
- The page hard-codes a single `canonical` and reads no `searchParams`. `WebSiteSchema` in
  `JsonLd.tsx` actively advertises `?q={search_term_string}` to Google as a SearchAction target, and the
  filter UI generates `?format=`/`?pokemon=`/`?tournament=`/`?rental=` combinations. Every one of those
  resolves to near-identical content under a distinct URL with the same self-canonical. Either noindex the
  parameterized variants or generate real faceted landing pages (see K2/K5 below — the latter is worth far
  more).

### D10. Sitemap emits ~10,000 URLs with no `lastModified` on any static entry — CONFLICT-RISK: **yes** (2 open PRs)
`src/app/sitemap.ts`
- Share and creator rows carry `lastModified`; **none of the 12 static pages or the 72 Mega guide pages
  do**, so crawlers get no recrawl hint on exactly the pages that must re-rank after a regulation rotation.
- `/creator/[name]` is submitted for up to 5,000 names with no minimum-report threshold, so
  single-report creators are sitemapped as thin pages.

## 3. What is actually healthy (no action)

**absolute apex URLs everywhere**, which neutralizes the `vgc-team-report.vercel.app`
duplicate-domain risk without needing a redirect; `robots.txt` uses one correct wildcard group;
all five private/auth routes are properly `noindex`; JSON-LD coverage is genuinely strong
(Organization, WebSite+SearchAction, WebApplication, HowTo, FAQPage, BreadcrumbList, ItemList,
CollectionPage, SportsEvent, CreativeWork with author/contributor split); `JsonLd.tsx` escapes `<`
against injection; per-route OG/Twitter tags are complete with 5 dynamic `opengraph-image` routes;
`/s/[id]` correctly noindexes private, unlisted, and `?key=` collaborator URLs.
