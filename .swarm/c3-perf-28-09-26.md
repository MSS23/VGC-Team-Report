# Findings (zero-conflict first)

## F1 — jspdf's optionalDependencies ship 383 KB of unused JS (incl. a second rasteriser)
**CONFLICT-RISK: no** (`next.config.ts` and `src/lib/utils/export-report.ts` are touched by 0 open PRs)

**Measured.** `jspdf@4.2.1` declares `optionalDependencies: { canvg, core-js, dompurify, html2canvas }`.
All are installed and all are emitted as real chunks:

| Chunk | Library | Raw | Gzip |
|---|---|---|---|
| `3gti1qdk5epqn.js` | html2canvas **1.4.1** | 198,037 | 44,704 |
| `0kjxc7ap1h92i.js` | canvg 3.0.11 | 157,244 | 49,408 |
| `0un5oef30t7pr.js` | dompurify 3.4.13 | 28,192 | 10,433 |
| **total** | | **383,473** | **104,545** |

Identified positively: `198,037` vs `node_modules/html2canvas/dist/html2canvas.min.js` = `198,689`.
This is a **duplicate rasteriser** — the app already uses `html2canvas-pro@2.0.2` (225,912 B,
`0k0aodha5k86u.js`) via the singleton in `src/lib/dynamic-imports/html2canvas.ts`.

Loader stub `3pmo22h58c3r_.js` (693 B) is what registers them:
```
48503, t=>{ t.v(o=>Promise.all(["static/chunks/3gti1qdk5epqn.js"]...) }   // html2canvas 1.4.1
95111, t=>{ t.v(o=>Promise.all(["static/chunks/0kjxc7ap1h92i.js"]...) }   // canvg
70653, t=>{ t.v(o=>Promise.all(["static/chunks/0un5oef30t7pr.js"]...) }   // dompurify
```

`export-report.ts` only ever calls jsPDF's raster API (`addImage`), never `.html()` or
`.addSvgAsImage()`, so all three code paths are dead.

* **Cause**: Turbopack resolves jspdf's optional deps because they are present in `node_modules`.
* **Fix**: in `next.config.ts`, add `turbopack.resolveAlias` mapping `canvg`, `dompurify` and
  `html2canvas` to a 1-line no-op stub module (keep `html2canvas-pro` untouched — different
  specifier, so the singleton is unaffected).
* **Expected saving**: 383,473 B raw / 104,545 B gz removed from deployed static output;
  ~8 MB off `node_modules`; removes the duplicate-rasteriser footgun.
* **Diff size**: ~10 lines, 1 file (+ a 1-line stub file).
* **Caveat, stated honestly**: these three are lazy-behind-lazy (only fetched if jsPDF reaches
  those paths), so user-facing first-load saving is 0. This is deploy-size + correctness hygiene,
  not a Core Web Vitals win. Rank it first only because it is free and conflict-free.

## F2 — a PDF export downloads 630 KB raw / 183 KB gzip, 418 KB of it just to wrap one PNG
**CONFLICT-RISK: no** (`export-report.ts` 0 hits; `package.json` ×3 but this is a one-line dep removal)

Traced through loader `3yrhe_qhfkwi5.js` (the compiled form of `src/lib/utils/export-report.ts`):

| Chunk | Raw | Gzip |
|---|---|---|
| `3yrhe_qhfkwi5.js` (loader) | 1,620 | — |
| `0k0aodha5k86u.js` html2canvas-pro | 225,912 | 52,722 |
| `3pmo22h58c3r_.js` (stub) | 693 | — |
| `3wb7i39y47n9u.js` jsPDF | 418,428 | 128,979 |
| **total** | **646,653** | **~183,000** |

`html2canvas-pro` is unavoidable (it does the rasterising) and, to be clear, is **not** duplicated —
all three registrations of module `70830` (`1g6-83jrx4acj.js`, `1h1mva18qlxjk.js`,
`3yrhe_qhfkwi5.js`) point at the same `0k0aodha5k86u.js`, so the singleton in
`src/lib/dynamic-imports/html2canvas.ts` is working correctly.

jsPDF, however, is 418,428 B (128,979 B gz) used only to put an already-rendered PNG onto a page.

* **Cause**: `src/lib/utils/export-report.ts:5` → `const mod = await import("jspdf")`.
* **Fix (pick one)**: (a) emit the single-image PDF by hand — a one-page PDF wrapping a JPEG/PNG
  is ~80 lines of string/`Uint8Array` assembly, no dependency; or (b) move PDF generation into
  the existing server route `src/app/api/team-graphic/route.tsx` so jsPDF never reaches the client.
* **Expected saving**: 418,428 B raw / 128,979 B gz per PDF export (−65% on that path), and F1
  becomes moot because jspdf leaves `package.json` entirely (−29 MB `node_modules`).
* **Diff size**: medium — 1 new util (~80 lines) + edit `export-report.ts` + drop the dep.

## F3 — @clerk is 199 KB raw / 58 KB gzip on all 22 routes, including 8 with no auth UI at all
**CONFLICT-RISK: yes** (`src/app/layout.tsx` ×1, `src/components/layout/PageNavbar.tsx` ×1)

The root layout's client chunk group is one indivisible group of 5 chunks on **every** route:

| Chunk | Raw | Gzip | What |
|---|---|---|---|
| `2eekuzkw77x2a.js` | 107,027 | 31,049 | @clerk/react core (chunk literally opens with `buildErrorThrower({packageName:"@clerk/react"})`) |
| `30c-09oqb9kj6.js` | 50,471 | 12,103 | clerk-js loader / IsomorphicClerk |
| `29qmbdn-xgjpj.js` | 41,547 | 14,836 | @clerk/shared |
| `3tab1r0k4d96l.js` | 16,225 | 6,369 | KeylessCookieSync + PostHog glue |
| `1bghurpleveap.js` | 35,728 | 13,724 | vanilla-cookieconsent + app layout code |
| **total** | **251,000** | **78,081** | |

Clerk's own share: **199,045 B raw / 57,988 B gzip**.

The client-reference manifest shows the group is shared by exactly these entry modules,
identically on `/`, `/faq`, `/dashboard`, `/explore`, `/creator/[name]`, `/champions/[pokemon]`:
```
@clerk/nextjs/dist/esm/client-boundary/controlComponents.js
@clerk/nextjs/dist/esm/client-boundary/uiComponents.js
@clerk/nextjs/dist/esm/client-boundary/hooks.js
@clerk/nextjs/dist/esm/app-router/client/ClerkProvider.js
@clerk/nextjs/dist/esm/app-router/client/keyless-cookie-sync.js
src/components/ui/DeferredLayoutExtras.tsx
src/components/providers/PostHogProvider.tsx
src/components/providers/ClarityProvider.tsx
src/components/providers/CookieBanner.tsx
src/components/layout/PersistentNavbar.tsx
```

* **Cause**: two independent pulls. (1) `src/app/layout.tsx:106` wraps the entire tree in
  `<ClerkProvider>`. (2) `src/components/layout/PageNavbar.tsx:5`
  `import { SignInButton, UserButton, useAuth } from "@clerk/nextjs"` — reached from
  `PersistentNavbar`, which the root layout renders on every route.
* **Routes that need none of it**: `/faq`, `/privacy`, `/terms`, `/support`, `/tools/ev-to-sp`,
  `/tournaments`, `/champions`, `/champions/[pokemon]` — the last being **74 SSG pages** the
  CLAUDE.md flags as SEO-critical.
* **Fix**: introduce an `(app)` route group holding `ClerkProvider` + the auth navbar island, and
  leave the static/marketing/SEO routes in a Clerk-free layout. Lower-effort partial: pull
  `SignInButton`/`UserButton` into a `NavAuth` island behind `next/dynamic(..., { ssr: false })`
  so `uiComponents.js` leaves the layout group.
* **Expected saving**: up to 199,045 B raw / 57,988 B gz on those 8 route patterns.
  `/champions/[pokemon]` 833 KB → ~634 KB (**−24%**); `/faq` 695 KB → ~496 KB (**−29%**).
* **Diff size**: medium (new route-group layout, move 4 provider mounts, 1 new island component).
* **Note**: the biggest single piece (`2eekuzkw77x2a.js`, @clerk/react core) is required by
  `ClerkProvider` itself, so the dynamic-island-only variant recovers materially less than the
  route-group split. The route-group split is the finding worth a ticket.

## F4 — POKEMON_DATA is eager in /compare's first load: 193,674 B raw / 38,183 B gzip
**CONFLICT-RISK: yes** (`src/components/compare/CompareContent.tsx` ×4; an open PR also adds
`src/components/compare/__tests__/compare-eager-imports.test.ts`, so this likely overlaps VGC-271 —
check before filing)

`/compare` is the heaviest route at **1,068 KB**. Two ~190/130 KB data chunks are eager on it:

* `3yv3y7esj_hpn.js` — 193,674 B raw / 38,183 B gz — **`src/lib/data/pokemon.ts` (source 243,217 B)**
* `2s786ain9e09t.js` — 131,143 B raw — `src/lib/data/dex-subset.json` (source 129,858 B) → **VGC-257/271, excluded**

Disambiguated by ability-string counts, which are exact: `pokemon.ts` contains `Overgrow` 32×,
`dex-subset.json` 36×; the chunks contain 32× and 36× respectively.

* **Cause**: `CompareContent.tsx` imports `POKEMON_DATA` at module scope; only the ~12 species in
  the two pasted teams are ever read.
* **Fix**: `const { POKEMON_DATA } = await import("@/lib/data/pokemon")` inside the compare
  handler, or expose a `getPokemon(slug)` accessor that lazily imports.
* **Expected saving**: 193,674 B raw / 38,183 B gz off `/compare` (1,068 → 874 KB, −18%).
* **Diff size**: small (1 file, ~15 lines).

## F5 — vanilla-cookieconsent (CSS + JS) on all 88 prerendered pages, for every repeat visitor
**CONFLICT-RISK: yes** (`src/components/providers/CookieBanner.tsx` ×1)

* `1y8ji36wj_c16.css` — 35,001 B raw / 6,191 B gz — is `vanilla-cookieconsent/dist/cookieconsent.css`
  (32,207 B on disk; the chunk carries the `cc--` selectors, the main 169,884 B Tailwind sheet
  does not). Referenced by **88/88** prerendered HTML files.
* The 23,296 B ESM lib sits inside `1bghurpleveap.js` (35,728 B raw / 13,724 B gz), also on all routes.

`CookieBanner.tsx` does a static `import * as CookieConsent from "vanilla-cookieconsent"` plus a
static CSS import, so both are in the layout's critical path even for visitors who consented months
ago (`cc_cookie`, 365-day expiry).

* **Fix**: `next/dynamic(() => import("./CookieBannerImpl"), { ssr: false })`, mounted only when
  `document.cookie` lacks `cc_cookie`; move the CSS import inside the lazily-loaded module.
* **Expected saving**: ~58 KB raw / ~20 KB gz (JS + CSS) on every repeat visit; first visit unchanged.
* **Diff size**: small (split 1 file into 2).
