## Proposal: Attach the team card PNG to the native share sheet (`navigator.share({ files })`)

### Problem

The Web Share API call at `ShareModal.tsx:291–301` sends only `{ title, url }`:

```ts
await navigator.share({ title, url: publicUrl });
```

When a mobile user taps the primary "Share via…" button, the OS share sheet hands the URL to the chosen app (iMessage, WhatsApp, Discord, Instagram, Signal). Receiving apps unfurl the URL — but the `/s/[id]` route deliberately disables OG images (`src/app/s/[id]/page.tsx` has `openGraph: { images: [] }` and `twitter: { images: [] }` because edge OG generation timed out under sprite-CDN race conditions, see comment on lines ~92–103). So every native share lands as a **text-only link** in the receiving thread. The viral hook — six Pokémon sprites on a gradient card — never arrives at the receiver.

Meanwhile, the team card is already rendered in two places in the modal:
- As a scaled-down compact preview at the top (`TeamCardExport` with `compact`).
- As an off-screen 600×338 capture node that html2canvas exports to PNG for the "Download Team Card" button (`TeamCardExport.tsx:34–60`).

The receiver of a native share never sees this image. The Spotify Wrapped / Strava monthly-recap pattern is to bundle the image INTO the share payload, not link to it.

### Solution

Upgrade `handleNativeShare` to pre-render the team card PNG via the existing html2canvas pipeline and pass it as a `files: [File]` array on `navigator.share`. Web Share Level 2 has shipped on iOS 16.4+ and Chrome/Android for years; the support check is `navigator.canShare({ files: [file] })`.

```ts
// Pseudocode for the change inside ShareModal.tsx:291
const handleNativeShare = async () => {
  const title = tournamentName
    ? `${tournamentName}${placement ? ` (${placement})` : ""} VGC Team Report`
    : "VGC Team Report";

  // Try to attach the team card PNG. Fall back to URL-only on any failure.
  let files: File[] | undefined;
  try {
    if (teamSpecies.length > 0 && typeof navigator.canShare === "function") {
      const node = captureNodeRef.current; // lifted from TeamCardExport
      if (node) {
        const html2canvas = await getHtml2Canvas();
        const canvas = await html2canvas(node, { useCORS: true, scale: 2, backgroundColor: null });
        const blob: Blob | null = await new Promise((res) =>
          canvas.toBlob(res, "image/png")
        );
        if (blob) {
          const fileName = `${(teamName || "vgc-team").toLowerCase().replace(/\s+/g, "-")}.png`;
          const file = new File([blob], fileName, { type: "image/png" });
          if (navigator.canShare({ files: [file] })) {
            files = [file];
          }
        }
      }
    }
  } catch {
    // Card render failed — share URL-only.
  }

  try {
    await navigator.share(files ? { title, url: publicUrl, files } : { title, url: publicUrl });
    posthog?.capture("share_native_used", {
      has_tournament: !!tournamentName,
      with_image: !!files,
    });
  } catch {
    // User cancelled — no-op
  }
};
```

This requires:
1. Surface the existing off-screen capture node from `TeamCardExport` via a forwarded ref or a `captureRef` prop. Today the ref is private to `TeamCardExport`; lift it so `ShareModal` can pass its own ref in.
2. Render the capture node (the `!compact` branch at `TeamCardExport.tsx:65–193`) inside the modal even when the visible variant is `compact`, OR add a `captureRef` prop to the `compact` variant that injects a parallel hidden off-screen capture div. The simpler change: render BOTH branches when used in the modal — the visible `compact` preview AND an `aria-hidden` off-screen full-size node — and accept a `captureRef` so `ShareModal` can grab it.
3. Add the canShare-files capability check so Android browsers without file-share support fall back gracefully to URL-only (current behaviour).

### Why this beats Improvement R5 (pre-rendered OG image in Blob) for tonight

- The OG image revival requires server infrastructure (Vercel Blob bucket, cron or save-time job, DB column). 2 days minimum.
- This attaches the same visual artifact via a different channel — the OS share sheet — entirely client-side, no DB/Blob/cron work.
- It also lands in surfaces where OG images don't help: iMessage thread previews carry the file inline; WhatsApp gets it as an image-with-caption; Instagram Stories opens the IG composer with the image pre-loaded; Discord receives it as an attachment in the channel.
- A future Blob-backed OG image is still worth doing — but this ships an aligned win tonight without blocking on it.

### Risks & mitigations

- **html2canvas adds latency.** Currently fires when the user taps Download, accepted ~1–2s wait. Adding it to native share means the OS share sheet opens 1–2s later than today. **Mitigation:** kick off the canvas render the moment the share modal opens (not on tap), so by the time the user hits "Share via…" the blob is ready. Cache it for the lifetime of the modal.
- **Some apps strip the file in favour of the URL.** e.g. Twitter/X via OS share frequently honours `url` and ignores `files`. **Mitigation:** that's the same as today — URL-only — so no regression. The change is purely additive for apps that DO honour files (iMessage, WhatsApp, Discord, Instagram, Photos).
- **`canShare({ files })` returns false on some old browsers.** **Mitigation:** fall through to URL-only (current behavior).
- **CORS on sprite endpoints.** Already handled inside `TeamCardExport.handleExport` (`useCORS: true`) and surfaces a friendly error today. Same path here.

### Expected impact

- iMessage / WhatsApp shares now include the team-card image inline — recipient sees the six sprites + tournament + placement BEFORE the link unfurls.
- Instagram Stories share path becomes one-tap (the OS hands the image to IG's Stories composer). Today that requires Download PNG → open IG → manual paste.
- Closes the gap to Strava / Spotify Wrapped without touching the server.
- Measurable via the new `with_image: true` property on the existing `share_native_used` PostHog event — A/B-able by browser-capability cohort.
