## 4. Top 5 prioritized perf wins

### #1 — Get Zod 4 out of the client bundle  *(NEW — biggest single win available)*
- **File:** `src/lib/sharing/url-codec.ts` (imports `z` from `zod`); chunk `159f6ieur16al.js` (470KB raw / **114KB gz**) is dominated by Zod 4 (475 `zod`-named identifiers vs only 18 `motion`-named ones — confirmed by `grep -ao` of long identifiers: chunk contains `$ZodAsyncError`, `$ZodObjectJIT`, `$ZodCheckRegex`, etc.).
- **Reachable from client:** `src/app/page.tsx` directly imports from `@/lib/sharing/url-codec`; hooks `useHomePage`, `useShareUrl`, `useShareFlow`, `useCollaborativeSync`, `useAutoDraft` also import it. That pulls the full Zod runtime (`$ZodObjectJIT`, `$ZodDiscriminatedUnion`, every check class) into every page that uses the share-codec.
- **Proposed change (~2h):** Two options:
  1. Replace Zod with hand-rolled type guards in `url-codec.ts` — the schemas are mostly `z.object({…})` with primitives, easy to inline (~50 LOC of TS guards). Server APIs that genuinely benefit from Zod can keep their own copy.
  2. Or: split `url-codec.ts` into `encode.ts` (client-safe, no Zod) and `decode.ts` (server-side, Zod-validated), and have clients POST to a small `/api/decode-share` endpoint for the rare paste-from-URL flow.
- **Expected savings:** **~90–110 KB gzip** off every route that uses share state (home, compare, dashboard). This is the largest single bundle line item now that `@pkmn/dex` is gone.

### #2 — Deduplicate `dex-subset.json` across `/` and `/compare`  *(NEW)*
- **Files:** `src/lib/data/dex-subset.ts`, `src/lib/data/pkmn-dex-fallback.ts`
- **Problem:** Turbopack emits the dex-subset JSON content **twice** — once as `0ri0npkdfd9o4.js` (331KB, only on `/`) and again as `04jz-043dkbr4.js` (331KB, only on `/compare`). Byte-compared: differ only at the trailing wrapper bytes (different chunk IDs) but contain the same `JSON.parse('{"schemaVersion":1,…')` payload. A user who navigates `/` → `/compare` downloads 660KB raw / ~96KB gzip of the same data.
- **Proposed change (~1h):** Force the JSON into a shared chunk by either:
  1. Adding `dex-subset.json` to `experimental.splitChunks` or `optimizePackageImports` in `next.config.ts`, OR
  2. Lazy-loading it via `await import("./dex-subset.json")` inside `pkmn-dex-fallback.ts` (it's a fallback path — most users never hit it on first paint).
- **Expected savings:** ~331KB raw / **~48 KB gzip** on the second navigation between `/` and `/compare`. Cuts `/compare`'s First Load by ~13%.

### #3 — Lazy-load `motion/react` (carry-over from May 23 #3)
- **Files:** `motion/react` is in `069~_h90gxh59.js` (115KB raw / **37KB gz**) and reachable from 13+ client modules: `WhatsNewModal.tsx`, `PasteInput.tsx`, `ChangelogContent.tsx`, `MegaLandingContent.tsx`, `dashboard/profile/page.tsx`, `FeedbackContent.tsx`, `ExploreContent.tsx`, `ExploreFilters.tsx`, `ExploreEmpty.tsx`, `ReportCard.tsx`, `SpotlightCard.tsx`, `CreatorProfile.tsx`. `PasteInput.tsx` alone uses 35 `motion.*` calls.
- **Proposed change (~90min):** Replace cheap fade/slide transitions with Tailwind `transition` utilities + `data-[state=open]` classes; keep motion only for non-trivial spring physics. Specifically: `PasteInput.tsx` shimmer → CSS `@keyframes`; `Explore*` simple `<motion.div initial={{opacity:0}} animate={{opacity:1}}>` → Tailwind `animate-in fade-in`.
- **Expected savings:** **~30–37 KB gzip** off every route that doesn't genuinely need spring physics (i.e., most of them).

### #4 — Lazy-split move-name translations  *(NEW)*
- **File:** `src/lib/data/move-names.ts` (18 KB source) → emitted as chunk `0ql~0n~pt~r3d.js` (94KB raw / **28KB gz**, eager on `/`).
- **Problem:** `MOVE_NAMES` ships all 7 languages (fr/it/es/ja/ko/zh + en metadata) eagerly for every user. The `i18n/index.ts` already lazy-loads UI translation strings, but move-names are pulled in eagerly via `translate-move.ts` which is in the client graph (used by `PokemonDetailSlide` / `CalcInput`).
- **Proposed change (~45min):** Convert `move-names.ts` into a 7-file split mirroring `i18n/translations/*.ts`. Make `translateMove(name, lang)` await an `import()` for the right language and cache the map (English path returns instantly without any import). Anglophones (~80% of traffic per locale defaults) avoid the entire chunk.
- **Expected savings:** **~25 KB gzip** off the cold load for English users on `/`. Other languages defer to first translation call.

### #5 — Reduce duplicate React-DOM/scheduler chunk  *(NEW)*
- **File:** chunk `0rwwge57xnfls.js` (199KB raw / **62KB gz**) on every route — appears to ship the full **React-DOM client** including legacy event-system fallbacks (`$$reactFormReplay`, `SuspenseList`, `TransitionCancel`, full keycode table, all CSS Moz-prefix names). 62KB gz of framework on every page is heavy.
- **Proposed change (~30 min investigation, then config):** Investigate if `serverComponentsExternalPackages` or the Turbopack `compiler.removeConsole` / `compiler.styledJsx` options are stripping less than they could. Verify Next 16 is shipping `react-dom/client` minified, not a debug build. Also check whether `optimizePackageImports` in `next.config.ts` actually treats react-dom correctly under Turbopack — Next 16's Turbopack pipeline has had reports of less-aggressive minification than webpack's Terser. Worth A/B against `next build --no-turbo` to see what the legacy bundler produces.
- **Expected savings:** speculative — **~15–25 KB gzip** if the Turbopack minifier is leaving dead branches. Lower confidence than #1–#4 but applies to every route.
