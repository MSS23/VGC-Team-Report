## N1. Tailwind's `dark:` variant is wired to the OS media query, but the app's theme is `[data-dark-mode]` — 130 utilities render the wrong colour
**Files:** `src/app/globals.css:1-4` (no `@custom-variant dark`), no `tailwind.config.*` exists, `src/hooks/useDarkMode.ts:40-42`, `src/app/layout.tsx:102`
**WCAG:** 1.4.3 Contrast (Minimum) — **Level AA** · **Severity: Critical**

Tailwind v4 with no `@custom-variant dark` defaults `dark:` to `@media (prefers-color-scheme: dark)`. The app instead toggles `data-dark-mode` on `<html>` (`useDarkMode.ts:40`) and swaps the CSS custom properties in `globals.css:263-286`. The two are completely independent. There is even a code comment acknowledging the mismatch at `OffensiveCoverageChart.tsx:121` — but 130 `dark:` utilities across 30+ files were never migrated.

Two failure modes, both common:
- **A — user clicks the theme toggle to dark while the OS is light:** surfaces go dark, but only the *base* (light-tuned) colour applies.
- **B — user clicks the toggle to light while the OS is dark:** surfaces go light, but the *`dark:`* (dark-tuned) colour applies.

Measured (text over its own tinted chip background, over `--surface`):

| `text-rose-600 dark:text-rose-400` + `bg-rose-500/10` — `PokemonDetailSlide.tsx:772,824` | `#EC003F` on `#2C152D` = **3.70 FAIL** | `#FF637E` on `#FFE9EE` = **2.47 FAIL** |

**Exact fix** — one line in `src/app/globals.css`, immediately after line 4:

```css
@custom-variant dark (&:where([data-dark-mode], [data-dark-mode] *));
```

This makes every existing `dark:` utility follow the real theme attribute with zero component churn. Add a regression test asserting the variant exists (e.g. a vitest that reads `globals.css` and matches `/@custom-variant\s+dark\b/`), because the failure is silent.

```css

```

## N3. The report viewer has **no `<h1>` on any slide except slide 0**, and two slide types start at `<h3>`
**Files:** `src/components/report/TeamReport.tsx:236-393` (one slide rendered at a time), `TeamOverview.tsx:418,431` (the only `h1`), `CommonModesSlide.tsx:181` (`h3` is the slide's top heading), `DefensiveCoverageChart.tsx:72` (`h3`), `OffensiveCoverageChart.tsx` (`h3`), `PokemonDetailSlide.tsx:582` (`h2`), `SpeedTierChart.tsx:431` (`h2`), `MatchupPlanSlide.tsx:193` (`h2`), `MatchupSheet.tsx` (`h3`)

## N4. Destructive **Delete** control is a `<span onClick>` nested inside a `<button>` — keyboard users can never reach it
**File:** `src/components/report/MatchupPlanSlide.tsx:552-559` (inside the `<button>` opened at `:500`, closed at `:560`)
**WCAG:** 2.1.1 Keyboard (A), 4.1.2 Name/Role/Value (A), 1.3.1 (A) · **Severity: Critical**

```tsx
{!isReadOnly && canDelete && (
  <span
    onClick={(e) => { e.stopPropagation(); onDelete(); }}
    className="text-text-tertiary hover:text-red-400 text-xs px-2 py-1 rounded-md hover:bg-red-400/10 transition-colors"
  >
    {t.delete}
  </span>
)}
```
The `<span>` has no `role`, no `tabIndex`, no key handler, and sits inside an interactive `<button>` (invalid HTML — a button's content model forbids interactive descendants). Keyboard and screen-reader users get the collapse toggle only; the delete action is mouse/touch-only. Screen readers also fold the word "Delete" into the outer button's accessible name, so the collapse toggle announces as e.g. "Lead Incineroar Delete, button".

**Exact fix** — move it out of the button and make it a real button. Restructure `:500-560` so the toggle button and the delete button are siblings in a flex row:

```tsx
<div className="flex items-stretch">
  <button type="button" onClick={onToggleCollapse} aria-expanded={!isCollapsed} className="flex-1 …">
    {/* existing header content, minus the delete span */}
  </button>
  {!isReadOnly && canDelete && (
    <button
      type="button"
      onClick={(e) => { e.stopPropagation(); onDelete(); }}
      aria-label={`${t.delete} ${planLabel}`}
      className="inline-flex items-center justify-center min-w-11 min-h-11 px-2 text-xs text-text-tertiary hover:text-red-500 hover:bg-red-500/10 rounded-md transition-colors"
    >
      {t.delete}
    </button>
  )}
</div>
```
(Also fixes the 44×44 target: the span is currently `px-2 py-1` ≈ 34×22 px.)

## N5. framer-motion entrance animations ignore `prefers-reduced-motion` — the CSS override cannot reach them
**Files:** `src/components/input/PasteInput.tsx` (35 `motion.*` elements — the landing hero, sprite row, banner, "How it works"), `src/app/feedback/FeedbackContent.tsx` (14), `src/app/changelog/ChangelogContent.tsx` (8), `src/components/ui/WhatsNewModal.tsx` (4), `src/components/explore/SpotlightCard.tsx` (4), `src/app/dashboard/profile/page.tsx` (4), `src/app/champions/[pokemon]/MegaLandingContent.tsx` (3), `ReportCard.tsx`/`ExploreEmpty.tsx`/`ExploreContent.tsx`/`CreatorProfile.tsx` (2 each). Only `src/components/explore/ExploreFilters.tsx:6,130` calls `useReducedMotion`.
**WCAG:** 2.3.3 Animation from Interactions (AAA) + the project's own stated bar ("reduced-motion respected", CLAUDE.md UI standards) · **Severity: Critical (project bar), Serious (WCAG)**

`globals.css:812-819` sets `animation-duration`/`transition-duration` to `0.01ms` — that only affects **CSS** animations and transitions. framer-motion drives `initial`/`animate` via JS, writing inline `transform`/`opacity` per frame; the media query has no effect on it. So `/` (the highest-traffic page) plays a full staggered translate+scale entrance for a user who has explicitly asked for reduced motion.

**Exact fix** — a shared wrapper that neutralises variants globally, rather than 12 per-file edits.

Create `src/lib/motion/MotionConfigProvider.tsx`:
```tsx
"use client";
import { MotionConfig, useReducedMotion } from "motion/react";
export function ReducedMotionConfig({ children }: { children: React.ReactNode }) {
  const reduce = useReducedMotion();
  return <MotionConfig reducedMotion="user" transition={reduce ? { duration: 0 } : undefined}>{children}</MotionConfig>;
}
```
and mount it in `src/app/layout.tsx` around `{children}` (line 142):
```tsx
<ReducedMotionConfig>
  <div id="main-content">{children}</div>
</ReducedMotionConfig>
```
`reducedMotion="user"` makes framer skip `transform`/`layout` animations while keeping opacity, which is the WCAG-preferred behaviour. For the hero specifically, also drop the `y`/`scale` from `PasteInput.tsx:258-262, 271-273, 291-293` when `useReducedMotion()` is true so no element starts off-screen.

## N13. Three dialogs in the report/landing flow have incomplete focus management
**WCAG:** 2.4.3 Focus Order (A), 2.1.2 No Keyboard Trap / inverse (A), 4.1.2 (A) · **Severity: Serious**

Reference implementation to copy from: `src/components/ui/ShareModal.tsx:154-190` (initial focus + Tab cycle + Escape + restore) — also correctly done in `OTSSheetModal.tsx:136-175`.
