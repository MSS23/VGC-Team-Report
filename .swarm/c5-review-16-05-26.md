## Issues Found

### HIGH — VGC-182: totalReports denominator regression

**File:** `src/app/api/champions/meta/route.ts`

**Bug:** The SQL refactor changed the denominator used for percentage calculations.

- **Old behaviour:** `totalReports = rows.length` = count of *all* champion-tagged shares fetched (including shares with null/empty paste fields). Matches what a user would expect: "usage rate out of all champion reports."
- **New behaviour:** `totalReports = count(DISTINCT id) FROM per_team` = count of shares that produced at least one parseable species block. Shares with null or empty `data->>'paste'` are silently excluded from the denominator but were counted before.

**Impact:** Percentages are inflated whenever any champion-tagged share has a null/empty paste. If 10 out of 100 shares have empty paste, old code shows Groudon at 80/100 = 80%; new code shows 80/90 = 89%. The UI implies these are "out of all champion reports" so inflated numbers are misleading.

**Fix:** In the `total` CTE, count DISTINCT id from `filtered` instead of `per_team`:
```sql
total AS (
  SELECT count(DISTINCT id) AS total_reports FROM filtered
)
```
This matches the old semantics exactly.

### MEDIUM — iOS PWA install prompt: scroll-only gate locks out non-scrolling pages

**File:** `src/components/ui/InstallPrompt.tsx`

**Issue:** For iOS Safari, the install prompt fires only if `scrollFired` is `true` when the 60-second timer fires:
```ts
const iosTimer = setTimeout(() => {
  if (scrollFired) {  // prompt NEVER shows if page doesn't scroll
    setShowIOSPrompt(true);
    setDismissed(false);
  }
}, 60000);
```
The 60-second dwell timer fires but the iOS prompt is then gated solely on whether the user scrolled ≥200px within that 60 seconds. If the landing page renders fully above the fold (e.g. on a large-screen iPad), the user satisfies dwell but the prompt never appears. The Android path correctly uses `timerFired && scrollFired && promptReady` but the iOS path has no fallback.

**Fix:** Either drop the scroll gate for iOS (just use 60s dwell) or add a separate, longer timer (e.g. 120s) as a fallback that fires even without scrolling.

### MEDIUM — VGC-183: Delete confirmation has no keyboard dismiss (Escape) and no focus management

**File:** `src/components/match-tracker/MatchTracker.tsx`

**Issues:**
1. When `pendingDeleteId` is set and the inline Delete/Cancel buttons appear, focus is not programmatically moved to the Cancel (or Delete) button. Keyboard-only users won't know the UI changed.
2. There is no Escape key handler to cancel the pending delete. Standard pattern for in-place confirmations is Escape = cancel.
3. If a delete API call fails (non-`res.ok`), the error is silently swallowed — `setPendingDeleteId(null)` resets state but the user gets no feedback that the delete failed. The existing `fetchError` state could be reused for this.

**Fix:**
- Add `autoFocus` to the Cancel button when it renders.
- Add `onKeyDown={(e) => e.key === 'Escape' && setPendingDeleteId(null)}` to the confirm group.
- On failed delete: call `setFetchError("Failed to delete. Please try again.")`.

### LOW — VGC-182: NULL paste in champions DB silently skips shares (acceptable but undocumented)

**File:** `src/app/api/champions/meta/route.ts`

**Issue:** If `data->>'paste'` is NULL for a share, `regexp_replace(NULL, ...)` returns NULL, and the LATERAL `regexp_split_to_table` produces no rows for that share. The share contributes nothing to the aggregation. This is silently dropped.

This is the same behaviour as the old `if (!paste.trim()) continue;` guard. However, as noted in the HIGH issue above, the old code still counted these shares in the denominator (`totalReports = rows.length`) while the new SQL excludes them from the denominator (`count(DISTINCT id) FROM per_team`). The fix to the HIGH issue resolves this low-severity item too.
