### N1. Three broken concatenated Tailwind classes silently killed both the 44px targets and the font size (`min-h-11text-…`) — **NEW, HIGH, one-line each**

A missing space in a template-literal class string produces a single nonsense token. Tailwind emits nothing for it, so **both** the touch-target utility and the font-size utility are lost, with no error anywhere.

| File:line | Current token | Should be |
|---|---|---|
| `src/components/report/SpeedTierChart.tsx:132` | `py-1 sm:py-1.5 min-h-11text-[10px] sm:text-xs` | `py-1 sm:py-1.5 min-h-11 text-[10px] sm:text-xs` |
| `src/components/report/SpeedTierChart.tsx:482` | `px-3 py-1.5 min-h-11text-xs` | `px-3 py-1.5 min-h-11 text-xs` |
| `src/components/report/SpeedTierChart.tsx:500` | `px-3 py-1.5 min-h-11text-xs` | `px-3 py-1.5 min-h-11 text-xs` |

Consequences today:
- The eight `SideModifierToggle` chips (`:128-142`), the "Mega Forms" toggle (`:478-492`) and the "Meta Threats" toggle (`:494-509`) render at `py-1.5` ≈ **28px tall**, not 44 — the project's 2.5.5 standard and the exact thing the mobile-touch commit `0024679` intended to fix.

Regression origin: introduced by `0024679 "fix: mobile touch and layout fixes across report UI"`. This is the cheapest, safest win in the report — three character insertions, zero behaviour change, and it restores an already-approved fix. Worth a regression test that greps `src/**/*.tsx` for `/min-[hw]-\d+[a-z]/` and fails on a hit; the same class of typo will recur.

WCAG 2.5.5 (AAA) / project standard; 1.4.4 adjacent.
