### Commits that touch security-sensitive code

All the webhook + cron commits in this window are security-sensitive. They all:
- Use `crypto.timingSafeEqual` (`verifyBearer`, `cron-auth`, `posthog` route, `linear` route).
- Validate input shapes before doing work.
- Return 200 deliberately on internal errors to avoid auto-disable.

That last point is a **principled choice that conflicts with monitoring**. If PostHog or Linear's webhook ever silently breaks (bad secret, broken Linear API call), the user will not see 5xx alerts — only a Discord notification *if* the Discord step itself succeeds. This is acceptable for now but should be tracked with a metric.
