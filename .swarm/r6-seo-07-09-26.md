## 2. TOP FINDING (NEW) — `public/llms-full.txt` teaches the SP system backwards

### What is wrong

`public/llms-full.txt` line 91, verbatim:

> **SP (Stat Points or Standard Points)** is an alternative notation sometimes used in team reports and competitive coaching content — particularly in some international communities — where 1 SP = 1 EV. The terms are interchangeable. If you see a Pokémon listed with "252 SP Atk" it means the same thing as "252 EVs in Attack" (i.e., 252 Attack EVs).
>
> VGC Team Report accepts both notations when importing and displays EVs in the standard Showdown format on all report pages.

Every clause is false against `src/lib/analysis/stat-calculator.ts`:

| Claim in llms-full.txt | Reality (`stat-calculator.ts`) |
|---|---|
| "Standard Points" | SP = **Stat Points** (`CHAMPIONS_TOTAL_SP`, `CHAMPIONS_MAX_SP_PER_STAT`) |
| "1 SP = 1 EV", "interchangeable" | `evToChampionsSp()` (line 94): 0→0, non-zero→`max(1, ceil(ev/8))`, 248+→32. First SP costs 4 EVs, each subsequent 8. |
| "252 SP Atk" is a legal thing | Per-stat cap is **32 SP** (line 78). 252 SP is illegal by a factor of ~8. |
| "an alternative notation … in some international communities" | SP is the **mandatory** stat system of Pokémon Champions Reg M-A/M-B, not a notation preference. |
| "displays EVs in the standard Showdown format on all report pages" | `PokemonCard`, `PokemonDetailSlide` and `SpeedTierChart` all derive SP via `convertToChampionsSp` for Champions teams. |

Secondary staleness in the same file: line 46 describes `/champions` as "the Pokémon Champions format (Regulation M-A)"; line 64 defines Champions as introduced "under the name 'Regulation M-A'"; line 75 says support is "Champions Regulation M-A fully"; line 112 glossary repeats M-A-only. `Updated: 2026-05-23` (line 3). `/tools/ev-to-sp` and `/champions/[pokemon]` — the two page types that exist specifically to win SP queries — are **not listed anywhere in the file**.

### Why this is the highest-value quick win

- It is a **static text file**. No TSX, no build risk, no UI review, no DB. Roughly a 15-minute edit.
- It is the *only* asset on the site that AI crawlers read as authoritative first-party documentation. Both prior AEO audits (`r7-aeo-audit.md`, `r7-ai-citation.md`) graded llms.txt/llms-full.txt an "A" for AI citability — which means this specific paragraph is the paragraph most likely to be lifted verbatim into a ChatGPT/Claude/Perplexity answer about Champions SP.
- The site's entire differentiating claim is *"we handle Champions SP correctly."* This file says the opposite, in detail, with a worked example.
- Competitors already own the correct answer. RotomLabs, ChampDex, ChampCalc and BattleWise AI all publish the correct "first SP = 4 EVs, then 8; 66 total, 32 cap" formula (see §5). Publishing the wrong one is worse than publishing nothing.
- The fix has a natural, convention-compliant regression guard: extend the existing `sp-docs-drift.test.ts` to cover `llms-full.txt` with the same assertions, which is exactly the "regressions get a test that names the bug" rule in CLAUDE.md.

### Exact edit list

| File | Change |
|---|---|
| `public/llms-full.txt` | Rewrite the "What is the difference between SP and EVs?" answer (lines 87–93) to match `stat-calculator.ts`: SP = Stat Points; 66 total, 32 per stat; `SP = ceil(EV/8)` with a floor of 1 and a cap of 32; first SP costs 4 EVs, each after costs 8; 248 and 252 EVs both = 32 SP; 252/252/4 → 32/32/1 = 65 of 66. Drop the "Standard Points" and "1 SP = 1 EV" sentences entirely. |
| `public/llms-full.txt` | Lines 45–49, 64, 75, 112: change M-A-only phrasing to "Regulation M-A and M-B" (and M-C once shipped — see §4). |

## 3. Everything else found (repo state, 2026-09-07)

### 3.1 `/champions` ItemList advertises 3 URLs nothing links to — NEW, small

`src/app/champions/page.tsx:45` builds the `ItemList` JSON-LD from `getRegMBMegas()` — all **75** M-B-legal Megas. But `generateStaticParams` and `sitemap.ts` both use `getRegMBMegasWithSprites()` — **72**. The three sprite-less Megas (`meowstic-mega`, `raichu-mega-x`, `raichu-mega-y`, per `MEGAS_WITH_SPRITES` in `mega-pokemon.ts:870`) therefore appear in structured data as `ListItem.url` entries but are:
- not prerendered,
- not in the sitemap,
- rendered as non-clickable "Coming Soon" cards in the visible grid (`ChampionsContent.tsx:245`),
- still resolvable on demand (`dynamicParams` is not set, so it defaults to `true`) and would render with a broken sprite.

So JSON-LD contradicts both the sitemap and the visible page. Fix is one line — `getRegMBMegas()` → `getRegMBMegasWithSprites()` at `champions/page.tsx:45` — plus optionally `export const dynamicParams = false` in `champions/[pokemon]/page.tsx` so the three slugs 404 cleanly instead of serving a broken page. Note `HUB_DESCRIPTION` (line 10) says "All 75 legal Mega Evolutions", which stays accurate for the prose either way.

### 3.2 `/tools/ev-to-sp` metadata is pinned to Reg M-A — NEW, small

`src/app/tools/ev-to-sp/page.tsx:20` `DESCRIPTION`: *"Free EV to SP converter for Pokémon Champions Regulation M-A."* Keyword array line 33: `"Regulation M-A SP spread"`. The page **body** is already correct and format-agnostic (lines 107 and 214 both say "Regulation M-A and M-B"), so only the metadata is stale. Also `src/app/tools/ev-to-sp/page.tsx:344` CTA copy says the tool "checks the whole team against Regulation M-A legality" — `src/lib/validation/champions-legality.ts` handles M-A **and** M-B.

This page is well built otherwise: `force-static`, self-canonical, `WebApplication` + `FAQPage` + `BreadcrumbList` JSON-LD, seven FAQ items, two conversion tables generated from the real `evToChampionsSp`/`championsSpToEv` functions so they cannot drift. It is the strongest SEO asset in the repo.

## 4. NEW — Regulation M-C ships Sept 8, 2026 and the repo does not know it exists

Confirmed via WebSearch across Pokemon.com, Bulbapedia, GoNintendo, Nintendo Everything, RotomLabs, Game8 and Pokémon Zone:

- **Reg M-B ran June 17 → Sept 9, 2026. Reg M-C runs Sept 8, 2026 7:00pm PDT → Dec 1, 2026.** M-B is stale as of tomorrow.
- M-C adds **6 new Megas**: **Mega Salamence, Mega Golisopod, Mega Baxcalibur**, plus three **Z Mega Evolutions** — **Mega Absol Z** (Dark/Ghost, Sharpness), **Mega Garchomp Z** (pure Dragon, Levitate), **Mega Lucario Z** (Aura Guard / "Aura Break", halves contact damage). All three Z-Megas are base **151 Speed**.
- Plus **24 newly legal Pokémon**, including Rillaboom.

Repo state: `src/lib/data/mega-pokemon.ts` contains exactly the 75 M-B-legal Megas and **none** of the six M-C additions. There is no `CHAMPIONS_REG_MC_MEGAS` set, no M-C branch in `getMegaRegulation()` (which returns a hard `"M-A" | "M-B"` union at line 926), and `src/lib/validation/champions-legality.ts` is M-A/M-B only. `/champions` metadata reads "Reg M-B & M-A". Every `/champions/[pokemon]` page's FAQ asserts M-A/M-B legality as final.

**SEO consequence:** the highest-volume, lowest-competition Champions queries for the next 12 weeks are "Mega Salamence Champions", "Mega Baxcalibur SP spread", "Z Mega Evolution VGC", "Mega Garchomp Z Levitate", "Reg M-C legal Pokémon". Nobody has authority on these yet — Pikalytics' M-C pages will be empty of usage data for ~2 weeks. The repo already has the machinery to win them (72 prerendered Mega guides with FAQ schema, OG image routes, sitemap wiring). Adding 6 `MEGA_POKEMON_LIST` entries + a `CHAMPIONS_REG_MC_MEGAS` set + widening `getMegaRegulation()`'s return type is a **data-shaped change**, not an architecture change, and it unlocks 6 new SSG landing pages on day one of the format. This is time-boxed: the window closes as competitors fill it.

Caveat for the implementer: Showdown sprites for the M-C Megas almost certainly do not exist yet, so they would enter `MEGA_POKEMON_LIST` but stay out of `MEGAS_WITH_SPRITES` and therefore out of `generateStaticParams`/sitemap — i.e. "Coming Soon" cards only, no landing pages, until a sprite re-probe. Shipping the pages requires either a sprite probe or a non-sprite fallback layout for M-C pages.

- **The site is indexed and ranking for brand + `/explore`, `/faq`, `/tournaments`, `/champions`.** Those four surfaced directly in a brand query. So indexation is healthy — the problem is topical coverage, not crawlability. (Except `/s/`, which surfaced for nothing — consistent with VGC-275.)
