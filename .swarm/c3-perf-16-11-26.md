## 0. Methodology — why the numbers are computed, not copied

**Next 16 + Turbopack prints no size columns.** The emitted route table (build log lines 926–1011) has
only `Route (app) | Revalidate | Expire`. Every KB figure below is computed, **two independent ways that
agree to the byte**:

1. **RSC manifests** — `.next/server/app/**/page_client-reference-manifest.js`
   (`clientModules[*].chunks`) unioned with `build-manifest.json`'s `rootMainFiles` + `polyfillFiles`.
   This covers the dynamic (`ƒ`) routes that have no prerendered HTML.
2. **Prerendered HTML** — every `/_next/static/chunks/*.js` referenced by each
   `.next/server/app/**/*.html`, deduped, summed.

For all 18 prerendered content routes the two methods produce **identical** gzip totals (see the
`FL_GZ` vs `HTML_GZ` columns in §1), so the dynamic-route figures from method 1 are trustworthy.

> **Gotcha for the next auditor:** the obvious regex `/__RSC_MANIFEST\[[^\]]+\]/` **silently fails** on
> bracketed routes — the character class stops at the `]` inside `["/champions/[pokemon]/page"]`. That
> drops `/champions/[pokemon]`, `/creator/[name]`, `/s/[id]`, `/q/[id]`, `/embed/[id]` from the results
> with no error. Use `/__RSC_MANIFEST\[[\s\S]*?\]\s*=\s*(\{[\s\S]*)$/` and let it backtrack.

**Polyfill caveat:** `static/chunks/0cz1d0mv5g_q7.js` (110.0 KB raw / 38.6 KB gz) is emitted with
`<script noModule>`, so **modern browsers never download it**. It is included in the First Load JS
columns (Next's historical convention) and subtracted in the "Modern" column. **The Modern column is
the one that matters for real users.**

## 2. Routes clearly out of line with their peers

### 2.1 `/compare` — 337.1 KB gz, heaviest route on the site, and it is `noindex`

`src/app/compare/page.tsx:10` → `robots: { index: false, follow: true }`. A noindex utility page is the
heaviest route, and **100 % of its 88.3 KB gz excess is static data tables that are not needed at first
paint** (the page opens with two empty paste boxes; `analyzePaste` only runs after the user clicks
Compare — `CompareContent.tsx:314-315`, `useMemo` gated on `compared`).

**Root cause is ONE import line.** A transitive static-import scan (`graph.mjs`) over
`CompareContent.tsx` returns exactly three paths, all through the same module:

```
components/compare/CompareContent.tsx -> @/lib/utils/effective-form -> @/lib/data/pokemon
components/compare/CompareContent.tsx -> @/lib/utils/effective-form -> @/lib/utils/mega-detect -> @/lib/data/mega-pokemon
components/compare/CompareContent.tsx -> @/lib/utils/effective-form -> @/lib/utils/mega-detect -> @/lib/data/pkmn-dex-fallback -> @/lib/data/dex-subset
```

i.e. `src/components/compare/CompareContent.tsx:19`:

```ts
import { resolveEffectiveForm } from "@/lib/utils/effective-form";
```

`resolveEffectiveForm` is called **once**, at `CompareContent.tsx:156`, inside `analyzePaste`.

**This is a half-fixed regression, and the tripwire cannot see it.** The direct imports of
`@/lib/data/pokemon` and `@/lib/utils/mega-detect` that the 2026-10-26 report flagged **are gone** from
`CompareContent.tsx` — but `src/lib/utils/effective-form.ts:1-2` statically imports both, and
`effective-form.ts` has exactly one non-test importer: `CompareContent.tsx`. So the full payload still
ships, one level deeper. `src/lib/__tests__/homepage-eager-imports.test.ts` is a **file-level** scan
(`EAGER_HOMEPAGE_FILES`, 5 homepage files) and is blind both to `/compare` and to transitive paths.

### 4.1 Tree-shaking and barrel files

- **No barrel-file problem.** `find src -name "index.ts*"` returns exactly **one** file,
  `src/lib/i18n/index.ts` (4 exports, 3,292 B, and it already lazy-loads all 7 translation bundles via
  `import()` — `index.ts:25-33`). Only one file in `src` uses `export * from` / `export {…} from`
  (`src/components/ui/PdfExport.tsx`). Nothing to fix here.
- **One `import * as` of a non-trivial module:** `src/components/providers/CookieBanner.tsx:4`
  `import * as CookieConsent from "vanilla-cookieconsent"` — a namespace import, which defeats
  tree-shaking of the 23,296 B ESM build. The lib is mostly needed anyway, so the namespace import is
  worth ~a few KB at most; it is listed for completeness, and §5.1 removes the whole thing from the
  critical path regardless, which is strictly better.
- **`pokemon.ts` is inherently not tree-shakeable.** `lookupPokemon` indexes a single
  244,458-byte `POKEMON_DATA` object literal. There is no "import less of it" — the only lever is
  *when* it loads, which is what §5.3 does.
- `experimental.optimizePackageImports: ["motion/react"]` is already set in `next.config.ts:21`. It is
  working (there is one shared `motion` chunk rather than per-component copies) and it does **not** make

## 5. Concrete low-risk wins

### 5.1 `CookieBanner` → `DeferredLayoutExtras` (site-wide; **includes a render-blocking stylesheet**)

**New this run and the strongest site-wide finding.** `src/app/layout.tsx:8` imports `CookieBanner`
eagerly and renders it at line 104. It costs every route **two** things:

1. a share of floor chunk `3pzg3m6751lyb.js` (46.7 KB raw / 17.9 KB gz = `vanilla-cookieconsent`
   23,296 B ESM + `PostHogProvider` + `ClarityProvider` + the consent config). `vanilla-cookieconsent`
   is ~50 % of the raw bytes → **~9 KB gz** attributable;
2. `CookieBanner.tsx:5` `import "vanilla-cookieconsent/dist/cookieconsent.css"` emits a **separate CSS
   chunk** `1uny7_so0xb6d.css`, **34.1 KB raw / 6.0 KB gz**, served as
   `<link rel="stylesheet" data-precedence="next">` in `<head>` on **97 of 98** prerendered pages.
   That is **render-blocking** — it delays first paint on every page on the site, including `/terms`.

`src/components/ui/DeferredLayoutExtras.tsx` already exists and does exactly this job for four
components ("None of these render anything above the fold"). `CookieBanner` is a bottom-anchored
consent banner — the same category.

- **Saved: ~15 KB gz per route (≈9 KB JS + 6.0 KB render-blocking CSS) × 23 routes / 97 prerendered pages.**
  The CSS half is worth more than its size suggests because it is currently on the critical path.
- **Files:** `src/app/layout.tsx`, `src/components/ui/DeferredLayoutExtras.tsx`.
- **Risk: low.** No logic change, `ssr: false` matches current behaviour (the banner is client-only
  anyway). One thing to check: the banner now appears a beat after hydration, so **get the GDPR timing
  signed off** before shipping, and confirm no analytics fires before consent resolves
  (`PostHogProvider` stays eager, so the ordering is unchanged).
- **Effort: small** (~10 lines).

### 5.2 `motion` → CSS, starting with `ReportCard` (highest aggregate reach)

37.4 KB gz, first-load on **7 route groups covering 88 pages**: `/dashboard`, `/dashboard/profile`,
`/explore`, `/creator/[name]`, `/champions/[pokemon]` (×81), `/feedback`, `/changelog`.

Two independent slices, and the first is unusually cheap:

**(a) `ReportCard` only — removes `motion` from `/dashboard` entirely.**
`DashboardContent.tsx`'s *only* static path to `motion` is via `ReportCard`, whose *entire* usage is one
`motion.a` with `variants: {hidden:{opacity:0,y:12}, visible:{opacity:1,y:0}}` (`ReportCard.tsx:163-170`).
Replace with a plain `<a>` + a CSS `@keyframes` fade-up.
- **Saved: 37.4 KB gz off `/dashboard`** (328.2 → 290.8 KB gz; 289.6 → 252.2 modern) — one component.
- **Risk: low–medium.** The `variants` are driven by a parent stagger container, so the per-card
  stagger must be reproduced with a CSS `animation-delay` (an `--i` index custom property on each card
  is the usual trick). Visual-only failure mode. Respect `prefers-reduced-motion` per the UI standards.
- Does **not** help `/dashboard/profile`, `/explore`, `/creator/[name]`, `/champions/[pokemon]`,
  `/feedback`, `/changelog`, which import `motion/react` directly.

**(b) All 10 importers → CSS.** 48 call sites, every one an opacity/`y` fade.
- **Saved: 37.4 KB gz × 7 route groups**, including all 81 SSG mega guides (293.6 → 256.2 KB gz).
- **Risk: medium**, 10 files + `next.config.ts` (drop `optimizePackageImports`), and
  `ExploreFilters.tsx` uses `AnimatePresence` + `useReducedMotion` (exit animations are the one thing
  CSS does badly). `src/app/dashboard/profile/page.tsx:4` and `WhatsNewModal.tsx:5` also use
  `AnimatePresence`. Needs `ui-checklist-reviewer` and a visual pass.
- A middle option that keeps the API: `LazyMotion` + `m` from `motion/react`, which defers the feature
  bundle. Smaller win, much smaller diff.

### 5.3 Lazy-load `effective-form` in `CompareContent` — **largest single number on the site**

Mirror the proven homepage pattern. In `src/components/compare/CompareContent.tsx`, drop the static

- **Saved: 88.3 KB gz / 379.0 KB raw off `/compare`'s First Load JS** — 337.1 → 248.8 KB gz
  (298.5 → 210.2 KB modern). **26 % of the route's gzip**, and it takes the heaviest route on the site

- **Files:** `src/components/compare/CompareContent.tsx`, `src/lib/__tests__/homepage-eager-imports.test.ts`.
- **Risk: low–medium.** One source file, no API or data change, and the identical refactor already
  shipped on the homepage. Two real risks: (i) the Compare click becomes async, so it needs a pending
  state or the first comparison renders with empty stats — `compared` is already a boolean gate

  the compare flow.

  `components/compare/CompareContent.tsx` + `app/compare/page.tsx` to the list (rename

### 5.5 `/champions` — hoist `MEGA_GROUPS` into the server component
