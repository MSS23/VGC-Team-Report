## Shortlist (ranked)

### 1. VGC-350 — VAPID private-key pattern missing from the hardcoded-secret guard  (high confidence)

Verified: `src/lib/security/__tests__/no-hardcoded-secrets.test.ts` has a `RULES` array at
line 54 covering discord-webhook-url, linear-api-key, clerk-secret-key, aws-access-key-id,

**no VAPID rule**. `src/lib/web-push.ts:7` reads `VAPID_PRIVATE_KEY` and `web-push` is a
prod dependency. One free file, no PR branch touches `src/lib/security/**`. Add the pattern
plus an assertion that it fires on a synthetic key.

### 2. VGC-347 — delete the orphaned i18n keys (partial: i18n only)  (high confidence)

The i18n half is all free (`src/lib/i18n/translations/{en,es,fr,it,ja,ko,zh}.ts`). The
other ~47 LOC was verified to live in owned files (`damage-calculator.ts`,
`dex-subset.ts`, `discord-bot.ts`, `url-codec.ts`, `ExploreFilters.tsx`) — leave it.

**New trap found tonight, not in the ticket.** `src/components/report/CommonModesSlide.tsx`
(an owned file) reads i18n keys through a dynamic index helper
(`const tr = (key, fallback) => (t as Record<string,string|undefined>)[key] ?? fallback`),
so a static `t.<key>` scan reports its keys as orphans while they are live at runtime, and
the `TranslationKeys` type-lock cannot catch the deletion. **Do not delete these 14:**
`addCombination`, `combinationBack`, `combinationLabel`, `combinationLeads`,
`combinationStrategy`, `combinationStrategyPlaceholder`, `commonCombinationsDesc`,
`commonCombinationsTitle`, `commonModesEmpty`, `commonModesTitle`, `legacyLeadsLabel`,
`legacyModesLabel`, `legacyNotesTitle`, `removeCombination`.
`src/hooks/useSlideSystem.ts:56` reads `commonModesTitle` the same way.
Also honour the two traps the ticket already names (`parseMetricCursor` /
`serializeMetricCursor` / `MetricCursor` in `src/lib/explore/chronological-cursor.ts`;
`_removed` in `src/lib/utils/normalize-report.ts`).

My independent scan of `en.ts` (314 keys) found 90 with no static call site; minus the 14
dynamic ones gives **76**, against the audit's 73. Reconcile with a fresh scan before
deleting, and keep the deletion in its own commit per locale file so `tsc` guards it.

### 3. VGC-122 — finish the Japanese pass: 50 empty stubs  (high confidence on the work, medium on whether the owner still wants the ticket)

Reality check: `ja.ts` exists and is 309/314 keys populated. What remains is **50 keys
shipped as `""`** — byte-identical key set in all six non-English locales (md5-verified),
with `src/lib/i18n/index.ts:78-86` silently falling back to English, so Japanese users see

Caveat: `.swarm/backlog-staleness-16-11-26.md` (via VGC-342) lists VGC-122 among tickets
to "close on sight as already shipped". That is ~86% true. Fill the 50 stubs and the ticket
becomes genuinely closeable.

### 4. VGC-330 — make `llms-full.txt` stop asserting both answers (partial: docs + test only)  (medium-high confidence)

The ticket needs a human ruling and must not get another assertion flip. There is a
narrower fix that needs neither, and it is the part doing active harm.

`public/llms-full.txt:92` states, in one sentence, `SP = ceil(EVs / 8)` **and**
`248 EVs = 32 SP`. Those are incompatible (`ceil(248/8) = 31`). The reason is that the
sentence describes the implementation incompletely: `evToChampionsSp`
(`src/lib/analysis/stat-calculator.ts:139`) is `ceil(ev/8)` with a floor of 1 **plus an
explicit `if (ev >= 248) return 32` clamp`. So the doc can be made self-consistent *with
the code as shipped* — state the clamp — without ruling on whether the clamp is correct
against the official ruleset, which is what VGC-330 actually asks a human.

Scope: one sentence in `public/llms-full.txt` (no PR branch touches it — verified by branch
diff, and `public/` only appears in the owned list as five `*.svg` files), plus the
boundary assertion the ticket's own item 3 asks for in the free test
`src/lib/analysis/__tests__/sp-docs-drift.test.ts` (it already derives `CAP_EV_COST =
championsSpToEv(32)` but never pins the doc's ladder endpoint to it).

**Hard limits for the implementing agent:** do not touch `stat-calculator.ts` (owned, and
the ruling is open), do not flip any existing assertion, do not add or change any EV→SP
number anywhere else, and say in the commit message that the ruling stays open. If the
owner would rather the file say nothing until the ruling, the fallback is to delete the
formula clause and keep the ladder.

All-new files: a generator in `scripts/` (mirror `generate-move-names.mjs`), a generated

The implementing agent should decide explicitly and record which surfaces it wired.
