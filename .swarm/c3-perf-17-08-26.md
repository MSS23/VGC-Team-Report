## 1. Methodology

Next 16 + Turbopack prints no `First Load JS` table (that is VGC-269). Two independent derivations were used and **cross-validated to the byte**:

1. **HTML parse** — for each of the 89 prerendered `.next/server/app/**/*.html`, extract every `/_next/static/**.js` referenced in `src=`/`href=` and in the escaped Flight payload. That is the exact cold-visit chunk set.
2. **RSC client-reference manifests** — evaluate every `.next/server/app/**/page_client-reference-manifest.js` in a VM, union each route's `clientModules[*].chunks` where `async === false`, plus `build-manifest.json`'s `rootMainFiles` + `polyfillFiles`.

Method 2 reproduced method 1 **exactly** for all 89 prerendered routes (e.g. `/` = 1823.0 kB raw / 525.8 kB gz under both). Method 2 additionally covers the **dynamic (`ƒ`) routes** — `/s/[id]`, `/embed/[id]`, `/creator/[name]`, `/notifications`, `/dashboard/notifications` — which the Aug-10 audit had to leave unmeasured. This is how the 8th `motion` route was found.

Sizes are on-disk bytes and `gzip -9`. Vercel serves brotli, so real transfer is ~15–20 % lower; ratios hold. Chunk contents identified by byte-signature grep (Turbopack scope-hoists whole chunks into one function, so per-module attribution inside a chunk is impossible; no client sourcemaps are emitted).

> ⚠️ **Snapshot gotcha for future runs.** `ln -s <repo>/node_modules /tmp/c3/node_modules` **fails** — Turbopack panics with `Symlink [project]/node_modules is invalid, it points out of the filesystem root`. Use a hardlink copy instead: `cp -al <repo>/node_modules /tmp/c3/node_modules` (971 MB, near-instant, no extra disk).

## 8. Caveats

1. **Version skew.** 10-08 measured Next 16.2.6; today is 16.3.0. Route-level gz deltas mix the ticket wins with framework changes (every route dropped ~5–6 kB gz, which is the framework floor moving). **Chunk-level facts — sizes, eager/lazy status, route sets, import sites — are exact and unaffected.**
2. **Gzip, not brotli.** Vercel serves brotli; real transfer ~15–20 % lower.
3. **Snapshot isolation.** Every number comes from `/tmp/c3` (a `git archive HEAD` tree with a hardlinked `node_modules`). The shared working tree and its `.next/` were never written to. `src/` was not modified.
4. **Concurrent swarm activity.** Other agents are editing `src/` tonight. All source line numbers in §5 were read from the live working tree at the time of writing and matched `HEAD`; if an implementation agent has since edited `page.tsx` / `ExploreContent.tsx` / `TeamReport.tsx`, re-grep before applying — the *files* are right regardless, only the line numbers can drift.
5. **Dynamic-route figures** come from the RSC manifest method only (no HTML to cross-check), but that method reproduced all 89 prerendered routes exactly, so confidence is high.
