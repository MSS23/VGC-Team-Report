## VGC-260 — Bug: version-diff emits `pokemon:<index>`, parses it as a species name — PASS

Files: `src/lib/utils/version-diff.ts`, `src/lib/utils/__tests__/version-diff.test.ts`,
`src/components/report/TeamOverview.tsx`, `src/components/report/PokemonDetailSlide.tsx`

Root cause was deeper than the ticket described. Both parse sites (`getNavigableChanges`,
`summarizeChangedFields`) matched `pokemon:<index>` with the SAME regex used for
`notes:/calcs:/roles:` and treated the payload as a species key. So the label capitalised the raw
index ("Set (0)") and `speciesKeys.indexOf("0")` returned -1, sending navigation to slide 0
(the overview) rather than the Pokemon's detail slide.

Fix is type-level, as the ticket asked: a `SectionKey` discriminated union with a single
`encodeSectionKey`/`parseSectionKey` pair, so emit and parse cannot drift again. `FIELD_LABELS`
became `as const satisfies Record<string,string>` so a field cannot be emitted without a label.
The three UI emit sites now call `encodeSectionKey`, so the `data-diff-field` DOM strings the
DiffNavigator scrolls to are generated by the same function that parses them.

Edge cases handled correctly, including the two that matter in this codebase:
index **0 is treated as a real value** (not missing), and species keys containing a colon
("Type: Null") survive because parse splits on the FIRST colon only. Out-of-range indices fall
back to the overview rather than throwing.

26 new tests, including the named "Set (0)" regression per CLAUDE.md.
