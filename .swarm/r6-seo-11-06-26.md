# R6 SEO Audit — 11-06-26

Scope: Next.js 16 App Router site at https://pokemonvgcteamreport.com. Read-only audit. Drafts below; nothing applied.

## TL;DR — single highest-leverage fix
The site has a strong foundation (rich `generateMetadata` on `/s/[id]` and `/champions/[pokemon]`, FAQPageJsonLd on /faq, BreadcrumbLists on most pages) but is leaking authority on `/` — the root route is `"use client"` with no per-page metadata, so Google indexes the homepage under the generic layout default ("VGC Team Report - Build and Share Pokemon VGC Teams") with no jsonLd hero, no FAQ, no HowTo. That is the single most-trafficked URL and the highest-leverage win. Split `page.tsx` into a server wrapper that exports `metadata` + injects HowToSchema + FAQPageJsonLd (subset) and a client child for the interactive paster.

---

## Top 10 keyword gaps (with target page)

1. **"VGC team builder"** → `/` (root). Homepage has no per-page metadata override and never says "team builder" in title. Layout default uses "Build and Share Pokemon VGC Teams" — close, but exact-match term is missing.
2. **"pokepaste alternative"** → `/` and `/faq`. /faq lists it as a keyword only; should appear in homepage title/description. Currently nowhere in the homepage's effective metadata.
3. **"Regulation H teams 2026"** → `/explore`. `/explore` keywords list only "Regulation M-A teams"; Reg H is the standard SV format and absent from title/desc/keywords. Sitemap exposes no Reg H landing page.
4. **"Pokemon VGC strategy"** → no targeted page. /faq mentions "strategy" in body but no page titles target the head term.
5. **"best VGC team"** (singular) → `/explore`. Targets "best VGC teams 2026" only (plural). Add singular variant; high-volume head term.
6. **"VGC team report template"** → `/` or new landing. Term absent everywhere; players searching for templates land on competitors.
7. **"VGC speed tier calculator"** → no page. Layout features list mentions "VGC Speed Tiers" but no dedicated page/route.
8. **"VGC damage calculator"** → no page. Mentioned in body copy only; no canonical landing.
9. **"open team sheet generator" / "OTS Pokemon"** → `/explore` has "OTS Pokemon" in keywords but no title/desc presence. Worlds 2026 will drive OTS query volume.
10. **"VGC Worlds 2026 teams"** → `/tournaments`. Title says "Team Reports 2026" but doesn't include "Worlds 2026" exact phrase; description does, title does not.

- `src/app/page.tsx` starts with `"use client"`. **No `export const metadata`** and **no `generateMetadata`**. Falls back to layout defaults only.
- No HowToSchema rendered on the homepage even though `HowToSchema` helper exists in `src/components/seo/JsonLd.tsx`.
- No homepage FAQPageJsonLd. AI bots citing "how do I build a VGC team report" cannot find a FAQ block on the canonical URL.
- No BreadcrumbList on `/`.
- Suggest: extract a tiny server `page.tsx` that exports metadata + jsonLd and renders the client component.

## Sitemap gaps (`src/app/sitemap.ts`)

1. **Duplicate `/compare` entry** at lines 16 and 18 — same URL emitted twice with different priorities (0.6 and 0.5). Sitemaps must contain unique URLs; some validators flag this. Remove the second entry.
2. **Missing `/dashboard`** — correctly omitted (noindex). OK.
3. **Missing `/tournaments/[id]`** — if individual tournament pages exist, they're not in the sitemap. If they don't exist yet, ignore.
4. **No `/s/[id]` lastModified urgency** — `changeFrequency: "monthly"` for shares undersells how often a freshly created team gets edited. Suggest `"weekly"` and bumping priority to 0.7 for shares with `updated_at` in the last 30 days.
5. **Creator pages have no `lastModified`** — Google may treat them as stale. Add `MAX(updated_at)` per creator.
6. **No image sitemap entries** — champion pages have per-Pokemon OG images that would benefit from inclusion via `images` extension.
7. **No `/explore?reg=H` or `/explore?reg=ma` faceted URLs** — if those query combinations should rank, they need either pre-rendered routes or sitemap inclusion. Currently no Regulation H landing exists.
8. **5000-share cap** — current `LIMIT 5000` will silently truncate when share count exceeds it. Suggest paginating into `sitemap-0.xml`, `sitemap-1.xml` via Next 15's `generateSitemaps()` API.

## robots.txt

File at `public/robots.txt` is static. Findings:

1. **`Google-Extended` NOT explicitly allowed.** This is the bot Google uses for AI-Overview training/grounding. With only wildcard `Allow: /`, it inherits the default — which is fine, but explicit allow signals intent and is what Anthropic/OpenAI docs recommend for clarity. **Add it.**
2. **`anthropic-ai` (legacy) and `Applebot-Extended` missing.** Anthropic uses both `ClaudeBot` (present) and `anthropic-ai` historically. Apple's bot powers Siri / Apple Intelligence citations.
3. **No `CCBot` (Common Crawl)** decision. Common Crawl feeds many LLM training sets; if you want AI citations you want this allowed. Currently inherited-allow via wildcard, but should be explicit.
4. **PerplexityBot present.** Good. Note Perplexity also uses `Perplexity-User` (on-demand fetches when a user clicks a citation); the spec says do NOT block. Currently inherited-allow.
5. **No `/api/` carve-out for OG-image endpoints** — `/api/team-graphic` (referenced in `src/app/s/[id]/page.tsx` comments) is blocked by `Disallow: /api/`. If you re-enable share-card unfurls in future, this blocks Discord/Slack/Twitter card crawlers. Consider `Allow: /api/team-graphic` exception or moving the endpoint outside `/api/`.
6. **Sitemap URL is correct** (`/sitemap.xml`). Good.

Draft additions:
```
User-agent: Google-Extended
Allow: /

User-agent: Applebot-Extended
Allow: /

User-agent: anthropic-ai
Allow: /

User-agent: CCBot
Allow: /

User-agent: Perplexity-User
Allow: /

User-agent: cohere-ai
Allow: /
```

## Canonical URL consistency

- Layout sets canonical to `https://pokemonvgcteamreport.com` (root). Per-page canonicals override correctly on `/explore`, `/champions`, `/champions/[slug]`, `/faq`, `/tournaments`, `/changelog`, `/feedback`, `/creator/[name]`, `/privacy`, `/terms`.
- `/compare`, `/dashboard`, `/notifications`, `/s/[id]` rely on layout default → fine because all are noindex except `/s/[id]`, where the layout canonical points to the homepage. **Bug:** public shares inherit a canonical pointing to `/` not to the share URL. Google will drop the share from the index in favor of `/`. Set canonical in `generateMetadata`:
```ts
alternates: { canonical: `https://pokemonvgcteamreport.com/s/${id}` },
```
- Homepage `/` doesn't have a per-page canonical (uses layout). Edge case: `/?ref=...` UTMs would canonicalize correctly via layout default. OK.

## Other findings worth flagging

- **WebApplication + SoftwareApplication multi-type in layout** — Google's parser accepts `@type` arrays but rich-result eligibility is on WebApplication only. Confirm in Search Console URL inspector.
- **OrganizationJsonLd `sameAs` only links GitHub.** Add X/Twitter, Discord, and Bluesky profile URLs — strongest Knowledge-Panel signal.
- **No `Person` schema for the operator (Manraj Sidhu)** — given Terms names a real operator, a Person entity linked from Organization improves E-E-A-T.
- **`opengraph-image.tsx` exists at root** — good. Per-route OG images on `/explore` and `/champions/[slug]`. `/tournaments`, `/champions`, `/faq` reuse default. Consider per-route for top traffic pages.
- **`llms.txt` and `llms-full.txt` exist** — good for AI citations. Confirm `llms-full.txt` has the full FAQ content; spot-check showed solid coverage.
- **No `next-sitemap` package** — using Next-native `sitemap.ts` only. Fine; just note it for future when share count crosses 50k (Google sitemap limit).
