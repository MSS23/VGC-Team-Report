## 4. Top 5 prioritized recommendations

### #1 — Move `@pkmn/dex` out of the client bundle (VGC-214)
- **Files:** `src/lib/data/pokemon.ts`, `src/lib/data/pkmn-dex-fallback.ts`, `src/lib/utils/mega-detect.ts`, `src/components/compare/CompareContent.tsx`, `src/components/report/InlinePokemonEditor.tsx`
- **Problem:** `pokemon.ts` imports `pkmn-dex-fallback`, which imports `Dex` from `@pkmn/dex` at module top-level. Because `pokemon.ts` is consumed by 5+ `"use client"` components (`PokemonCard`, `PokemonDetailSlide`, `SpeedTierChart`, `MatchupPlanSlide`, `CompareContent`), webpack pulls the entire `@pkmn/dex/index.min.js` (1.84 MB raw / **~350 KB gzip**) into the client bundle of `/` and `/compare`.
- **Fix (~90 min):**
  1. Make `lookupPokemonFromDex` callable **only from the server** by either (a) creating a `/api/pokemon-lookup` route and calling it from the client when `POKEMON_DATA[key]` misses, or (b) moving the fallback into the server `generateStaticParams` / RSC layer and shipping the pre-resolved data via props.
  2. Replace the `Dex` import in `InlinePokemonEditor` with a static JSON of just `{name, types, baseStats}` for all species (~80 KB raw vs 1.8 MB) — `species.all()` is the only API used. Easy to pre-generate at build time.
  3. Verify `mega-detect.ts` is not in the client graph; if it is, extract the static parts.
- **Impact:** ~**350 KB gzip** off `/` and `/compare` First Load JS. Largest single win available.
- **Conflict risk:** `pokemon.ts` and `page.tsx` are in `.swarm/main-changed-files.md` — review recent commits before refactor. `PasteInput.tsx` also recently changed.

### #2 — Refactor `src/app/page.tsx` to RSC shell (VGC-162)
- **Files:** `src/app/page.tsx` (1881 LOC, `"use client"` at top)
- **Problem:** The whole route is a Client Component. The marketing/landing-state portion (above the paste form) runs at the client for every cold visitor and forces the entire dependency graph (incl. dex via PokemonCard) into the client bundle.
- **Fix (~2 h):** Convert `page.tsx` to a Server Component that renders a small `<HomeClient>` island only for the paste/report interactive section. Move `<Navbar>`, FAQ JSON-LD, marketing copy, and `<TeamCardCTA>` to the RSC layer. This unblocks Next's tree-shaking of `pokemon.ts` from the client.
- **Impact:** Combined with #1, an additional ~50–100 KB gzip; without #1, ~30 KB. Also improves LCP/FCP because the marketing shell streams immediately.
- **Conflict risk:** **HIGH** — `page.tsx` is in `.swarm/main-changed-files.md`. Coordinate with whoever last touched it.

### #3 — Hoist `motion/react` out of the shared chunk
- **Files:** `src/components/ui/WhatsNewModal.tsx`, `src/components/ui/InstallPrompt.tsx`, `src/components/social/DoubleTapLikeOverlay.tsx`, `src/components/social/FloatingReactionDock.tsx`, `src/app/champions/[pokemon]/MegaLandingContent.tsx`, plus 7 more (12 total files)
- **Problem:** `motion/react` resolves to a **485 KB raw / 118 KB gzip** chunk shipped on the home route. `next.config.ts` has `optimizePackageImports: ["motion/react"]` but that only deduplicates named imports — it doesn't tree-shake the whole library.
- **Fix (~60 min):** (a) Audit each `motion.X` usage — many are simple fade/slide transitions (`<motion.div initial opacity 0 …>`) that can be replaced with Tailwind `transition-opacity` + `data-[state]` classes. (b) For the rest, lazy-load `motion/react` inside the components that genuinely need spring physics. (c) Replace the dynamic `<motion.img>` in `PasteInput.tsx` with a CSS `@keyframes` shimmer.
- **Impact:** ~80–118 KB gzip off `/`. Also reduces TBT because motion's spring runtime is hot in the main thread.

### #4 — Eliminate the duplicate `html2canvas-pro` chunk
- **Files:** `src/components/ui/TeamCardExport.tsx`, `src/components/ui/OTSSheetModal.tsx`, `src/lib/utils/export-report.ts`
- **Problem:** Two `html2canvas-pro` chunks exist: `0xr012s5lag5a.js` (418 KB raw) and `0i4g9_wngqb2c.js` (226 KB raw). Each call site does its own `await import("html2canvas-pro")`, so Turbopack emits a separate chunk per call site rather than deduping. Total wasted: ~226 KB raw / ~60 KB gzip on the user who triggers both export paths.
- **Fix (~30 min):** Funnel every `html2canvas-pro` use through `getHtml2Canvas()` in `src/lib/utils/export-report.ts` (already exists). Replace direct `await import("html2canvas-pro")` in `OTSSheetModal.tsx:109` and `TeamCardExport.tsx:31` with `await getHtml2Canvas()`. Same for `jspdf` via `getJsPdf()`.
- **Impact:** ~60 KB gzip saved on PDF/PNG export paths. Faster second export (warm cache hit).

### #5 — Decompose `PokemonDetailSlide.tsx` for code-splitting (VGC-158)
- **Files:** `src/components/report/PokemonDetailSlide.tsx` (962 LOC)
- **Problem:** 962 LOC single client component shipped eagerly inside `TeamReport`. Contains 16 hooks, all 5 detail tabs (stats / moves / calcs / matchups / notes), and inline JSX for each. Re-renders the entire tree on any tab change — measurable jank on mid-range Android.
- **Fix (~90 min):**
  1. Extract each tab (`StatsTab`, `MovesTab`, `CalcsTab`, `MatchupsTab`, `NotesTab`) into its own file.
  2. Lazy-load non-default tabs via `dynamic()` — only the active tab's code reaches the client at first render.
  3. Wrap each tab in `React.memo` and lift the `useState` for tab selection up to the container so tab bodies don't re-render on unrelated state changes.
- **Impact:** ~20–40 KB gzip off the initial `TeamReport` chunk. Runtime: 2–4× faster tab switches on mid-range mobile. Easier to maintain.
- **Conflict risk:** Low — file not in `.swarm/main-changed-files.md`.

## 7. Build warnings noticed

The build log is flooded with `Failed to fetch teams for <species> Error: No database connection string was provided to neon()` during static generation of `/champions/[pokemon]`. This is the SSG step trying to query the DB without `DATABASE_URL` in the build env. Not a perf issue, but it slows local builds (silently swallowed errors per page) and pollutes the log. Worth a follow-up ticket: either inject the env var into build, or guard `generateStaticParams` to skip DB calls when the URL is missing and rely on ISR.
