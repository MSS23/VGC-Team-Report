## Budget reallocation — deliberate deviation from the routine's Wave 1 spec

The routine specifies ~13 Wave 1 agents, 8 of them outward-facing research (R1-R8). I cut
Wave 1 to 6 read-only code audits and moved the budget to implementation. Reasons:

1. **GOAL A outranks GOAL B** in the routine's own priority order, and there are 53
   implementable tickets waiting.
2. **The research half of the board is saturated**: 58 of 74 Backlog tickets already carry
   `auto-research`, and `.swarm/drafts/` already holds **40** un-actioned draft files.
   Filing 5-10 more research tickets on top of that is negative value — it is the review
   debt VGC-265 is about, in ticket form.
3. **PostHog is unreachable** (no credentials — VGC-220), and the routine makes PostHog
   cross-referencing a core input to R3, R5, C4 and C5. Four of the specified agents would
   have run half-blind.
4. The routine's own instruction "Leave NO subagent slot wasted" points this way: with 53
   implementable tickets, spending slots generating more backlog is the waste.

Allocation: **7 implementation (Batch A) + 2 implementation (Batch B) + 6 read-only audits
= 15 of 25.** Webhook investigation, board triage, and the VGC-299 webhook-logging fix all
ran inline at zero budget cost.

## Correction: VGC-298's own prescription contained an error

VGC-298 asked for the SP drift-guard to pin the ladder figure as *"cost(n) = 8n − 4, so the
32nd SP = **252** EVs"*, and described the existing "32 SP = 248+ EVs" wording in
`public/llms.txt` as the stale figure to fix.

**"248+" is correct and "252" would have been a regression.** Verified against the single
source of truth, `evToChampionsSp` in `src/lib/analysis/stat-calculator.ts`:

```
if (ev >= 248) return CHAMPIONS_MAX_SP_PER_STAT;   // 248+ EVs → the 32 SP cap
```

and its inverse `championsSpToEv(32) === 248`.

The algebra `cost(n) = 8n − 4` gives 252 for n=32, but the implementation rounds **up**
(`ceil(ev / 8)`, floor of 1 SP for any investment), so 248 EVs already reaches 32 SP and
everything from 248 to 252 maps to the same 32 SP. The `+` in "248+" is carrying exactly
that. The agent correctly took `llms.txt` as the source of truth rather than the ticket
text, and added a sentence to `llms-full.txt` making the 248-vs-252 collapse explicit.

Flagged on VGC-298 so whoever closes it does not "fix" 248 back to 252.
