### B2 — `dark:` utilities are wired to the OS, not to the app's theme toggle

**WCAG 1.4.3 — AA.** | Severity: **BLOCKER** | Effort: **XS** (one line) | `src/app/globals.css:3-4`

`globals.css` declares `@custom-variant creator` and `@custom-variant presenting` but **no
`@custom-variant dark`**. With Tailwind v4.2.1 (confirmed from `node_modules/tailwindcss/package.json`)
`dark:` therefore defaults to `@media (prefers-color-scheme: dark)`.

The app's real theme is the `data-dark-mode` attribute on `<html>`, written from
`localStorage["vgc-dark-mode"]` by `src/hooks/useDarkMode.ts:40-42` and bootstrapped at
`src/app/layout.tsx:97`; `prefers-color-scheme` is only the first-visit default. The moment a user
toggles the theme the two diverge. **142 `dark:` utilities across 28 files** are affected.

Worst case — dark-OS user switches the app to **light** (`dark:` applies over white surfaces):

| Class | Colour | on `#FFFFFF` |
|---|---|---|
| `dark:text-amber-300` | `#FFD230` | **1.45:1** |
| `dark:text-emerald-300` | `#5EE9B5` | **1.52:1** |
| `dark:text-sky-300` | `#74D4FF` | **1.67:1** |
| `dark:text-amber-400` | `#FFB900` | **1.72:1** |
| `dark:text-emerald-400` | `#00D492` | **1.94:1** |
| `dark:text-blue-400` | `#51A2FF` | **2.64:1** |
| `dark:text-rose-400` | `#FF637E` | **2.86:1** |
| `dark:text-red-400` | `#FF6467` | **2.89:1** |

Mirror case — light-OS user switches the app to **dark** (`dark:` never applies):
`text-amber-700 #BB4D00` on `#141428` = **3.60:1**; `text-red-600 #E7000B` = **3.79:1`;
`text-sky-700 #0069A8` = **3.09:1**; `text-emerald-700 #007A55` = **3.37:1**.

In-scope sites include `src/app/tournaments/TournamentsContent.tsx:85-86` (the Worlds/International
event-type badges), `src/components/explore/ReportCard.tsx:172,301` (regulation + rental badges),
`src/components/report/TeamReport.tsx:221` (the "fields hidden by the creator" privacy notice),
`src/components/report/PokemonCard.tsx:515,516,533`,
`src/components/report/pokemon-detail/StatsPanel.tsx:99,100,117,168,169`,
`src/components/report/TeamOverview.tsx:243,269-272`, `src/app/champions/ChampionsContent.tsx`,
`src/app/changelog/ChangelogContent.tsx:25,32,39,411-414`.

**Fix.** One line, next to the existing variants:

```css
@custom-variant dark (&:where([data-dark-mode], [data-dark-mode] *));
```

That makes all 142 `dark:` utilities track the real theme. In the same pass, retarget the three dead
rules that select a `.dark` class never added anywhere — `globals.css:630`
(`.dark .walkthrough-spotlight`), `:921` (`:is(.dark) .version-diff-border`), `:957`
(`:is(.dark) .version-diff-highlight::before`) — to `[data-dark-mode]`.

> **Order of work:** B2 must land first. Several fixes below (S2, M4) specify
> `text-X-700 dark:text-X-400` pairs that are inert until the variant is correct.

### N1 — `prefers-reduced-motion` is not honoured by the `motion` library

**WCAG 2.3.3 Animation from Interactions — AAA** (so not AA-blocking) **+ CLAUDE.md UI standard.**
Severity: **MINOR** | Effort: **S**

The CSS rule at `globals.css:845-852` cannot reach JS-driven animations, and `motion@12` defaults to
`reducedMotion: "never"`. Ten files import `motion/react`; only
`src/components/explore/ExploreFilters.tsx:130` calls `useReducedMotion()`. In scope:

- `src/components/explore/ExploreContent.tsx:262-271` (stagger), `ExploreEmpty.tsx:28-32` (400ms), `ReportCard.tsx:162-168` (per-card entrance)
- `src/app/champions/[pokemon]/MegaLandingContent.tsx:38-43` — animates **`width`** over **600ms**: a layout-thrashing property and well past the 150–300ms transform/opacity standard — and `:180-183`
- `src/app/changelog/ChangelogContent.tsx:123-126` (450ms), `:165-168, 267-272, 374-377`

**Fix.** Wrap each page's tree in `<MotionConfig reducedMotion="user">` (one import per page), and
change the stat bar to `initial={{ scaleX: 0 }} animate={{ scaleX: 1 }}` with
`style={{ transformOrigin: "left" }}` at 250ms.

### N2 — No "previous slide" control on mobile

**WCAG 2.1.1 — A (arguably met).** Severity: **MINOR** | Effort: **XS**
`src/components/report/SlideNavControls.tsx:465-482`

`prevButton` is deliberately omitted on phones ("swipe covers it"). Keyboard users are fine (the
window listener at `useSlideNavigation.ts:130` handles ArrowLeft), but a VoiceOver/TalkBack user who
navigates by control cannot step back one slide — the section tabs only jump to a section's first
slide.

**Fix.** Render `{prevButton}` in the mobile row at `:479` next to `{nextButton}`, or add an
`sr-only` previous button.

### N3 — Emoji icons in the speed-modifier chips

**CLAUDE.md "SVG icons only"; WCAG 1.3.1 adjacent.** Severity: **MINOR** | Effort: **S**
`src/components/report/SpeedTierChart.tsx:64-71`, rendered at `:150`

`MODIFIER_CONFIG` uses 💨 ⚡ ❄️ ⬆️ ⏫ 🌧️. The glyph `<span>` at `:150` is not `aria-hidden`, so
screen readers prepend "dash symbol / wind blowing face" to each chip name. The actual semantics
("×2 speed", "-1 stage") live only in `title` (`:145`).

**Fix.** Replace with inline SVGs from `src/components/ui/icons.tsx` (which are already
`aria-hidden="true" focusable="false"` by default and regression-tested in
`src/components/ui/__tests__/icons.a11y.test.tsx`), and fold `cfg.description` into the button's
`aria-label` or an `aria-describedby` target.

### N4 — Missing accessible names on tables and a breadcrumb

**WCAG 1.3.1 — A.** Severity: **MINOR** | Effort: **XS**

- `src/components/report/DefensiveCoverageChart.tsx:131` and `OffensiveCoverageChart.tsx:238` — `<table>` with no `<caption>` and no `aria-label`. `ChampionsContent.tsx:354-357` and `SpreadBuilder.tsx:52` both do it right; copy them.
- `src/app/champions/[pokemon]/MegaLandingContent.tsx:106` — breadcrumb `<nav>` with **no `aria-label="Breadcrumb"`**, unlike `src/app/faq/page.tsx:146`. (This invalidates the prior report's blanket "breadcrumbs carry `aria-label="Breadcrumb"`" claim.)

### N5 — Skip-link target is a plain `<div>`

**WCAG 2.4.1 — A (met, but fragile).** Severity: **MINOR** | Effort: **XS**
`src/app/layout.tsx:100` → `:137`

The link targets `#main-content`, which is `<div id="main-content">{children}</div>`. Most browsers
set the sequential-focus starting point correctly from a fragment, but `tabIndex={-1}` on that div
makes it deterministic. (The link's own styling is also B1 — `focus:bg-accent focus:text-white`.)

### N6 — Animations on non-transform/opacity properties

**CLAUDE.md UI standard.** Severity: **MINOR** | Effort: **S**

`globals.css:441-442, 551` — `.skeleton` animates `background-position`; `:918, 929-941` —
`version-diff-pulse` animates `box-shadow` on an `infinite` loop (the loop *is* capped by the
reduced-motion rule at `:845`); `SlideNavControls.tsx:459-462` uses `transition-[width]`.

### N7 — Light-mode semantic tokens and two translucent error surfaces

**WCAG 1.4.3 — AA.** Severity: **MINOR** | Effort: **XS**

The dark half of `--success/--warning/--danger` was fixed (prior S1), but the **light** values were
not: `--success` `#16A34A` = **3.13:1** on bg / **3.30:1** on surface; `--warning` `#D97706` =
**3.03:1** on bg / **3.19:1** on surface / **2.80:1** on surface-alt. Used as body text at
`src/components/layout/Navbar.tsx:155,163`, `src/components/report/pokemon-detail/StatsPanel.tsx:40`.

Two composited surfaces also fail:
- `src/app/tools/ev-to-sp/EvToSpConverter.tsx:214` — `text-danger` on `bg-danger/10` over bg = **3.94:1** (the tool's only error channel)
- `src/components/report/SpeedTierChart.tsx:676-679` — the TIE badge, `text-amber-500` on `bg-amber-500/10` over surface-alt = **1.75:1**

**Fix.** Darken `globals.css:25-26` to `--success: #15803D` (4.63:1 on bg) and
`--warning: #B45309` (4.59:1); for the two badges use the opaque token colour on a plain
`bg-surface-alt` rather than a 10% tint of the same hue.

### N8 — Low-severity notes

- `src/components/explore/ReportCard.tsx:245` — the verified-creator badge is a `<span title="Verified creator">` around an `aria-hidden` SVG; a generic element cannot take a name from `title`, so the badge is silent. Add `role="img" aria-label="Verified creator"` to the SVG instead.
- `src/components/layout/PageNavbar.tsx:207` — the mobile tab-bar SVGs have no `aria-hidden="true"` (they sit next to a text label, so impact is limited to a stray "graphic" node).
- `src/components/report/pokemon-detail/CalcEntryGroup.tsx:107-116` — `<span onClick>` click-to-edit. No keyboard path into edit mode, but the segmented category switcher beside it (`:120-125`) is reachable, so this is a convenience gap rather than a lockout. Fix: wrap in a `<button>` or add `role="button" tabIndex={0}` + Enter/Space.
- `src/app/tournaments/TournamentsContent.tsx:85-88` — the event-type badges (`text-amber-600 dark:text-amber-400` etc.) are also 1.4.1 cases: the Worlds/International/Regional distinction is carried by colour plus the badge text, so the text redundancy saves it. Light-mode `text-amber-600 #E17100` on `bg-amber-500/10` over white = **2.96:1** — fails 1.4.3; use `text-amber-700` (`#BB4D00`, 5.04:1 on that tint).
