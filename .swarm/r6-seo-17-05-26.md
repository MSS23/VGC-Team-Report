## Remaining Gaps Confirmed Tonight

### Gap 1: `OrganizationJsonLd` missing `logo` field
File: `/src/components/seo/JsonLd.tsx` (line 60–76)
The `Organization` schema has `name`, `url`, `description`, `applicationCategory`, and one `sameAs` link (GitHub) but no `logo` property. `icon-512.png` already exists in `/public/`. Google requires `logo` on `Organization` for Knowledge Panel eligibility. AI citation engines use it for entity disambiguation.

### Gap 2: `ItemList` schema absent from `/champions` hub page
File: `/src/app/champions/ChampionsContent.tsx` (line 41–54) and `/src/app/champions/page.tsx`
The champions hub page emits only a bare `WebPage` JSON-LD. The page renders all legal Mega Pokemon in a grid from `getRegMAMegas()` — but no `ItemList` schema wraps those entries. Google Carousel/Gallery rich results (which appear for authoritative list pages) require `ItemList`. The data is already available client-side from `getRegMAMegas()`.

**Blocker:** `ChampionsContent.tsx` is a `"use client"` component, so the `ItemList` must be injected from the server — either via `ChampionsPage` in `page.tsx` (already a server component) or via a new server-side import of `getRegMAMegas()`.

### Gap 3: `/tournaments` page has no JSON-LD at all
File: `/src/app/tournaments/page.tsx`
`SportsEventJsonLd` component exists in `JsonLd.tsx` and is fully ready to use. The tournaments page renders `TournamentsContent` directly with zero JSON-LD. The `SportsEventJsonLd` needs known events hardcoded (Indianapolis Regionals, VGC Worlds SF) as static data — no DB query needed.

### Gap 4 (minor): `featureList` in root layout still says "EV Spread Builder"
File: `/src/app/layout.tsx` (line 125)
The `WebApplication` JSON-LD `featureList` still contains `"EV Spread Builder"` — factually wrong for Pokemon Champions (SP system). Should be `"SP Spread Builder"`. Low impact (featureList is not a rich-result field) but corrects entity accuracy for AI engines reading the schema.

### Gap 5 (minor): `/explore` and `/faq` missing `BreadcrumbList`
Only `/champions/[pokemon]` pages emit `BreadcrumbList`. The prior audit flagged `/explore`, `/faq`, `/tournaments` as missing it. `/explore/page.tsx` has `CollectionPage` only.

### Win 3 — Add `ItemList` JSON-LD to `/champions` hub page (server component)
**File:** `/src/app/champions/page.tsx`
**Effort:** ~30 minutes
**Impact:** MEDIUM-HIGH — `ItemList` enables Google Carousel/Gallery rich results for "best Mega Pokemon VGC 2026" and "all Mega Pokemon Regulation M-A" queries. The hub page currently renders a bare `WebPage` schema. Since `page.tsx` is a server component, `getRegMAMegas()` can be imported directly there and a `JsonLd` block emitted alongside `ChampionsContent`. No client-side changes required.

```tsx
// In champions/page.tsx:
import { JsonLd } from "@/components/seo/JsonLd";
import { getRegMAMegasWithSprites } from "@/lib/data/mega-pokemon";

export default function ChampionsPage() {
  const megas = getRegMAMegasWithSprites();
  return (
    <>
      <JsonLd data={{
        "@context": "https://schema.org",
        "@type": "ItemList",
        name: "All Mega Evolutions Legal in Pokemon Champions Regulation M-A",
        url: "https://pokemonvgcteamreport.com/champions",
        numberOfItems: megas.length,
        itemListElement: megas.map((m, i) => ({
          "@type": "ListItem",
          position: i + 1,
          name: m.displayName,
          url: `https://pokemonvgcteamreport.com/champions/${m.slug}`,
        })),
      }} />
      <ChampionsContent />
    </>
  );
}
```
