# VGC-152: Downloadable Team Card — Design Scope (17-05-26)

## Current Share Flow

`ShareModal.tsx` is a bottom-sheet modal (mobile) / centered dialog (desktop) triggered from the Navbar. It already receives all the data the card needs: `teamSpecies: string[]`, `creatorName`, `tournamentName`, `placement`, `isPublic`, plus a `publicUrl`. Actions today: Copy link, Twitter, Reddit, Discord (formatted text), Copy Paste (Showdown format), Native Share, Embed iframe snippet. The `ShareDock` component is a persistent bottom bar on shared views with the same share targets inline.

There is **no image download path yet** — this is a clean addition, not a refactor.

## Proposed Team Card Content

A single 16:9 (1200×675 px) or 4:3 (1200×900 px) image:

- **Header row:** Player name (`creatorName`) · Tournament name + placement/record (if set)
- **Sprite row:** 6 Pokémon sprites at ~110 px each, centered, spaced evenly (use the `/api/sprite?u=` proxy that already exists for CORS-clean captures)
- **Species name labels:** below each sprite, small text
- **Footer:** `pokemonvgcteamreport.com` wordmark + branding color bar
- **Background:** dark gradient matching `--color-surface` / brand palette; or a subtle Poké Ball texture layer
- Format/regulation tag badge (e.g., "Reg H") if `tags.regulation` is set

## Implementation Approach

### New file: `src/components/ui/TeamCardExport.tsx`

A self-contained `"use client"` component that:

1. Renders a **hidden** `<div ref={cardRef}>` with the card layout using Tailwind inline styles (fixed 1200×675, not responsive — it's a capture target, not a page element).
2. On button click, calls `html2canvas-pro` (already installed at `^2.0.2`) on `cardRef.current` with `{ useCORS: true, scale: 2, backgroundColor: null }`.
3. Converts the canvas to a PNG blob and triggers a `<a download="team-card.png">` click.

### Key technical notes
- `PokemonSprite` already switches to `/api/sprite?u=` proxy in `isPrint` mode (see `print-context`). The card renderer must set `PrintContext.Provider value={true}` around the card div, or pass `isPrint=true` down, so sprites route through the proxy and avoid the CORS blank-sprite problem.
- The existing `/api/sprite` edge route proxies Showdown CDN with `Cache-Control: immutable` — no new API needed.
- `html2canvas-pro` is already installed; jsPDF is also available but not needed for PNG output.
- Species names come in as `teamSpecies: string[]` (already in ShareModal props).
- Sprite URL resolution: use `getGenThemedSpriteUrls(species, "gen9", false, false)[0]` for a reliable static home-sprite URL, then wrap in the proxy.

### Where the button lives

Add a "Download card" button inside `ShareModal.tsx` in the social-actions grid (same pattern as the Discord/Paste buttons). It only needs `teamSpecies`, `creatorName`, `tournamentName`, `placement`, and optionally `tags.regulation`. All of these are already props on ShareModal — no prop threading needed.

Optionally add a second entry in `ShareDock` for discoverability on read-only views.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Sprites blank in capture | Use `PrintContext` to force `/api/sprite` proxy; existing PdfExport already solves this |
| html2canvas-pro cross-origin CSS vars | Inline critical styles as explicit hex values in the card component; don't rely on Tailwind CSS custom properties at capture time |
| Long capture time (6 sprites fetched sequentially) | Pre-load images before capture; show a brief "Generating..." spinner on button |
| Card looks bad at different sprite sizes | Fix card div to 1200×675, scale=2 for 2x canvas; test with substitute sprite fallback |
