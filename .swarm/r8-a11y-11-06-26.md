# R8 Accessibility Audit — 11-06-26

WCAG 2.1 AA pass over public marketing, report viewer, explore/champions/compare, and layout chrome. Scope: keyboard, focus, contrast, touch targets, labels, dialog semantics, heading hierarchy, live regions, alt text. Conflict-risk files were skipped per the brief.

## High-impact gaps (start here)

- `src/components/layout/PageNavbar.tsx:104` — Mobile bottom tab bar `<nav>` is OK, but each tab `<Link>` (line 113) has no `aria-current="page"` when active. Active state is visual only (accent color + pill). Screen-reader users have no way to know which page they're on. Add `aria-current={isActive ? "page" : undefined}` on the Link.

- `src/components/explore/ExploreContent.tsx:154-217` — Live region missing for search/filter results. When the filters change, the results grid silently rewires from skeleton → list → empty state. Add `aria-live="polite"` + `aria-busy={loading}` on the wrapping results container (e.g. the grid/empty branch), and an offscreen status like "Showing N reports" so AT users know results updated.

- `src/components/explore/ReportCard.tsx:319-340` — Like count updates on click but the visible number is `aria-hidden="true"` and there's no live region. Toggling like/unlike makes no announcement. Wrap the like+count cluster with `role="status"` `aria-live="polite"` or expose the count via `aria-label={"${likeCount} likes"}` on the button (and re-render on change). Same gap for bookmark toggle (`:346`).

- `src/app/champions/[pokemon]/MegaLandingContent.tsx:107-115` and `src/app/champions/ChampionsContent.tsx:140-149` — Type-pill colors (Normal `#A8A878`, Electric `#F8D030`, Ice `#98D8D8`, Ground `#E0C068`, Fairy `#EE99AC`, Flying `#A890F0`) with white text fail 4.5:1 contrast. Electric `#F8D030` + white is ~1.7:1 — unreadable. These are type labels appearing on every Champions page. Fix: darken the bg or switch to dark text on light types (Showdown's own convention).

- `src/app/champions/[pokemon]/MegaLandingContent.tsx:89` — Breadcrumb `<nav>` has no `aria-label="Breadcrumb"`. Compare `src/app/faq/page.tsx:146` which gets this right. Add `aria-label="Breadcrumb"`.

## Medium-impact

- `src/components/layout/PageNavbar.tsx:88-98` — Dark mode toggle button is the only place announcing dark mode state via `aria-label="Toggle dark mode"` — but the label never updates with the current state. Use `aria-label={darkMode ? "Switch to light mode" : "Switch to dark mode"}` and add `aria-pressed={darkMode}` so toggle state is conveyed.

- `src/components/explore/ExploreFilters.tsx:283-298` — Search-category chips use `aria-pressed` (good), but the inline SVG icons are wrapped in a `<span aria-hidden="true">` only on the chip — the chip's accessible name is just the label, which is fine, but the same file at `:367` (chevron in More-filters) and `:390-392` (X icon in active-pill clear button) omits `aria-hidden`. Add `aria-hidden="true"` to all decorative SVGs in this file for consistency.

- `src/components/explore/ReportCard.tsx:160` — The whole card is an anchor (`motion.a`), but inside it there are nested interactive children (like, bookmark, creator link). Nested interactives inside an `<a>` violates HTML semantics and breaks keyboard tabbing order in some screen readers. Consider moving the card href onto an overlaid `<a>` with `aria-label={tournamentName ?? species.join("/")}` and a `::before` clickable layer, or use the "card wrapper as `<a>`" pattern with `onClick={stopPropagation}` (already present) plus making interior buttons `type="button"` (they are). At minimum, this needs documented testing — accessible-name conflict between the outer `<a>` text content and the child button labels.

- `src/components/compare/CompareContent.tsx:405,424` — Team A / Team B `<label>` elements have no `htmlFor` and the corresponding textareas (`:415, :434`) have no `id`. The label/control association is broken; screen readers will not announce "Team A" when focusing the textarea. Add `id="paste-a"` / `id="paste-b"` and matching `htmlFor`. Also add `aria-label` to the report-select `<select>` in `ReportDropdown` (`:82`) — currently labeled only by its disabled placeholder option.

- `src/components/compare/CompareContent.tsx:443` — Fetch error is a styled `<p>` with no `role="alert"` / `aria-live`. When fetch fails the error appears silently. Add `role="alert"` (or wrap in `aria-live="assertive"`).

- `src/components/layout/PageFooter.tsx:62-68` — "Cookie Settings" button dispatches a `window` custom event with no visible feedback or focus handoff. If the cookie banner doesn't auto-focus when opened, keyboard users are stranded. Verify (out of audit scope) and consider `aria-haspopup="dialog"`.

- `src/components/report/PokemonCard.tsx:271-294` — Damage calculator external link has `aria-label` (good) but is a 44x44 hit target sitting next to other 44x44 targets in a row (Mega toggle, replace, MVP). Touch-spacing rule (8px gap) is satisfied by parent `gap-1 sm:gap-1.5` only on sm+; on mobile `gap-1` = 4px, below the 8px guideline. Bump to `gap-2` on mobile.

- `src/app/feedback/FeedbackContent.tsx:197-222` — Type selector buttons (`motion.button`) have no `aria-pressed` to convey the selected state to AT. The visual selected state is colour + ring only. Add `aria-pressed={type === t.value}`.

- `src/app/feedback/FeedbackContent.tsx:269-273` — Character countdown (`{2000 - description.length}`) is purely visual. Wrap in `<span aria-live="polite">` so AT users hear approaching the limit (especially when it flips amber at 1800).

- `src/components/explore/ExploreFilters.tsx:413-419` — `AnimatePresence` height collapse for advanced filters does not set `aria-hidden` while collapsed. If `motion` keeps the DOM mounted during exit, focusable controls inside (`SpeciesChipPicker` inputs, event-type `<select>`) remain in the tab order while invisible. Verify and add `inert` or `aria-hidden` to the collapsed wrapper.

- `src/components/layout/PageNavbar.tsx:104` — Mobile fixed bottom bar overlays page content on small screens. Pages account for this with `pb-24 sm:pb-12` on `<main>`, but ensure the bar doesn't trap focus visually — it has no `aria-label` translation; "Mobile navigation" is hard-coded English while the rest of the site is translatable.

- `src/components/report/MatchupSheet.tsx:84-99` — Drag-and-drop reorder is mouse/touch only. Keyboard users cannot reorder matchup plans. Add keyboard-accessible move-up/move-down buttons (Arrow-up / Arrow-down with `aria-label="Move up"`).

- `src/components/compare/CompareContent.tsx:206-217` — Pokemon card uses `displaySpecies` text and `TypeBadge` but no `role="group"` or `aria-label` around the card. Each card is a focusable region only via the sprite img (which has `alt`). Low priority but worth grouping.

- `src/app/champions/ChampionsContent.tsx:128-152` — "Coming Soon" disabled cards use `aria-disabled="true"` but the inner Pokemon name is `text-text-tertiary` (#5E5E7A on `bg-surface/60` = ~4.6:1, borderline) and the ability is `text-text-tertiary/70` (drops below 3:1). Bump ability text to at least text-text-tertiary or use `text-text-secondary`.

- `src/components/layout/Navbar.tsx:139-160` — `WarningPopover` opens on click but has no `role="dialog"` / `aria-expanded` on the trigger button. Keyboard users can tab to it but pressing Esc won't close it — only outside-click does. Add `aria-expanded={open}`, focus the popover when opened, and close on Escape.

- `src/components/explore/ExploreFilters.tsx:255-270` — Sort `<select>` has `aria-label` (good) but the down-chevron SVG next to it (line 267) has no `aria-hidden`. Decorative. Add `aria-hidden="true"`.

- `src/components/report/TeamOverview.tsx:432-438` — QR code `<img>` has good alt text but is an img tag (not Next/Image); fine for a11y but ensure `loading="lazy"` to avoid CLS (it's a perf nit, not a11y issue).

- `src/components/explore/ExploreFilters.tsx:225-240` — Search input placeholder uses `text-text-tertiary` (#5E5E7A) which sits at ~5.78:1 against `bg-surface` (`#FFFFFF` light) — passes AA for normal text, but several places (e.g. `src/components/compare/CompareContent.tsx:419, :438`) use `placeholder:text-text-tertiary/40` which drops to ~2.3:1 — fails AA. Same anti-pattern in `src/components/report/TeamStats.tsx`, `PokemonCard.tsx`, `MatchupPlanSlide.tsx`, `MatchupSheetRow.tsx`. Replace `/40` with `/70` or full `text-text-tertiary`.

- `src/app/privacy/page.tsx:14`, `src/app/terms/page.tsx:14` — These pages have no `<PageNavbar>` rendered above them (they rely on `PersistentNavbar`). Confirmed OK, but the `<main>` element has no `id="main-content"` to match the layout's "Skip to content" link target. The skip link in `src/app/layout.tsx:104` references `#main-content`, but no `<main id="main-content">` exists on Privacy/Terms/Feedback/FAQ/Champions/Explore/Compare. The skip link is currently broken everywhere. Fix: add `id="main-content"` to the `<main>` in every page (one-line each).
