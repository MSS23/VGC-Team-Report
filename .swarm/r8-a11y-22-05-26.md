## CRITICAL

### C1. Mega Evolution toggle on Pokemon detail/card is below 44×44 touch target — visible to all viewers
- File: `/src/components/report/PokemonCard.tsx:244-258` — class `w-7 h-7 sm:w-6 sm:h-6` (28/24 px)
- File: `/src/components/report/PokemonDetailSlide.tsx:585-600` — class `w-9 h-9 sm:w-8 sm:h-8` (36/32 px)
- WCAG 2.5.5 (Target Size — AAA, but project's stated baseline is 44×44 per CLAUDE.md UI standards).
- This button is rendered for **every** viewer of a Mega-capable team on /s/[id], not just creators. The aria-label/aria-pressed are correct — only the size is wrong.
- Fix: bump to `min-w-[44px] min-h-[44px]` (or `w-11 h-11` on mobile, keep `sm:w-9 sm:h-9` if desktop density matters).

### C2. PokemonCard icon-button cluster (damage calc, replace, MVP) — all ~30 px touch targets
- File: `/src/components/report/PokemonCard.tsx:266-289` damage calc anchor — `p-2` + 14 px svg ≈ 30 px (always rendered, including public read-only view; only suppressed in print mode).
- File: `/src/components/report/PokemonCard.tsx:294-307` replace button — `p-2` + 14 px svg ≈ 30 px.
- File: `/src/components/report/PokemonCard.tsx:309-325` MVP star — `p-2` + 16 px svg ≈ 32 px.
- WCAG 2.5.5.
- Fix: replace `p-2` with `min-w-[44px] min-h-[44px] flex items-center justify-center` (and keep the small inner svg).

### C3. Mobile slide-progress slider has `role="slider"` + `tabIndex={0}` but no keyboard handlers
- File: `/src/components/report/SlideNavControls.tsx:220-261`
- WCAG 2.1.1 (Keyboard) + 4.1.2 (Name/Role/Value).
- The element is announced as a slider to screen readers and is focusable, but Arrow-Left/Right / Home / End do nothing. Touch and tap-to-seek work; keyboard does not. (Prev/Next buttons on either side still work, but the slider itself is a keyboard trap of sorts — focuses, can't be interacted with.)
- Fix: add `onKeyDown` handling Arrow keys → `onGoTo(currentSlide ± 1)`, Home/End → `onGoTo(0 / totalSlides-1)`; or drop `tabIndex={0}` and `role="slider"` and rely on Prev/Next buttons (simpler — the slider is a touch convenience, the buttons are the real keyboard surface).

## SERIOUS

### S1. Missing `<h1>` on /s/[id] shared report views when creator left teamName + tournamentName blank
- File: `/src/components/report/TeamOverview.tsx:393-416`
- `<h1>` only renders if `teamName` is truthy; `<h2>` only if `tournamentName` is truthy.
- When both are empty (common for casual link-shares) the entire report has **no h1**. WCAG 1.3.1 (Info & Relationships) + 2.4.6 (Headings & Labels).
- Fix: render a fallback `<h1 className="sr-only">{tournamentName || speciesLine || "VGC Team Report"}</h1>` when neither user-provided heading is present, so assistive tech still has a document landmark.

### S2. Edit-mode TeamOverview skips h1/h2 entirely
- File: `/src/components/report/TeamOverview.tsx:489-555`
- In creator/edit mode the first heading is `<h3>` ("Tournament Info") followed by `<h4>` (Tags) and then another `<h3>` (Team Summary). No h1 or h2 anywhere on the editing surface (the team-name + tournament-name fields are bare `<input>` elements, not headings).
- WCAG 1.3.1 / 2.4.10.
- Fix: wrap the page in an `<h1 className="sr-only">Edit team report</h1>` (or render visible `<h1>{teamName || "Untitled team report"}</h1>` above the inputs).

### S3. Export Theme modal has no focus trap
- File: `/src/app/page.tsx:1723-1803`
- The modal sets initial focus into the dialog (line 415-423 `useEffect`) but has no Tab cycle trap and no Escape handler attached to the dialog itself (Escape only fires while the backdrop has focus via `onKeyDown` on the outer div — which isn't focusable by default).
- WCAG 2.1.2 (No Keyboard Trap — inverse failure: focus escapes the modal back to the page underneath) and 2.4.3 (Focus Order).
- Fix: lift the focus-trap logic from `ShareModal.tsx:128-175` into a reusable hook and apply it here. Add `useEffect` Escape listener on the dialog ref.

### S4. Tournament/team form `<input>` elements have no labels
- File: `/src/components/report/TeamOverview.tsx:495-542` — teamName, tournamentName, placement, record, rentalCode, creatorName.
- File: `/src/components/report/TeamOverview.tsx:170-177` — Update-Team textarea.
- File: `/src/components/report/TeamOverview.tsx:643-650` — Team Summary textarea (when editing).
- File: `/src/components/report/PokemonCard.tsx:365-372` — Pokemon role input.
- File: `/src/components/report/PokemonDetailSlide.tsx:854-860` — Pokemon notes textarea.
- File: `/src/components/report/MatchupPlanSlide.tsx:681-687, 742-755` — game-plan notes textarea + replay URL input.
- File: `/src/components/report/CalcInput.tsx:215-227, 357-369` — bulk-paste textarea + single calc input.
- File: `/src/components/report/AddOpponentInput.tsx:85-114` — opponent label input + paste textarea.
- All use only `placeholder` for affordance. Placeholders are not accessible names (WCAG 1.3.1 / 3.3.2 / 4.1.2). Screen-reader users hear "edit text" with no context.
- Fix: add visible `<label htmlFor>` (preferred — matches the existing pattern on `/feedback`) or `aria-label` (faster shim if visual design is locked).

### S5. ExploreFilters sort dropdown has no label
- File: `/src/components/explore/ExploreFilters.tsx:262-274`
- `<select>` for sort order with no `<label>` and no `aria-label`. Adjacent search input has placeholder only (also see S6 below). WCAG 1.3.1 / 3.3.2.
- Fix: `aria-label="Sort reports"` on the `<select>`.
- Same pattern on the `Event type` select at line 463-472 (it does have an associated `<label htmlFor>` — that one is fine; the *sort* select is the only one missing).

### S6. Explore search input has no associated label
- File: `/src/components/explore/ExploreFilters.tsx:231-245`
- The main search `<input>` only has a placeholder; no `<label>` or `aria-label`. The decorative search icon is `pointer-events-none` and not labeled.
- WCAG 1.3.1 / 3.3.2.
- Fix: `aria-label="Search VGC team reports"` on the input.

### S7. CalcInput category buttons unlabeled on mobile (icon-only)
- File: `/src/components/report/CalcInput.tsx:319-333`
- The "Offensive / Defensive / Speed" toggle buttons render `<span>{cfg.icon}</span>` (a Unicode emoji) plus `<span className="hidden sm:inline">{label}</span>`. On mobile the label is hidden, leaving an emoji-only button with **no `aria-label` and no `aria-pressed`**.
- WCAG 4.1.2 (Name/Role/Value) + 1.3.1.
- Fix: add `aria-label={catLabelMap[cfg.label] ?? cfg.label}` and `aria-pressed={isActive}` (matching the pattern already used in PokemonDetailSlide.tsx:193-194).

### S8. ReportCard like/save buttons are well under 44 × 44
- File: `/src/components/explore/ReportCard.tsx:314-369`
- Like, sign-in-to-like, save, sign-in-to-save: all `inline-flex items-center gap-1 text-[10px]` with a 13 px SVG and no min-width/min-height. Effective hit area ~16-20 px tall.
- WCAG 2.5.5 (and per project's stated 44 px minimum). These are the primary social actions on the Explore grid.
- Fix: add `min-w-[44px] min-h-[44px] justify-center` to each of the four button variants; or wrap them in a 44 px tap shell that absorbs the click.

### S9. PokemonDetailSlide calc inline-edit buttons under 44 px on mobile
- File: `/src/components/report/PokemonDetailSlide.tsx:187-233`
- Category switcher buttons `h-8 w-8 sm:h-9 sm:w-9` (32/36 px). Delete button same.
- WCAG 2.5.5. Creator-only surface but still applies.
- Fix: bump mobile to `h-11 w-11` (`sm:h-9 sm:w-9` is fine for pointer-device desktop).

### S10. InlinePokemonEditor modal has no focus trap (and the `role="dialog"` element is not focusable for Escape)
- File: `/src/components/report/InlinePokemonEditor.tsx:128-229`
- Has `role="dialog"`, `aria-label`, autofocus into the search input, and an Escape listener on `window` — but Tab can escape the modal into the page beneath. Same issue as S3 but a separate component.
- WCAG 2.4.3 / 2.1.2.
- Fix: apply the same focus-trap pattern as `ShareModal.tsx:128-175`.

## MODERATE

### M1. Mobile sub-tabs in PokemonDetailSlide lack `role="tablist"` / `role="tab"`
- File: `/src/components/report/PokemonDetailSlide.tsx:919-935`
- The "Set / Stats / Notes / Calcs" tab bar uses plain buttons with no ARIA tab roles or `aria-selected`. Compare with MatchupPlanSlide.tsx:350 which does use `role="tablist"`.
- WCAG 4.1.2.
- Fix: add `role="tablist"` to the container, `role="tab"` + `aria-selected={mobileTab === tab}` + `aria-controls` per button, and `role="tabpanel"` on the rendered panel below.

### M2. PokéPaste error toast dismiss button is an inline `<button>` styled as plain underlined text
- File: `/src/app/page.tsx:1807-1819`
- No min-h/min-w; touch target ≈ 18 px. Inside a `role="alert"` toast so screen readers will get the announcement, but mobile users can't easily tap "Dismiss".
- WCAG 2.5.5.
- Fix: bump to `min-h-[44px]` or add proper padding (`px-3 py-2`).

### M3. URL "Loading shared team…" redirect screen has no `aria-live` for the loading state
- File: `/src/app/s/[id]/redirect.tsx:13-21`
- A purely visual spinner; no `aria-busy` or `aria-live` region. Screen reader users get nothing while the redirect runs (usually <100 ms but on slow networks visible).
- WCAG 4.1.3 (Status Messages).
- Fix: wrap in `<div role="status" aria-live="polite">` so the "Loading shared team..." text is announced.

### M4. Decorative SVGs missing `aria-hidden="true"` on the home-page landing flow
- File: `/src/app/page.tsx:778-783, 816-820, 956-959, 1021-1024, 1060-1064, 1089-1093, 1196-1200, 1336-1349`
- Multiple inline SVGs in banners/icons lack `aria-hidden`. They have no `<title>` and no `role="img"`, so most ATs treat them as decorative anyway, but explicit `aria-hidden="true"` is the documented practice and the codebase already does this on most SVGs (good consistency target).
- WCAG 1.1.1.
- Fix: add `aria-hidden="true"` to each of the listed SVGs (mechanical sweep).

### M5. PrivateFields panel select control + "More filters" panel — minor color-only state
- File: `/src/components/explore/ExploreFilters.tsx:339-379` ("More filters" toggle)
- The toggle communicates its open/active state only via background color (`bg-accent/10`). It does have `aria-expanded` (good), but the badge of `advancedFilterCount` is the only non-color signal of "applied filters". Borderline; acceptable because of aria-expanded.
- Note only — not a fix.

### M6. ExploreEmpty substitute sprite has empty `alt=""` (correct) but is the only visual element in the empty state
- File: `/src/components/explore/ExploreEmpty.tsx:33-40`
- Correctly decorative (`alt=""`). Heading + body text carry the meaning. No action needed; flagging only because R5/R8 prior audits flagged decorative `alt` elsewhere. Pass.

### M7. Feedback page submit button color-only severity hint
- File: `/src/app/feedback/FeedbackContent.tsx:324-352`
- Bug=red, improvement=amber, other=blue, feature=accent. The button text ("Submit Bug Report" / "Submit Feature Request") carries the type, so colour is redundant rather than primary. Pass — included only because R8 prior reports flagged similar patterns.

### M8. ShareModal "URL display" and "Embed snippet" rows mix `<div role="button">` with native `<button>` siblings
- File: `/src/components/ui/ShareModal.tsx:354-368, 570-584`
- Both have proper `tabIndex={0}`, `aria-label`, and `onKeyDown` Enter/Space handlers — functionally compliant. Recommendation only: a native `<button>` styled to match would be simpler, but no a11y defect.

### M9. FAQ structured-data slug ids aren't focusable via keyboard
- File: `/src/app/faq/page.tsx:149-158`
- The `<h2 id="...">` slugs power deep links from JSON-LD/AI citations but aren't keyboard-focusable, so screen reader users following a hash link land near the heading but can't easily resume from there. Low impact (URL-fragment focus is generally a browser concern). Suggest `tabIndex={-1}` so `:target` focus works programmatically.
