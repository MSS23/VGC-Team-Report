### 1. [HIGHEST IMPACT] Add `llms.txt` — AI Engine Optimization Entry Point

**What:** Create `/public/llms.txt` (an emerging AEO standard, analogous to `robots.txt` for LLMs) that describes the site's purpose, key URL patterns, and machine-readable summaries for AI citation engines (ChatGPT, Perplexity, Claude, Gemini).

**Why this is #1:** The site already allows AI crawlers in `robots.txt` but gives them no structured context about what the site IS. AI citation engines (Perplexity, ChatGPT search, Gemini) answer queries like "how do I share a VGC team?" by reading page content — but a dedicated `llms.txt` makes the site's authority and purpose explicit to the model layer, improving citation probability. Competitors like Pikalytics dominate SERPs; capturing AI-generated answers is a route to traffic that bypasses traditional SERP ranking entirely.

**Implementation:**

File: `/public/llms.txt`


### 2. Add `logo` + Social `sameAs` to `OrganizationJsonLd`

**Why:** Google's Knowledge Graph and AI citation engines use `Organization.logo` to match entities across the web. Without it the site is less likely to receive a Knowledge Panel or be cited as an authoritative entity. The `sameAs` array with only one GitHub repo link fails to establish cross-platform entity disambiguation, which AI engines rely on to verify and cite a source.

### 3. Add `BreadcrumbList` Schema to `/explore`, `/faq`, `/tournaments`, `/champions` Pages

**What:** Only `/champions/[pokemon]` has `BreadcrumbList` structured data. The other key content pages — `/explore`, `/faq`, `/tournaments`, and `/champions` — render visual breadcrumbs in the UI but emit no `BreadcrumbList` JSON-LD.

**Why:** Google renders breadcrumbs in SERPs as a path below the page title (e.g., `VGC Team Report › Champions`), which increases click-through rate by 5–15% (Moz/SEMrush studies). It also signals page hierarchy to AI engines that read structured data to understand content relationships.

**Add a reusable component to `JsonLd.tsx`:**
```tsx
export function BreadcrumbJsonLd({ items }: { items: Array<{ name: string; item: string }> }) {
  return (
    <JsonLd
      data={{
        "@context": "https://schema.org",
        "@type": "BreadcrumbList",
        itemListElement: items.map((crumb, i) => ({
          "@type": "ListItem",
          position: i + 1,
          name: crumb.name,
          item: crumb.item,
        })),
      }}
    />
  );
}
```

Then in each page (e.g., `/explore/page.tsx`):
```tsx
<BreadcrumbJsonLd items={[
  { name: "Home", item: "https://pokemonvgcteamreport.com" },
  { name: "Explore", item: "https://pokemonvgcteamreport.com/explore" },
]} />
```

Repeat for `/faq`, `/tournaments`, `/champions`.

### 4. Add `SportsEvent` / `Event` Schema to `/tournaments` Page + Fix Missing JSON-LD

**What:** The `/tournaments` page has metadata (title, description, OG) but no JSON-LD at all — the `TournamentsContent` component doesn't emit any schema. Add `Event` or `SportsEvent` schema for indexed tournaments (Indianapolis Regionals, 2026 Worlds, etc.).

**Why:** Google surfaces Event schema in SERPs as rich results with date/location ("Indianapolis Regionals — May 29–31, 2026 · Indianapolis, IN"). For a tournaments archive page, this is high-value real estate. AI engines also use `Event` schema to answer "when is the next Pokemon VGC tournament?" queries — being in that answer is a strong AEO signal.

**Minimum viable implementation in `TournamentsContent.tsx`** (or a new `tournaments/page.tsx` server component that fetches events from DB):
```tsx
<JsonLd data={{
  "@context": "https://schema.org",
  "@type": "SportsEvent",
  name: "2026 VGC Indianapolis Regional Championships",
  startDate: "2026-05-29",
  endDate: "2026-05-31",
  location: {
    "@type": "Place",
    name: "Indianapolis, Indiana",
    address: { "@type": "PostalAddress", addressLocality: "Indianapolis", addressRegion: "IN", addressCountry: "US" }
  },
  organizer: { "@type": "Organization", name: "The Pokemon Company International", url: "https://www.pokemon.com" },
  url: "https://pokemonvgcteamreport.com/tournaments",
  sport: "Pokemon VGC",
  description: "VGC Regulation M-A Regional Championships. Browse team reports from top finishers.",
}} />
```

Add one `SportsEvent` block per major known tournament. These can be static data initially.

### 5. Emit `twitter:site` Handle in Root Metadata + Add `ItemList` to `/champions` Index

**Two sub-fixes bundled as one slot:**

**5a. Missing `twitter:site` handle.** The root metadata in `layout.tsx` has `twitter.card`, `title`, and `description` but no `creator` or `site` handle. Twitter/X uses `twitter:site` to associate the card with a verified account, which improves unfurl trust scores and can boost click-through in social previews. If a `@vgcteamreport` or similar handle exists, add to `layout.tsx`:
```tsx
twitter: {
  card: "summary_large_image",
  site: "@vgcteamreport",   // add this
  ...
}
```

**5b. Missing `ItemList` on `/champions` index.** The `/champions` page lists all Mega Pokemon but has only a generic `WebPage` schema (`ChampionsContent.tsx`). Adding `ItemList` with `@type: Thing` entries for each Mega makes the page eligible for Google's Carousel/Gallery rich results and tells AI engines this is an enumerable, authoritative list of all legal Megas in Regulation M-A.

```tsx
<JsonLd data={{
  "@context": "https://schema.org",
  "@type": "ItemList",
  name: "All Mega Evolutions Legal in Pokemon Champions Regulation M-A",
  url: "https://pokemonvgcteamreport.com/champions",
  numberOfItems: megaList.length,
  itemListElement: megaList.map((m, i) => ({
    "@type": "ListItem",
    position: i + 1,
    name: m.displayName,
    url: `https://pokemonvgcteamreport.com/champions/${m.slug}`,
  })),
}} />
```
