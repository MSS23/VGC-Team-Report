## TL;DR — Ship a real `ItemList` JSON-LD on `/explore` populated with the top N published team reports

The `/explore` page is the natural landing page for "best VGC teams 2026" and
"share VGC team" queries (its `<title>` already says so, and `metadata.keywords`
already targets those exact queries). But the JSON-LD it currently emits
(`src/app/explore/page.tsx:48-79`) is only a `CollectionPage` shell with a
breadcrumb — **it does not list any of the actual teams the page describes.**
To an AI crawler, the page advertises itself as a collection of zero items.

Meanwhile `/api/explore` already returns up to ~20 published, public reports
per request (`src/app/api/explore/route.ts:171-219`) with creator names, view
counts, like counts, comment counts, regulation tags, and update timestamps —
everything an `ItemList` needs to be authoritative.

The single highest-ROI change tonight: convert `/explore/page.tsx` from a pure
client wrapper into a Server Component that fetches the top 20 popular public
reports server-side and emits a fully-populated `ItemList` schema with each
team's URL, name, creator, and `interactionStatistic` (likes + views as
`UserLikes` / `UserPageVisits`). The existing `<ExploreContent />` continues to
hydrate the interactive UX on the client.

### Why it's the highest-ROI 2026 win

1. **Category-query targeting.** AI answers for "best VGC teams 2026" cite
   pages that present an enumerated, ranked list with names and metadata —
   exactly what an `ItemList` of top-by-likes teams provides. Right now no VGC
   tool publishes a machine-readable list of "top teams" with structured data;
   we'd be first.
2. **2.5x citation lift, documented for 2026.** Schema-compliant pages are
   cited 2.5x more often by Perplexity and ChatGPT (digidop / ailabsaudit 2026
   GEO research). `ItemList` specifically is what Google uses to classify
   pages as "listings" and surface them as carousel rich results — the same
   structural signal AI engines use to decide which page is the canonical
   "list of top X."
3. **Already-built infrastructure.** Database, ranking logic, and HTML render
   all exist. The change is ~60 lines: a server fetch + a JSON-LD block. No
   new content, no new authors, no editorial calendar.
4. **Crawler-friendly.** `/explore`'s server-rendered HTML currently emits the
   `CollectionPage` schema but no team data. After this change, GPTBot,
   ClaudeBot, and PerplexityBot (all explicitly allowlisted in
   `src/lib/security/bot-detection.ts:73-78`) get a clean, enumerated list of
   our best teams in the very first byte of the response — no JS execution
   required.
5. **Compounds existing work.** Each entry's URL points to a `/s/[id]` share
   page that already carries its own `CreativeWork`/`Article` schema. The
   `ItemList` acts as a hub that distributes authority to the share pages and
   tells AI which 20 reports are canonical/popular this week.

### Implementation note (avoid double-fetch)

Don't do `fetch('/api/explore?sort=popular')` from the server component — it
costs an extra edge invocation and a network hop on every page render. Either:
(a) extract the popular-sort SQL into `src/lib/explore/get-popular-reports.ts`
and import it in both `/api/explore/route.ts` and `/app/explore/page.tsx`, or
(b) inline the same SQL directly in the server component. Vercel ISR with
`revalidate = 300` (5 min) is plenty fresh — top teams don't churn faster than
that, and it caps build invocations to ~288/day.

## Suggested JSON-LD block

Drop into `src/app/explore/page.tsx` next to the existing `<JsonLd>`:

```tsx
// Top N popular public reports, fetched server-side. Revalidate every 5 min.
const topReports = await getPopularPublicReports({ limit: 20 });

<JsonLd
  data={{
    "@context": "https://schema.org",
    "@type": "ItemList",
    name: "Best VGC Teams 2026 — Top Community Reports",
    description:
      "The most-liked competitive Pokémon VGC team reports published to VGC Team Report, ranked by community reactions. Includes Pokémon Champions Regulation M-A teams with Mega Evolution.",
    url: "https://pokemonvgcteamreport.com/explore",
    numberOfItems: topReports.length,
    itemListOrder: "https://schema.org/ItemListOrderDescending",
    itemListElement: topReports.map((r, i) => ({
      "@type": "ListItem",
      position: i + 1,
      url: `https://pokemonvgcteamreport.com/s/${r.id}`,
      item: {
        "@type": "CreativeWork",
        "@id": `https://pokemonvgcteamreport.com/s/${r.id}`,
        name: r.title || `VGC Team Report by ${r.creatorName || "Anonymous"}`,
        url: `https://pokemonvgcteamreport.com/s/${r.id}`,
        ...(r.creatorName && {
          author: { "@type": "Person", name: r.creatorName },
        }),
        ...(r.regulation && { about: `Pokémon VGC ${r.regulation}` }),
        datePublished: r.createdAt,
        dateModified: r.updatedAt,
        interactionStatistic: [
          {
            "@type": "InteractionCounter",
            interactionType: "https://schema.org/LikeAction",
            userInteractionCount: r.likeCount ?? 0,
          },
          {
            "@type": "InteractionCounter",
            interactionType: "https://schema.org/ViewAction",
            userInteractionCount: r.viewCount ?? 0,
          },
        ],
        isPartOf: {
          "@type": "WebApplication",
          name: "VGC Team Report",
          url: "https://pokemonvgcteamreport.com",
        },
      },
    })),
  }}
/>
```

### Why these specific fields

- `itemListOrder: ItemListOrderDescending` + `numberOfItems` — Google's rich
  result eligibility requires both for ranked carousels. AI crawlers use the
  same fields to decide whether to extract the list verbatim into an answer.
- `position` on each `ListItem` — required by spec; without it Google ignores
  the list.
- Wrapping each entry as a `CreativeWork` with `@id` pointing back to the
  `/s/[id]` URL creates a citation graph: the hub page (`/explore`) endorses
  each share page, and AI engines following the graph land on a fully-formed
  share page with its own schema. This is the "schema stack" effect from
  ailabsaudit's 2026 research.
- `interactionStatistic` with real like/view counts gives Perplexity a
  popularity signal *without* needing an `aggregateRating` (which would
  require an external review source we don't have).
- `author` (when present) gives Perplexity the named-authorship signal that
  `r7-aeo-citations.md` flagged as a "confirmed Perplexity citation signal."
  We already store `creatorName` on every public report.
- `datePublished` + `dateModified` solve the "Perplexity cites <30-day-old
  content at 82%" recency signal that prior R7 reports flagged but didn't
  attach to /explore. Each top-team entry now carries a fresh timestamp.
