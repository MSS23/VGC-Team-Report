**Date:** 2026-06-29
**Build:** Next.js 16.2.6 / React 19 / Turbopack production build
**Method:** built locally, summed raw + gzip bytes of every `<script src>` chunk
referenced from `.next/server/app/*.html`, identified chunk contents via

classic per-route First Load JS table, so the chunk map below is the source
of truth.

## 4. Top 5 NEW prioritized recommendations

### #1 — Stop bundling zod on the home route (NEW, ~75 KB gzip)

- **Problem:** `src/lib/sharing/url-codec.ts` does `import { z } from "zod"` at module top.
  It's imported by `useHomePage.ts`, `useShareFlow.ts`, `useShareUrl.ts`, `useAutoDraft.ts`,
  `useCollaborativeSync.ts`, `src/app/page.tsx`, `src/lib/utils/diff-state.ts`,
  `src/lib/utils/version-diff.ts`. Result: zod 4's full runtime + locale tables
  end up in the 484 KB `0tqjik8d73i53.js` chunk shipped on `/`. Zod alone is
  ~50–75 KB gzip.
- **Why it matters now:** added in commit `f5217c0` ("Shared-report URLs are now schema-validated").
  Defensive coding win, but the schema runs on every cold home visitor.
- **Fix (~60 min):**
  1. Move the zod `safeParse` call from `url-codec.ts` into a separate
     `url-codec-validate.ts` module that is **only** imported by the
     decode-from-URL path (`useShareUrl`, the `/s/[id]` route handler).
  2. Replace the type-only re-export on `cache.ts` with a structural type
     so the Redis layer doesn't pull zod either.
  3. Verify with `grep -ao zod 0tqjik...js` — should drop from 475 → 0.
- **Impact:** ~75 KB gzip off `/`, ~50 KB off every route that ends up in the same shared chunk.
- **Conflict risk:** `src/app/page.tsx`, `src/lib/sharing/url-codec.ts` (callers
  `useHomePage.ts`, `useShareFlow.ts`, `useShareUrl.ts`) are all in
  `.swarm/main-changed-files.md`. Coordinate with whoever last touched the
  share flow.
- **Files:** `src/lib/sharing/url-codec.ts` (209 LOC), `src/lib/cache.ts`,
  `src/hooks/useShareUrl.ts`, `src/hooks/useShareFlow.ts`, `src/hooks/useHomePage.ts`,
  `src/hooks/useAutoDraft.ts`, `src/hooks/useCollaborativeSync.ts`, `src/app/page.tsx`,
  `src/lib/utils/diff-state.ts`, `src/lib/utils/version-diff.ts`.

### #2 — Deduplicate `dex-subset.json` across routes (NEW, ~48 KB gzip per affected route)

- **Problem:** The same 332 KB `dex-subset.json` is webpacked into two
  byte-different chunks: `103evazcum~c0.js` (shipped on `/`) and
  `02bypvm_bu3vd.js` (shipped on `/compare`). Turbopack treated the import
  chain (`pkmn-dex-fallback.ts` → `dex-subset.ts` → `dex-subset.json`) as
  two distinct module graphs per route entry. Each visitor downloads the
  full subset; a visitor that browses both routes downloads ~96 KB gzip of
  identical data twice.
- **Why it matters now:** new since 2026-05-23. Side effect of the partial
  VGC-214 fix.
- **Fix (~90 min):** two viable paths —
  1. **Move the JSON behind a fetch.** Expose `dex-subset.json` at
     `/api/dex-subset` (returns the file with strong `Cache-Control:
     immutable`). Replace the static `import rawSubset from "./dex-subset.json"`
     in `src/lib/data/dex-subset.ts` with a lazy `await fetch("/api/dex-subset")`
     wrapped in a module-scoped promise. The browser caches the file across
     routes, so `/compare` re-uses the `/`-warmed copy. Net saving on
     `/compare`: ~48 KB gzip every time. On `/`: zero immediate saving but
     it shifts the cost off the cold path (the 332 KB ships only when
     `lookupPokemonFromDex` actually misses the hand-curated static maps,
     which is rare).
  2. **Make the fallback dynamic.** Wrap `pkmn-dex-fallback.ts` in a
     `dynamic(() => import("./pkmn-dex-fallback"))` so it is never on the
     critical client graph at all. Easier to ship, similar effect.
- **Impact:** ~48 KB gzip off `/compare`, plus removes a 332 KB raw cold-path
  cost from anyone who hits both routes.
- **Conflict risk:** `src/lib/data/pokemon.ts` is in
  `.swarm/main-changed-files.md`. Touch carefully — many callers.

### #3 — Convert `ClarityProvider` to a lazy/idle init (NEW, ~5 KB gzip + LCP improvement)

- **Problem:** `src/components/providers/ClarityProvider.tsx` does
  `import Clarity from "@microsoft/clarity"` at module top, and is rendered
  unconditionally from `src/app/layout.tsx`. Clarity's source is tiny
  (~836 bytes), but its `init()` synchronously injects an external script
  (`https://www.clarity.ms/tag/...`) into the page. That request blocks the
  network for a tag that is **not even allowlisted in the CSP**
  (`script-src` in `next.config.ts` lists Clerk, Sentry, PostHog, Vercel
  but not `clarity.ms`) — so the request fires *and* is blocked.
- **Why it matters now:** `PostHogProvider` already mirrors this pattern correctly
  with `requestIdleCallback(load)`. Clarity should do the same and gate on
  `hasAnalyticsConsent()`, matching the consent model PostHog already uses.
- **Fix (~30 min):**
  1. Change to `const Clarity = await import("@microsoft/clarity")` inside
     the `useEffect`.
  2. Wrap in `if (!hasAnalyticsConsent()) return;` + `onConsentChange` subscription.
  3. Schedule with `window.requestIdleCallback(load, { timeout: 3000 })`.
  4. Either remove ClarityProvider entirely (CSP blocks it anyway) **or**
     add `https://www.clarity.ms https://*.clarity.ms` to `script-src` and
     `connect-src` in `next.config.ts`.
- **Impact:** Removes a blocked main-thread request from every page,
  small (~5 KB raw) JS shave on layout chunk, and unblocks ~50–150 ms of
  TBT on cold load (browser still parses + queues the blocked script).
- **Conflict risk:** None — file not in changed files list.
- **Files:** `src/components/providers/ClarityProvider.tsx`, `src/app/layout.tsx`,
  `next.config.ts` (CSP).

### #4 — Force Turbopack to share the `html2canvas-pro` chunk (NEW, ~100 KB gzip on second export)

- **Problem:** Despite the runtime `getHtml2Canvas()` singleton in
  `src/lib/dynamic-imports/html2canvas.ts`, Turbopack still emits **three
  separate chunks** containing html2canvas-pro: 418 KB (combined with jsPDF),
  226 KB, 198 KB. Three call sites of `getHtml2Canvas()`
  (`src/lib/utils/export-report.ts`, `src/components/ui/TeamCardExport.tsx`,
  `src/components/ui/OTSSheetModal.tsx`) each create a private chunk.
  A user who triggers more than one export path downloads html2canvas-pro
  twice or three times.
- **Why it matters now:** previous audit assumed the helper would fix this;
  it does at runtime but not at build time. Turbopack treats each
  `import("html2canvas-pro")` call expression as its own splitting point
  regardless of helper indirection.
- **Fix (~30 min):**
  1. Make the `getHtml2Canvas` helper itself the dynamic boundary: have
     each call site call `getHtml2Canvas()` (already true) but **rename the
     module barrel** so the dynamic import lives in `dynamic-imports/`
     only — currently OK, but the issue is Turbopack still inlines the
     dependency.
  2. The fix that actually works in Turbopack 16: re-export the
     `getHtml2Canvas` promise through a `webpackChunkName` magic comment:
     `import(/* webpackChunkName: "html2canvas" */ "html2canvas-pro")`.
     Turbopack 16 honors this name and emits one named chunk.
  3. Same treatment for `getJsPDF()` in `export-report.ts`.
- **Impact:** ~100 KB gzip saved on first export, ~50 KB on second; also
  reduces cold-cache PDF export TTI by ~300 ms on 4G.
- **Conflict risk:** None — not in changed files.

### #5 — Split `motion/react` from the home critical chunk (CARRIED FORWARD, refined)

- **Problem:** zod is the new dominant contributor to `0tqjik8d73i53.js`
  (484 KB), but `motion/react` is still co-located with it. Even after
  win #1 lands, motion will leave ~120 KB raw / ~30 KB gzip on `/`.
  12 files import `motion/react`; most uses are simple fade-in/up-on-mount
  patterns reducible to CSS.
- **Files:** `src/app/changelog/ChangelogContent.tsx` (10 usages),
  `src/app/feedback/FeedbackContent.tsx` (8), `src/app/dashboard/profile/page.tsx` (3),
  `src/app/champions/[pokemon]/MegaLandingContent.tsx` (3),
  `src/components/explore/SpotlightCard.tsx`, `ReportCard.tsx`,
  `ExploreFilters.tsx`, `ExploreEmpty.tsx`, `ExploreContent.tsx`,
  `src/components/input/PasteInput.tsx`, `src/components/social/CreatorProfile.tsx`,
  `src/components/ui/WhatsNewModal.tsx`.
- **Fix (~90 min):** Same approach as 2026-05-23 audit: replace the simple
  fade/translate transitions with Tailwind `transition-opacity`/`transform`
  + `data-[state]`, retain `motion.div` only where springs or `AnimatePresence`
  are actually used (3 of the 12 files). Add `dynamic(() => import("motion/react"))`
  for the remaining call sites.
- **Impact:** ~30 KB gzip off the shared chunk that hits 5 routes (`/`,
  `/changelog`, `/dashboard`, `/explore`, `/feedback`); ~50 KB off the
  `/`-only chunk.
- **Conflict risk:** `PasteInput.tsx` is in `.swarm/main-changed-files.md`.
  Coordinate.
