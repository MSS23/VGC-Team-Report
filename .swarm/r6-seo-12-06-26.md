## Findings

### Finding #1 — `s/[id]/opengraph-image.tsx` exists but is force-suppressed *[KNOWN-AND-UNFIXED is wrong here — this is NEW: the OG image generator was added since 22 May, conflicting with the long-standing `images: []` block]*

- **Page/file**: `src/app/s/[id]/page.tsx:114–133` and `src/app/s/[id]/opengraph-image.tsx` (entire file).
- **Current state**: A working `ImageResponse` OG image generator now exists for every share page — sprite slug map, edge runtime, the lot. But `generateMetadata` in the same route still hardcodes `openGraph.images: []` and `twitter.images: []`, with a long comment explaining the historical "image failed to load" Discord unfurl problem. Net result: the generator is dead code; every share unfurls as a text-only card; the work spent building the OG image is wasted.
- **Proposed change**: Decide one way or the other and commit. Either (a) delete `src/app/s/[id]/opengraph-image.tsx` so future readers don't believe it's live, or (b) remove the explicit `images: []` lines and let Next.js auto-wire the convention file. The historical comment says the issue was sprite CDN + edge runtime timeouts — those are testable in <5 min by visiting `https://pokemonvgcteamreport.com/s/<id>/opengraph-image` directly. If it renders within ~2s, ship it: rich-preview unfurls roughly 3–5× CTR vs text-only on Discord/X.
- **Effort**: TRIVIAL (either delete the file OR delete two `images: []` lines).
- **Expected impact**: HIGH if the image actually renders (every share link gets a rich preview = significantly more clicks from Discord/X/Reddit). ZERO downside on deletion (cleans up dead code).

### Finding #2 — `/compare` is noindexed yet listed in the sitemap (twice) *[NEW since 22 May — `/compare` was indexable in the prior audit]*

- **Page/file**: `src/app/compare/page.tsx:10` and `src/app/sitemap.ts:16, 18`.
- **Current state**: `/compare` now declares `robots: { index: false, follow: true }`. But the sitemap lists it as a static page — twice, with different `priority` values (0.6 then 0.5). Google treats sitemap inclusion as "please crawl this," noindex as "don't show it" — pairing the two wastes crawl budget AND sends conflicting signals. Also, the compare page has full title/description/OG metadata and a clear search intent ("compare VGC teams"), so noindexing it is leaving organic traffic on the table.
- **Proposed change**: Pick one. Recommended path: flip `compare/page.tsx` back to `index: true, follow: true` (it's a public tool page that ranks competitors don't own) AND dedupe the sitemap entry. If keeping noindex (e.g. because compare URLs carry query params that look duplicative), remove both sitemap entries.
- **Effort**: TRIVIAL (two-line edit in `compare/page.tsx`, dedupe one line in `sitemap.ts`).
- **Expected impact**: MEDIUM — `/compare` was the only tool page in the prior audit that had clean canonicals + OG and a real keyword target ("compare VGC teams" / "VGC team diff"). Re-enabling it costs nothing.

### Finding #3 — Footer + desktop nav still missing `/tournaments` and (footer) `/champions`, `/compare` *[KNOWN-AND-UNFIXED — flagged in 22 May Win #3]*

- **Page/file**: `src/components/layout/PageFooter.tsx:7–14`, `src/components/layout/PageNavbar.tsx:13–20`.
- **Current state**: Footer NAV_LINKS = Home / Explore / FAQ / Changelog / Privacy / Terms. Desktop NAV_LINKS = Home / Explore / Champions / Compare / Updates / Feedback. `/tournaments` is reachable from neither persistent surface; `/champions` and `/compare` are absent from the footer entirely.
- **Proposed change**: Add `/champions`, `/tournaments`, `/compare` to footer NAV_LINKS; add `/tournaments` to desktop nav NAV_LINKS between Champions and Compare.
- **Effort**: 1-line (×4 array entries across 2 files).
- **Expected impact**: MEDIUM-HIGH — every page on the site reaches the footer; adding three permanent internal links sitewide is the cheapest internal-PageRank shift available. The 22 May audit estimated ~10–15× link-equity boost to `/champions/[mega-slug]` and `/tournaments` clusters. Six weeks later this is still the highest-leverage unshipped item.

### Finding #4 — `/dashboard` (and dashboard subroutes) still missing `alternates.canonical` *[KNOWN-AND-UNFIXED — flagged in 22 May Win #5a]*

- **Page/file**: `src/app/dashboard/page.tsx:4–8`, plus `src/app/dashboard/profile/layout.tsx`, `src/app/dashboard/privacy/layout.tsx`, `src/app/dashboard/notifications/page.tsx`, `src/app/notifications/page.tsx`.
- **Current state**: All correctly have `robots: { index: false, follow: false }`. None has `alternates.canonical`. Google can still treat `?utm_source=discord`, `?ref=email`, etc. as distinct URLs even on noindexed pages, which leaks parameter variants into the Search Console "crawled — currently not indexed" bucket and burns crawl budget that should be going to `/champions/[mega]` and `/s/[id]`.
- **Proposed change**: Add `alternates: { canonical: "https://pokemonvgcteamreport.com/<path>" }` to each noindexed page's metadata block. Defence-in-depth.
- **Effort**: 1-line × 5 files.
- **Expected impact**: LOW–MEDIUM — won't move rankings directly, but cleans up Search Console noise and avoids a known crawl-budget leak.

### Finding #5 — Sitemap has duplicate `/compare` entries *[NEW — bug introduced since 22 May]*

- **Page/file**: `src/app/sitemap.ts:16` and `:18`.
- **Current state**: Two distinct `/compare` entries with priorities 0.6 and 0.5, both with `changeFrequency: "monthly"`. Google will pick one and ignore the other, but this is plainly a copy/paste regression from when Win #2 was shipped — somebody added the new entry without removing the old one.
- **Proposed change**: Delete the line with priority 0.5 (the duplicate). Also worth noting: `/changelog` has `priority: 0.3`, which is unusually low for an indexable page that lives in the navbar — bump to 0.4 or 0.5 for consistency.
- **Effort**: TRIVIAL (delete one line).
- **Expected impact**: LOW (cosmetic — Google handles dupes silently — but it's a 5-second fix and the file is currently lying about its own structure).

### Finding #6 — `/privacy` and `/terms` still missing `openGraph` + `twitter` blocks *[KNOWN-AND-UNFIXED — flagged in 22 May Win #5b]*

- **Page/file**: `src/app/privacy/page.tsx:5–8`, `src/app/terms/page.tsx:5–8`.

- **Effort**: 1-line (×2 small blocks per file, but mechanical).
- **Expected impact**: LOW (no traffic impact) but pure trust hygiene for B2C compliance flows.

### Finding #7 — Indianapolis 2026 Regional teams should drive a `/tournaments/[slug]` programmatic page family *[NEW — major real-world event since 22 May]*

- **Page/file**: would be new `src/app/tournaments/[slug]/page.tsx`.
- **Current state**: 22 May audit Gap #2 recommended per-regulation landing pages (`/format/reg-h` etc.). Six weeks later, the **Indianapolis Regional 2026** has happened — 1,013 players, Arsal Puri won with Mega Charizard Y + Mega Floette, Wolfe Glick R2'd with Mega Tyranitar + Mega Steelix. Pikalytics, Bulbagarden, Limitless, Victory Road, and MetaVGC all rank for `"Indianapolis Regional 2026 teams"`, `"2026 Indianapolis VGC top cut"`, `"Arsal Puri Charizard team"`. We rank for none of them. The `tournamentName` field on every share record already names the tournament; querying `WHERE data->>'tournamentName' ILIKE '%Indianapolis%'` would produce a populated landing page from existing data.
- **Proposed change**: New dynamic route `/tournaments/[slug]` that resolves to a curated list of tournaments (Indianapolis-2026, Worlds-2026, future regionals). Each page: `<h1>2026 Indianapolis Regional — VGC Team Reports</h1>`, intro paragraph naming top finishers, `SportsEvent` JSON-LD, `ItemList` of the top 9 public shares tagged to that tournament, breadcrumb. The data plumbing already exists.
- **Effort**: new-file (one new route file + a slug-to-tournament-name map).
- **Expected impact**: HIGH — captures a tier-1 seasonal-spike keyword pattern (`"<event> 2026 teams"`) that competitors dominate. Each major event ships one new page; ~6–8 events/year. Net-new informational traffic and a strong internal-link source for `/s/[id]`. Same template will pay off again for Worlds 2026 (San Francisco, August).

### Finding #8 — `/explore` regulation/format filters have no canonical landing pages *[KNOWN-AND-UNFIXED — 22 May Gap #2, still unshipped, escalated in priority by ChampionsMeta growth]*

- **Page/file**: would be new `src/app/format/[regulation]/page.tsx`.
- **Current state**: `/explore?regulation=H` (and `=M-A`, `=G`, `=I`) works as a filter, but there is no static URL with `<h1>Regulation H VGC Teams</h1>` for search engines to rank. ChampionsMeta.io has overtaken us on `"reg M-A teams"` queries since 22 May (they're indexing 14K+ teams and 201 tournaments). Pikalytics owns the format-stats version. Nobody on the first SERP serves the "browse community-curated reg-X teams in one URL" intent — and we have the database.
- **Proposed change**: Static routes `/format/reg-m-a`, `/format/reg-h`, `/format/reg-i`, `/format/reg-g`, each rendering `ExploreContent` with the regulation filter pre-applied + a short `<h1>`-headed intro + an `ItemList` JSON-LD of the top 9 public reports for that regulation. Title pattern: `"VGC Regulation M-A Teams — Top Reg M-A Team Reports & Builds"`. Zero manual upkeep; auto-populated from `shares`.
- **Effort**: new-file (one shared route + a 4-entry regulation map). ~1–2h.
- **Expected impact**: HIGH — programmatic SEO that scales with the format calendar (every new regulation set gets a new high-intent landing for free).

### Finding #9 — `/ots-generator` standalone landing for the in-app OTS modal *[KNOWN-AND-UNFIXED — 22 May Gap #3]*

- **Page/file**: would be new `src/app/ots-generator/page.tsx`.
- **Current state**: `OTSSheetModal` (`src/components/ui/OTSSheetModal.tsx`) ships a fully working VGC Open Team Sheet generator (sprites + QR code + downloadable PNG) — but it's only reachable from inside a share's menu. The query `"VGC open team sheet generator"` has near-zero owned-tool competition (forum threads, a Chrome extension, NuzTools). Six weeks after the 22 May audit identified this as the highest-leverage keyword gap, it's still unshipped while competitors (PikaChampions, ChampDex, Champions Lab) have all launched standalone tool pages.
- **Proposed change**: New static route `/ots-generator` with `<h1>Pokemon VGC Open Team Sheet Generator</h1>`, a paste input that pre-loads the OTS modal flow, a short explainer (reuse the FAQ copy), `SoftwareApplication` JSON-LD specifically for the generator, sitemap priority 0.8.
- **Effort**: new-file (small wrapper page + a `useEffect` paste-to-modal handoff).
- **Expected impact**: HIGH — the SERP has no real tool competitor and we ship the actual generator. Realistic path to #1 for `"VGC OTS generator"` and adjacent within ~6–8 weeks.

### Finding #10 — Homepage JSON-LD is still client-only *[KNOWN-AND-UNFIXED — flagged in 28 May `r6-seo-audit.md` as the single biggest cause of "Google indexes 2 pages"]*

- **Page/file**: `src/app/page.tsx:1, 74–84`.
- **Current state**: `page.tsx` is still `"use client"`, so `FAQPageJsonLd` and `HowToSchema` only render after JS execution. Googlebot's renderer often skips JS-emitted JSON-LD on new domains with low crawl budget. This was called out 15 days ago as a *critical* finding — it remains unfixed. The site still likely has only 2–3 pages indexed.
- **Proposed change**: Hoist `<FAQPageJsonLd />` and `<HowToSchema steps={HOW_TO_STEPS} />` out of the client component. Two options: (a) move them into `layout.tsx` (simplest, makes them global — overkill but cheap), or (b) wrap them in a tiny server component sibling exported from a new `src/app/_home-schema.tsx` and render it next to `<Home />` from a server-component shell. The 22 May audit notes that the same FAQ schema already renders server-side from `/faq/page.tsx` — duplicate FAQ schema on `/` and `/faq` is fine per Google's docs.
- **Effort**: 1-line move (option a) or ~10-line new-file shim (option b).
- **Expected impact**: HIGH — if this is genuinely the blocker on home-page indexing, every other recommendation here is downstream of fixing it.

## Keyword opportunities (June 2026 — 3-query web check)

Three quick top opportunities from a June 2026 SERP check, kept narrow because the 22 May audit covered the broader keyword landscape:

1. **`"Pokemon Champions SP spread <species>"`** — Pokemon Champions launched April 8 2026 on mobile (June 17 wider release). Pikalytics owns `champions/<species>` URLs already; community guides (PokeStats, Game8, ChampDex) own the "how does SP training work" informational intent but NOT the per-species spread page. Our existing `/champions/[pokemon]` template targets this — but only for the ~40 sprited Megas. Extending to the broader Reg M-A roster (Greninja, Gengar, Dragonite — all flagged as top picks in the SERP) compounds existing template ROI. (Reinforces 22 May Gap #1.)
2. **`"<Tournament> 2026 teams"` (Indianapolis-Regional-2026, Worlds-2026)** — Confirmed real seasonal-spike traffic pattern (Arsal Puri's Charizard team is being searched right now). Drives Finding #7 above. Limitless, Pikalytics, MetaVGC, Bulbagarden all rank. Victory Road's `/champions-replica/` page is a near-direct keyword competitor.
3. **`"VGC Mega Evolution tier list 2026"` / `"Pokemon Champions tier list"`** — ChampionsMeta.io, Showdown Tier, and ChampDex are the SERP. Our `/champions` page is an ItemList — not a tier list — and ranks for `"Pokemon Champions format"` but not `"tier list"`. A modest content addition (top-5 / mid / niche groupings on `/champions` driven by `share` count + view count as a usage proxy) could rank for the tier-list query without manual editorial work. **Don't write this as a new page** — augment the existing `/champions` page so we don't dilute its existing authority.
