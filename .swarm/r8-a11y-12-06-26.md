## P0 — Blocks usage for assistive-tech / keyboard users

### P0-1. ShortcutHintOverlay is a modal that's invisible to screen readers   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/ui/ShortcutHintOverlay.tsx:56-92`
- WCAG 4.1.2 (Name, Role, Value), 2.1.2 (No Keyboard Trap), 1.3.1.
- Current: full-screen `<div className="fixed inset-0 z-50 …">` overlay with
  `<h3>Keyboard Shortcuts</h3>`. No `role="dialog"`, no `aria-modal="true"`,
  no `aria-labelledby`, no focus trap, no `tabIndex={-1}` container, no
  focus-restore. The Escape listener is fine but Tab still escapes underneath.
  Screen readers announce nothing when the user hits `?` to open it.
- Fix: wrap the inner panel in `<div role="dialog" aria-modal="true"
  aria-labelledby="shortcut-hint-title" ref={dialogRef} tabIndex={-1}>` and
  reuse the focus-trap pattern from `OTSSheetModal.tsx:132-179`. The header
  `<h3 className="…">{t.keyboardShortcuts}</h3>` already exists at line 65 —
  just add `id="shortcut-hint-title"`.

### P0-2. LanguageSelector dropdown has no listbox/combobox semantics or keyboard nav   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/ui/LanguageSelector.tsx:26-89`
- WCAG 4.1.2, 2.1.1 (Keyboard).
- Current: trigger `<button>` has `aria-label={t.language}` but no
  `aria-haspopup`, no `aria-expanded`, no `aria-controls`. The opened menu
  `<div>…</div>` at line 44-86 is a plain div with `<button>` children — no
  `role="menu"`/`role="listbox"`, no `role="menuitem"`/`role="option"`, no
  `aria-selected`, no arrow-key navigation, no Escape-to-close (only outside
  click via `mousedown` listener at line 17-23). Keyboard users can Tab through
  options but the menu doesn't announce as a menu and Escape doesn't close it.
- Fix: add `aria-haspopup="listbox"` + `aria-expanded={isOpen}` to the trigger.
  Convert the option container to `role="listbox" aria-label={t.language}`, each
  language `<button>` to `role="option" aria-selected={isActive}`. Add an
  `onKeyDown` Escape handler on the menu and ArrowUp/ArrowDown to move focus
  between options. Same pattern as `PokemonDropdown.tsx` (already passes —
  verified in May 22 audit as "Not a defect").

## P1 — Poor UX for screen-reader / mobile users

### P1-3. WhatsNewModal never restores focus on close   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/ui/WhatsNewModal.tsx:62-107`
- WCAG 2.4.3 (Focus Order).
- Current: focus trap (`handleFocusTrap` lines 80-107) and Escape handler are
  fine. But `dismiss()` (line 75-78) only calls `setShow(false)` + sets the
  storage key — no `previouslyFocused.focus()` restore. The modal is launched
  at app boot, so the user often had no prior focus, but on returning-visitor
  pop-ups this leaves focus on the body. The modal is rendered into a portal
  with `tabIndex={-1}` at the root, so focus also never lands inside reliably
  on mount (no auto-focus call into the first focusable element).
- Fix: copy the focus-restore + auto-focus block from `OTSSheetModal.tsx:138-145,
  176-178`. On mount, query for the first focusable inside `dialogRef` and
  `.focus()` it; on unmount, restore to the saved `previouslyFocused`.

### P1-4. VersionHistoryPanel role="dialog" has no aria-modal, focus trap, or Escape handler   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/social/VersionHistoryPanel.tsx:164-169`
- WCAG 2.1.2, 2.4.3, 4.1.2.
- Current: side-panel rendered with `role="dialog" aria-label="Version history"`
  but **no** `aria-modal="true"`, no focus trap (Tab escapes to the page
  beneath), no Escape-to-close (the only close path is clicking the scrim role
  button at line 149-161 or the X at 189-198 — keyboard users on the panel itself
  have no Escape). Restore button click reverts the report — high-impact action
  trapped behind broken focus management.
- Fix: add `aria-modal="true"`, ref the panel, and wire the focus-trap + Escape
  pattern from `OTSSheetModal.tsx:132-179`. Also restore focus to whatever
  triggered the panel open (EditChangelog button).

### P1-5. CreatorProfile sort `<select>` and Dashboard sort `<select>` have no labels   **KNOWN-AND-UNFIXED (sibling pattern of S5)**
- Files:
  - `/home/user/VGC-Team-Report/src/components/social/CreatorProfile.tsx:316-323`
    (`sortBy` newest/views select).
  - `/home/user/VGC-Team-Report/src/app/dashboard/DashboardContent.tsx:198-207`
    (`sortBy` newest/oldest/views/name select).
- WCAG 1.3.1, 3.3.2, 4.1.2.
- Current: bare `<select value={sortBy} onChange={…}>` with no `<label htmlFor>`,
  no `aria-label`. Screen readers announce "combo box, blank" before the options.
- Fix: `aria-label="Sort reports"` (creator profile) / `aria-label="Sort my
  reports"` (dashboard). May 22 audit already shipped this fix on
  `ExploreFilters.tsx` sort select — these two are the same pattern, missed.

### P1-6. Dashboard tab strip uses plain buttons — no tablist semantics, no arrow-key nav   **KNOWN-AND-UNFIXED (May 26 #8)**
- File: `/home/user/VGC-Team-Report/src/app/dashboard/DashboardContent.tsx:155-192`
- WCAG 4.1.2, 2.1.1.
- Current: 8 tabs (`drafts/my/saved/feed/collab/collections/analytics/trash`) all
  rendered as `<button onClick={() => setTab(t)}>` inside a plain
  `<div className="flex items-center gap-1 …">`. No `role="tablist"`, no
  `role="tab"`, no `aria-selected`, no `tabIndex={active ? 0 : -1}`, no
  arrow-key handlers. ChangelogContent's tablist (lines 198-216) is now the
  reference implementation — copy that handler verbatim.
- Fix: mirror `ChangelogContent.tsx:198-216`. The active state is already
  computed (line 165 `tab === t`), so wiring `aria-selected` + `tabIndex` is
  a 3-line change per button.

### P1-7. CollaboratorPanel user-search input has no label; results list has no listbox role   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/social/CollaboratorPanel.tsx:212-218, 239-265`
- WCAG 1.3.1, 3.3.2, 4.1.2.
- Current: search input at 212-218 has only a placeholder ("Search users to
  invite..."); no `<label>`, no `aria-label`. The results dropdown at 239-265
  is a `<div className="mt-2 space-y-1">` with no `role="listbox"`. Each result
  row is a `<div>` containing an Add `<button>` — but the row itself isn't
  announced as a selectable option. This is the collaborator invite flow, an
  ownership-changing action.
- Fix: add `aria-label="Search users to invite as collaborators"` to the input
  (and a `<label htmlFor>` if visible label fits). Add `role="listbox"
  aria-label="Search results"` to the results container, `role="option"` to
  each result row. Same pattern as PokemonDropdown.

### P1-8. CommentSection collapse button: focus moves to hidden form without announcement   **NEW (minor)**
- File: `/home/user/VGC-Team-Report/src/components/social/CommentSection.tsx:158-200`
- WCAG 4.1.3 (Status Messages), 1.3.1.
- Current: toggle button has `aria-expanded={expanded}` (good) and
  `aria-controls` is missing — when expanded the comment form + list appear in
  a `<div>` at line 202-329 with no `id`. Screen readers don't know that
  expanding the button reveals the labeled region.
- Fix: add `id="comments-panel"` to the panel div (line 202) and
  `aria-controls="comments-panel"` to the toggle button (line 158). One-line
  fix; restores the announcement contract.

## P2 — Polish / nice-to-have

### P2-9. ThemePicker locked tiles communicate "locked" only via grayscale + disabled   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/ui/ThemePicker.tsx:40-70`
- WCAG 1.3.1, 1.4.1 (Use of Color).
- Current: each tile is a `<button disabled={!isUnlocked} title={…}>`. The lock
  state is announced as "dimmed/disabled" (because of `disabled`), but the
  *why* — "Unlock at 100 views" — lives in the `title` attribute only, which is
  not reliably read by screen readers and never on mobile (no hover). Sighted
  users see a lock icon (line 64-69) that has no accessible name.
- Fix: add `aria-label={isUnlocked ? theme.name : \`${theme.name} — locked, unlocks at ${tier} views\`}` to the button. The lock SVG is fine as-is once the parent button has a proper label.

### P2-10. FollowButton communicates toggle state only via text + color, no aria-pressed   **NEW**
- File: `/home/user/VGC-Team-Report/src/components/social/FollowButton.tsx:48-77`
- WCAG 4.1.2.
- Current: button toggles between "Follow" and "Following" text + visual state
  but has no `aria-pressed`. Screen reader users navigating with VoiceOver/NVDA
  rotor will see two different button names but won't know it's a toggle.
- Fix: add `aria-pressed={following}` + `aria-label={following ? \`Unfollow ${creatorName}\` : \`Follow ${creatorName}\`}`.

### P2-11. dashboard/profile avatar URL input has no associated label   **NEW (related to May 22 S4)**
- File: `/home/user/VGC-Team-Report/src/app/dashboard/profile/page.tsx:304-310`
- WCAG 1.3.1, 3.3.2.
- Current: parent `<label className="…">Profile Picture</label>` at line 282
  has no `htmlFor` and contains a complex layout (img preview + input + buttons)
  — the label is not associated with the URL `<input>`. Only the placeholder
  ("https://example.com/your-photo.jpg") conveys purpose.
- Fix: `<input id="profile-avatar-url" aria-label="Profile picture URL" …>` or
  split the visible label into its own `<label htmlFor="profile-avatar-url">`.
