# VGC-190 Design: Unlisted Privacy Tier
**Researcher:** Feature Researcher Agent
**Date:** 2026-05-17
**Ticket:** VGC-190 — draft → unlisted → public privacy tier

---

## Current Data Model

The `shares` table has a single boolean column `is_public`:
- `is_public = FALSE` → "Private" (owner sees it in dashboard, not on /explore)
- `is_public = TRUE` → "Public" (listed on /explore, indexed in sitemap, appears in feeds)

There is NO existing `unlisted` or three-state `visibility` field anywhere in the codebase.
The `is_draft` column exists as a separate boolean (used for auto-save drafts before first share).

Key files confirming the current model:
- `src/app/api/share/route.ts` — accepts `isPublic: z.boolean().optional()` in `ShareBodySchema`; writes `is_public` column
- `src/app/api/explore/route.ts` — all three sort queries filter `WHERE s.is_public = TRUE AND s.deleted_at IS NULL`
- `src/app/api/user/reports/[shareId]/route.ts` — PATCH accepts `isPublic: boolean`, writes `is_public`
- `src/app/dashboard/DashboardContent.tsx` — `ManagedReportCard` renders a binary "Public"/"Private" toggle button
- `src/components/ui/ShareModal.tsx` — binary toggle labeled "Listed on Explore"/"List on Explore"; the `!isPublic` badge already reads "UNLISTED" (confusingly — it means private today)

---

## What "Unlisted" Means for VGC-190

A report set to **unlisted** should:
1. Be accessible via direct link (`/s/{id}`) — the URL works for anyone who has it
2. NOT appear in `/explore`, sitemap, creator profiles, or follower feeds
3. NOT require tags or creator name to stay in this state (unlike public)
4. Be represented distinctly from "Private" (which might eventually mean "owner only")

---

## Feasibility: YES — No DB Schema Migration Required

The implementation can be done tonight without a schema migration. The key insight is:

**Strategy A (recommended): Reuse `is_public` as a tri-state via a new `visibility` enum/text column — BUT this requires a migration.**

**Strategy B (no migration): Add a nullable `is_unlisted` boolean column via `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`** — this is additive and safe to run without downtime. Postgres ADD COLUMN with a DEFAULT is instant (no table rewrite). This is the same pattern used by `add-species-column.sql`.

**Strategy C (no migration at all): Encode unlisted as `is_public = FALSE` + a new `JSONB` flag in the `data` blob.** This is the truly zero-migration path but is messy — the data blob is already stripped to a specific schema on write.

**Recommended path: Strategy B** — add `is_unlisted BOOLEAN NOT NULL DEFAULT FALSE` column. A report that is unlisted has `is_public = FALSE, is_unlisted = TRUE`. A truly private report has `is_public = FALSE, is_unlisted = FALSE`.

## Minimal Implementation Plan

### 1. DB Migration (additive, ~5 min)
New file: `src/lib/db/migrations/add-unlisted-column.sql`
```sql
ALTER TABLE shares ADD COLUMN IF NOT EXISTS is_unlisted BOOLEAN NOT NULL DEFAULT FALSE;
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_shares_is_unlisted ON shares (is_unlisted) WHERE is_unlisted = TRUE;
```
Run once before deploying. No downtime, no data loss, no backfill needed (all existing rows default to `FALSE` = private).

### 2. API: share route (`src/app/api/share/route.ts`)
- Add `isUnlisted: z.boolean().optional()` to `ShareBodySchema`
- In UPDATE path: write `is_unlisted = ${isUnlisted ?? false}` alongside `is_public`
- In CREATE path: same
- Keep the tag requirement only for `is_public = TRUE`; unlisted skips the tag gate

### 3. API: PATCH route (`src/app/api/user/reports/[shareId]/route.ts`)
- Add `isUnlisted: z.boolean().optional()` to `UpdateBody` schema
- Write `is_unlisted` column in the UPDATE query

### 4. API: explore route (`src/app/api/explore/route.ts`)
- No change needed. Explore already filters `WHERE s.is_public = TRUE`. Unlisted reports have `is_public = FALSE` so they are invisible to /explore automatically.

### 5. UI: ShareModal (`src/components/ui/ShareModal.tsx`)
- Replace the binary `isPublic` toggle with a 3-state selector: **Private → Unlisted → Public**
- The modal already renders an "UNLISTED" badge for private teams (misleadingly). Repurpose this for real unlisted state.
- Add `isUnlisted` prop, update `onTogglePublic` to `onSetVisibility(v: 'private' | 'unlisted' | 'public')`
- "Unlisted" description: "Anyone with the link can view. Not listed on Explore."

### 6. UI: DashboardContent (`src/app/dashboard/DashboardContent.tsx`)
- `DashboardReport` interface: add `isUnlisted?: boolean`
- `ManagedReportCard.toggleVisibility`: cycle through 3 states instead of toggle
- Display a third badge state: amber "Unlisted" between the existing "Private" (gray) and "Public" (green)
- `DashboardInner` bulk actions: add "All Unlisted" bulk action (optional for tonight)

### 7. Hook: useShareFlow (`src/hooks/useShareFlow.ts`)
- Pass `isUnlisted` through to the share API call
- Return `isUnlisted` from the hook state

### 8. User reports API (`src/app/api/user/reports/route.ts`)
- Add `is_unlisted` to SELECT, return as `isUnlisted` in response

## Notable Gotchas

1. **ShareModal already says "UNLISTED"** for private teams today (line 629). This is pre-existing confusing copy that VGC-190 will correct with real semantics.
2. **Visibility change auth guard** in `share/route.ts` (lines 177-198) only covers `isPublic`. Need to add the same owner-only guard for `isUnlisted` changes.
3. **Follower notifications** (`notifyFollowers`) currently fire for `isPublic = TRUE` on new creates. Unlisted should NOT trigger follower notifications.
4. **Analytics stat card** in DashboardContent shows `publicReports` vs `privateReports`. A third `unlistedReports` counter should be added to `/api/user/analytics` — minor, can defer.
5. **Sitemap** (`src/app/sitemap.ts`) filters `WHERE is_public = TRUE` — no change needed.
