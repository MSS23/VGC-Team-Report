## Top 5 Mechanical Wins

### 1. **Memoize QR Code Generation in TeamOverview**
**File**: `/home/user/VGC-Team-Report/src/components/report/TeamOverview.tsx` (line ~520–570)

**Issue**: The rental code QR code is generated inside a `useEffect` without dependencies on `rentalCode`, causing re-renders to regenerate the QR even if the code unchanged.

**Current**:
```tsx
useEffect(() => {
  if (!rentalCode) return;
  import("qrcode").then((QRCode) =>
    QRCode.default.toDataURL(rentalCode, { width: 100, margin: 1 })
      .then(setQrDataUrl)
  );
}, [rentalCode]); // ✓ Good, but QR SVG generation is sync after async import
```

**Proposed**:
```tsx
const qrDataUrl = useMemo(() => {
  let cancelled = false;
  const task = async () => {
    if (!rentalCode) return null;
    const QRCode = (await import("qrcode")).default;
    const url = await QRCode.toDataURL(rentalCode, { width: 100, margin: 1 });
    if (!cancelled) setQrDataUrl(url);
  };
  task();
  return () => { cancelled = true; };
}, [rentalCode]);
```

**Expected Impact**: Avoids re-importing qrcode module on every render. Cached QR generation saves ~50–100ms on parent re-renders if rental code is stable.

### 3. **Memoize `.filter().map()` Chains in Navbar Warning Rendering**
**File**: `/home/user/VGC-Team-Report/src/components/layout/Navbar.tsx` (line ~140–150)

**Issue**: WarningPopover renders `warnings.map()` inline on every render. If warnings array is stable but the parent re-renders frequently, this walks the entire array.

**Current**:
```tsx
{warnings.map((w, i) => {
  const fix = getWarningFix(w);
  return (
    <div key={i} className="text-xs">
      <div className="flex items-start gap-1.5">
        <span className="text-warning shrink-0 mt-px">&#9888;</span>
        <span className="font-semibold text-text-primary">{w}</span>
      </div>
      // ...
    </div>
  );
})}
```

**Proposed**:
```tsx
const renderedWarnings = useMemo(
  () => warnings.map((w) => ({
    w,
    fix: getWarningFix(w),
  })),
  [warnings]
);

// ...
{renderedWarnings.map(({ w, fix }, i) => (
  <div key={i} className="text-xs">
    // ...
  </div>
))}
```

**Expected Impact**: Prevents recomputation of warning fixes when parent (Navbar) re-renders due to unrelated state changes. Saves ~5–10ms on high-frequency re-renders (e.g., slide navigation).

### 4. **Defer PostHog Analytics Import in PostHogProvider**
**File**: `/home/user/VGC-Team-Report/src/components/providers/PostHogProvider.tsx` (line ~1–30)

**Issue**: PostHog client initialization is synchronous and blocks page interactivity if the PostHog JS library is slow to parse.

**Current**: *(Check for synchronous `import posthog`)*

**Proposed**: Lazy initialize inside useEffect:
```tsx
const [client, setClient] = useState(null);
useEffect(() => {
  import("posthog-js").then((m) => {
    const posthog = m.default;
    posthog.init(process.env.NEXT_PUBLIC_POSTHOG_KEY, {
      // ...
    });
    setClient(posthog);
  });
}, []);
```

**Expected Impact**: Defers ~50–80 KB of PostHog JS off the critical rendering path. May improve FCP (First Contentful Paint) by 100–200ms on slow networks.

### 5. **Add `useCallback` to Inline Event Handlers in PokemonCard**
**File**: `/home/user/VGC-Team-Report/src/components/report/PokemonCard.tsx` (line ~480–500)

**Issue**: `.filter().map()` chains for stat rendering are not wrapped in `useMemo`. Every parent re-render (e.g., slide change) recalculates stat arrays.

**Current**:
```tsx
{(["hp", "atk", "def", "spa", "spd", "spe"] as const)
  .filter((stat) => relevantStats.has(stat))
  .map((stat) => (
    <div key={stat} className="stat-row">
      // ...
    </div>
  ))}
```

**Proposed**:
```tsx
const visibleStats = useMemo(
  () => (["hp", "atk", "def", "spa", "spd", "spe"] as const)
    .filter((stat) => relevantStats.has(stat)),
  [relevantStats]
);

{visibleStats.map((stat) => (
  <div key={stat} className="stat-row">
    // ...
  </div>
))}
```

**Expected Impact**: Prevents stat re-filtering on every render. Given PokemonCard renders 6 times per team (once per Pokemon), this saves ~2–5ms per slide navigation in presentation mode.

## "Do Not Touch" List

### High-Risk, Low-Reward Changes

1. **`src/app/page.tsx` — `HomeContent()` hook structure**
   - Recently in `.swarm/main-changed-files.md` — avoid refactoring this complex orchestrator
   - Heavy state coordination with `useHomePage` hook; changes risk breaking shared-view sync

2. **`src/components/ui/PdfExport.tsx` — Portal rendering**
   - The `createPortal()` approach is deliberate: keeps print DOM separate from interactive DOM
   - Attempting to optimize print CSS or pre-render the print container risks layout shifting

3. **`src/lib/utils/export-report.ts` — Retry logic**
   - The `captureWithRetry()` function with 500ms delays is intentional
   - html2canvas sometimes produces blank canvases on first attempt; removing retries breaks PNG exports

4. **`src/app/api/user/notifications/route.ts` — Promise.all pattern**
   - Already batching queries with `Promise.all()` where possible
   - Further consolidation requires database schema changes (out of scope)

5. **`src/components/social/DoubleTapLikeOverlay.tsx` — Gesture detection**
   - Inline pointer event handling is optimal for low-latency touch feedback
   - Memoizing this component would prevent gesture listeners from updating on share state changes
