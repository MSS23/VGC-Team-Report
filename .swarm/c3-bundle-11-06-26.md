## Quick wins (dynamic-import candidates)

### 1. `motion/react` — 469 KB chunk loaded by 12 components ⚠ biggest win
The `motion`/framer-motion runtime (`chunks/085i3dn7oy7w2.js` = 469 KB raw) is the single largest static client chunk. Every file that does `import { motion } from "motion/react"` at module top level adds itself to the same async chunk graph but forces the page to wait on motion before paint. `next.config.ts` already sets `experimental.optimizePackageImports: ["motion/react"]` (good for tree-shaking sub-paths) but it does **not** make motion lazy.

Files that statically import `motion/react` and only use 1–3 `motion.div`/`AnimatePresence` for entrance animations — strong candidates to either drop motion (use CSS transitions) or wrap in `dynamic()`:

| File | Uses |
|---|---|
| `src/app/changelog/ChangelogContent.tsx` | 8 motion.* calls — keep, but lazy-load via `dynamic()` |
| `src/app/champions/[pokemon]/MegaLandingContent.tsx` | imports motion, 0 motion.* usages → **dead import, remove** |
| `src/app/dashboard/profile/page.tsx` | AnimatePresence + motion in account-settings panels — page-level lazy |
| `src/app/feedback/FeedbackContent.tsx` | motion import, 0 motion.* usages → **dead import, remove** |
| `src/components/explore/SpotlightCard.tsx` | motion import, 0 motion.* usages → **dead import, remove** |
| `src/components/explore/ExploreContent.tsx` | 1 `<motion.div>` wrapping the results grid — replace with CSS `@keyframes fadeIn` |
| `src/components/explore/ExploreEmpty.tsx` | motion import, 0 motion.* usages → **dead import, remove** |
| `src/components/explore/ExploreFilters.tsx` | 3 AnimatePresence (filter panel reveal) — keep |
| `src/components/explore/ReportCard.tsx` | motion import, 0 motion.* usages → **dead import, remove** |
| `src/components/input/PasteInput.tsx` | 5 motion.* (logo float / CTA hover) — replaceable with CSS transitions |
| `src/components/ui/WhatsNewModal.tsx` | 3 AnimatePresence — already dynamically loaded from ExploreContent, good |
| `src/components/social/CreatorProfile.tsx` | motion import, 0 motion.* usages → **dead import, remove** |

**Highest-ROI action:** delete the 6 dead-import lines above. Even without unloading motion, Turbopack's tree-shake should then exclude these files from forcing motion into the rootMain graph. If after that the chunk is still rootMain-shared, wrap remaining call sites in `next/dynamic(() => import("..."), { ssr: false })` at the parent.

### 2. `import * as CookieConsent from "vanilla-cookieconsent"` — 156 KB dep, defeats tree-shaking
`src/components/providers/CookieBanner.tsx:4` uses a star import. The only call site is `CookieConsent.run({...})` inside a `useEffect`. Banner is mounted on every page but only initialises once. Two compounding wins:

```ts
// before
import * as CookieConsent from "vanilla-cookieconsent";
import "vanilla-cookieconsent/dist/cookieconsent.css";

// after
useEffect(() => {
  Promise.all([
    import("vanilla-cookieconsent"),
    import("vanilla-cookieconsent/dist/cookieconsent.css" as never),
  ]).then(([{ run }]) => run({ /* config */ }));
}, []);
```

This removes 156 KB of cookieconsent + its CSS from the initial paint of every page, defers it to idle. ROI: high — banner is below-the-fold UI.

### 3. `@microsoft/clarity` — small (36 KB) but eagerly imported in provider
`src/components/providers/ClarityProvider.tsx:4` does `import Clarity from "@microsoft/clarity"` at module top. Component renders nothing on mount unless `NEXT_PUBLIC_CLARITY_ID` is set. Wrap in `await import` inside the `useEffect`:

```ts
useEffect(() => {
  const id = process.env.NEXT_PUBLIC_CLARITY_ID;
  if (!id) return;
  import("@microsoft/clarity").then(({ default: Clarity }) => Clarity.init(id));
}, []);
```

ROI: small (36 KB), but a one-line change.

### 4. `import * as Sentry from "@sentry/nextjs"` — used in global-error only
`src/app/global-error.tsx:3` star-imports Sentry just for `Sentry.captureException`. global-error is its own route bundle, so impact is limited — but switching to named import `import { captureException } from "@sentry/nextjs"` is free and unambiguous for tree-shake.

### 5. `Navbar.tsx` — split `VersionHistoryPanel` + `NotificationBell`
`src/components/layout/Navbar.tsx:11-12` statically imports `NotificationBell` and `VersionHistoryPanel` (16 KB). Both are conditionally rendered (signed-in users only, version-history is owner-only). Wrap both in `next/dynamic(() => ..., { ssr: false })`. Navbar is on every page so this saves on every first-load.

### 6. `Dashboard` tab-splitting
`DashboardContent.tsx` (58 KB) renders 8 tabs from one bundle even though users see one at a time. Each tab's `useEffect` fetcher + JSX could be extracted to per-tab modules and `dynamic()`-loaded on tab activation. Biggest impact for `/dashboard` first-load.
