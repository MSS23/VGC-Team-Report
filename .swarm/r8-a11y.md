# R8 — Accessibility Findings

Scope: WCAG 2.1 AA audit of marketing pages and report viewer, static analysis only. Already-shipped fixes (text-tertiary contrast bump, OTSSheetModal focus trap, Navbar/PageNavbar 44px, Toggle invalid HTML, ReactionBar aria-pressed) are excluded.

Baseline good news: `src/app/globals.css:822-825` provides a global `*:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` rule, so most components inherit a visible focus ring. The `:focus:not(:focus-visible) { outline: none }` rule has a proper replacement and is fine. `prefers-reduced-motion` is honoured.

## P0 (fix this run — WCAG A violations)

- `src/components/ui/InstallPrompt.tsx:112-205` — Bottom-sheet install modal is rendered as a plain `<div className="fixed inset-0 ...">` with **no `role="dialog"`, no `aria-modal`, no focus trap, no Escape handler, no return-focus on close**. Screen-reader users can't perceive it as a dialog and keyboard users can't dismiss it without clicking. WCAG **2.1.1 Keyboard**, **2.1.2 No Keyboard Trap**, **4.1.2 Name, Role, Value**.
  Fix snippet (mirror the pattern used in `OTSSheetModal.tsx` / `ShareModal.tsx`):
  ```tsx
  const dialogRef = useRef<HTMLDivElement>(null);
  const titleId = "install-prompt-title";
  useEffect(() => {
    if (dismissed) return;
    const previouslyFocused = document.activeElement as HTMLElement | null;
    const first = dialogRef.current?.querySelector<HTMLElement>(
      'button, [href], [tabindex]:not([tabindex="-1"])'
    );
    first?.focus();
    const onKey = (e: KeyboardEvent) => { if (e.key === "Escape") handleDismiss(); };
    window.addEventListener("keydown", onKey);
    return () => { window.removeEventListener("keydown", onKey); previouslyFocused?.focus(); };
  }, [dismissed, handleDismiss]);
  // …
  <div ref={dialogRef} role="dialog" aria-modal="true" aria-labelledby={titleId}
       className="fixed bottom-0 left-0 right-0 z-[61] safe-bottom animate-sheet-up">
    {/* add id={titleId} to the "Install VGC Team Report" / "Add to Home Screen" <p> */}
  ```

- `src/components/social/CollaboratorPanel.tsx:212-218` — Collaborator-search `<input>` has **no `aria-label`, no associated `<label>`, no `htmlFor`**. Only a placeholder names the field. WCAG **1.3.1 Info & Relationships**, **4.1.2 Name, Role, Value**, **3.3.2 Labels or Instructions**.
  Fix:
  ```tsx
  <label htmlFor="collab-user-search" className="sr-only">Search users to invite</label>
  <input id="collab-user-search" type="text" aria-label="Search users to invite" … />
  ```

- `src/components/report/CalcInput.tsx:215-227` and `:359-371` — Both the bulk-paste `<textarea>` and the single-calc `<input type="text">` have **no `<label>` and no `aria-label`** (placeholder only). WCAG **1.3.1**, **3.3.2**, **4.1.2**.
  Fix:
  ```tsx
  <label htmlFor="calc-bulk-paste" className="sr-only">Paste multiple damage calcs</label>
  <textarea id="calc-bulk-paste" aria-label="Paste multiple damage calcs" ref={textareaRef} … />
  // …
  <label htmlFor="calc-single-input" className="sr-only">Add a single calc</label>
  <input id="calc-single-input" aria-label={`Add ${calcCategory} calc`} … />
  ```

- `src/components/report/InlinePokemonEditor.tsx:128-134` — Modal has `role="dialog"` and `aria-label="Replace Pokemon"` but **no `aria-modal="true"`** and **no focus trap** (only Escape close + initial focus at line 96/104). With it open, Tab can move focus to the page behind. WCAG **2.4.3 Focus Order**, **4.1.2**.
  Fix: add `aria-modal="true"` to the dialog div, then add the same Tab-cycling logic ShareModal uses (lines 156-175 of ShareModal.tsx), plus restore focus to the trigger on close.

## P1 (WCAG AA violations — fix this run)

- `src/components/social/CommentSection.tsx:284-308` — Per-comment **Delete / Flag** action buttons are only visible via `opacity-0 group-hover:opacity-100`. On touch devices there is no hover, so these controls are functionally inaccessible without keyboard tab-through. They are also `text-[10px]` with no padding — far under the **24×24 CSS px AA minimum (2.5.8 Target Size)**.
  Fix: drop the opacity-0 hover gating entirely (always-visible), and bump to `inline-flex items-center min-h-[24px] min-w-[24px] px-1.5 py-1 text-xs`.

- `src/components/ui/NotificationBell.tsx:103-121` — Bell trigger button is `p-2` around a 16×16 icon, total ≈32×32. Below **WCAG 2.5.8 AA (24×24)** in practice it passes, but at 32px it is below the project's own 44×44 standard used elsewhere in Navbar/PageNavbar. Bump for consistency:
  ```tsx
  className="relative min-w-[44px] min-h-[44px] flex items-center justify-center rounded-lg text-text-secondary hover:text-text-primary hover:bg-surface-alt transition-all"
  ```

- `src/components/social/FollowButton.tsx:48-77` — Button is `px-3 py-1.5 text-xs` → ≈24px tall. Touch target violation against project policy and on a critical social action. WCAG **2.5.5 / 2.5.8**.
  Fix: add `min-h-[44px]` and `aria-pressed={following}` (it's a toggle):
  ```tsx
  <button … aria-pressed={following} className="inline-flex items-center gap-1.5 min-h-[44px] px-3 py-1.5 …">
  ```

- `src/components/explore/ReportCard.tsx:319, 333, 348, 360` — Like and Save buttons on every explore card use `min-h-[32px]`. Below project 44px standard and tightly packed (gap-2.5) — AA passes the 24px rule but spacing/size combination on a touch-dense grid is risky. Bump to `min-h-[44px] min-w-[44px]` with `-mx-2` to keep visual layout.

- `src/components/explore/ExploreFilters.tsx:241-252` — Search-clear button is `w-6 h-6` (24×24). Sits inside an input row; meets AA target-size with sufficient surrounding spacing, but at min size and adjacent to other tappables. Increase to `w-9 h-9` with negative margin to preserve input padding.

- `src/components/explore/ExploreFilters.tsx:282-298` — Category filter chips are `px-3 py-1.5 text-xs` (~28px tall). Below project 44px standard. WCAG 2.5.5. Add `min-h-[44px]`.

- `src/components/social/CollaboratorPanel.tsx:254-261` — "Add" button is `px-2.5 py-1 text-[10px]` (~20px). Below WCAG **2.5.8 (24×24)**. Bump to `min-h-[32px]` minimum, ideally `min-h-[44px]`.

- `src/components/ui/Button.tsx:21-25` — Base Button `size="md"` (`px-5 py-2.5 text-sm`) and `size="lg"` produce ~36-44px heights depending on font; only `sm` explicitly carries `min-h-[44px]`. Inconsistent — md/lg should also enforce min height to meet the project's 44px policy:
  ```tsx
  sm: "… min-h-[44px]",
  md: "… min-h-[44px]",
  lg: "… min-h-[48px]",
  ```

- `src/components/report/MatchupSheet.tsx:84-104` — Drag-and-drop reordering of matchup plans has **no keyboard alternative**. Only mouse/touch dragging is supported. WCAG **2.1.1 Keyboard**. The slide-reorder up/down buttons exist for Pokemon slides in `page.tsx` (`handleMoveSlideUp/Down`) but the same flow on `MatchupSheet` rows is drag-only. Add visible Move-up / Move-down buttons per row that call `onReorderPlans(index, index ± 1)`.

- `src/components/ui/ShareModal.tsx:395-409` and `:651-664` — URL-display and embed-code blocks are `<div role="button" tabIndex={0}>` with `onClick` + `onKeyDown` (Enter/Space). The pattern is valid, but the visible focus ring relies on the global `:focus-visible` rule against a colored surface — verify contrast in dark mode where `bg-surface-alt` (`#1C1C38`) and the 2 px accent ring (`#FB7185`) should pass but the offset-2 outline may sit on `bg-surface` edges. Low risk; if tightening, add an explicit `focus-visible:ring-2 focus-visible:ring-accent` class.

## P2 (best-practice improvements)

- `src/app/page.tsx` (home, the report viewer) — No `<h1>` is rendered when an analysis loads. The PasteInput landing has one (`PasteInput.tsx:283`), but the report itself only uses `<h2>` (`TeamReport`/`MatchupSheet`/`SpeedTierChart`) on non-overview slides. `TeamOverview.tsx:398` has an `<h1>` only on slide 0. When the user is on any other slide there is no `<h1>` on the page. WCAG **1.3.1** best practice. Add a visually-hidden persistent `<h1 className="sr-only">{tournamentName || teamName || "VGC Team Report"}</h1>` to the main report container in `page.tsx`.

- `src/components/ui/Toggle.tsx:9` — Wrapper `<div>` is `min-h-[36px]`. The button switch itself is `h-[24px] w-[42px]`. Below the 44px touch standard. AA passes via the 24×24 rule but consider bumping the wrapper to `min-h-[44px]` with extra padding so the whole row is tappable.

- `src/components/ui/InstallPrompt.tsx:134-137` — App-icon SVG inside the sheet uses hard-coded fills (`#E11D48`, `#BE123C`, `white`). These are decorative; mark the SVG `aria-hidden="true"` for consistency (it isn't currently). Minor.

- `src/components/social/CommentSection.tsx:236-243` — "Post Comment" submit is `px-4 py-2 text-xs` (~28px). Bump to `min-h-[44px]`.

- `src/components/social/CommentSection.tsx:320-326` — "Load more comments" link-button is text-xs with no min height. Bump.

- `src/components/explore/ExploreEmpty.tsx:33-40` — Substitute sprite uses `alt=""` decoratively. That's correct, but the image is meaningful empty-state imagery — consider `alt="No reports found"` or wrap in a labelled container. Low priority.

- `src/components/social/CollaboratorPanel.tsx:246-250` and similar avatar `<img alt="">` in dashboard/profile pages — decorative `alt=""` is technically fine because the adjacent name span is the accessible label, but pair the avatar+name in a single labelled element for screen readers. Minor.

- `src/components/ui/InstallPrompt.tsx:115-119` — Scrim div has `aria-hidden="true"` and an `onClick` — keyboard users can't dismiss via the scrim. Fine since the bottom sheet has its own dismiss buttons, but only once a focus trap + Escape are added (P0 above).

- Drag-and-drop reordering generally: `src/components/report/MatchupSheet.tsx`, `src/components/report/MatchupPlanSlide.tsx` (game-plan `bring` reorder) also rely on `draggable={true}` HTML5 DnD with no keyboard equivalent. Same WCAG 2.1.1 concern; add up/down arrow buttons.

- `src/components/ui/Button.tsx:13` — Base class uses `focus:outline-none focus-visible:ring-2 focus-visible:ring-accent/50`. The global `:focus-visible` rule (globals.css:822) adds an outline; this is double-styled but harmless. Optional cleanup.

## Focus-trap / modal a11y summary

Three modal-shaped surfaces are missing complete WCAG modal semantics:
1. **InstallPrompt** — no role, no aria-modal, no focus trap, no Escape (P0).
2. **InlinePokemonEditor** — has `role="dialog"` + Escape + initial focus, missing `aria-modal` and Tab cycling (P0).
3. **CollaboratorPanel** — inline disclosure not a modal so it's fine, but the user-search input lacks a label (P0).

ShareModal, OTSSheetModal, WhatsNewModal, NotificationBell popover, VersionHistoryPanel, WalkthroughOverlay all already follow the focus-trap + Escape + aria pattern correctly. The Navbar overflow dropdown was already fixed in v5.20 (aria-expanded/haspopup, role=menu) per the changelog.
