# WCAG 2.1 AA Accessibility Audit Report
**VGC Team Report Next.js App**  
**Date:** May 21, 2026

## Executive Summary

Overall, the application has strong accessibility foundations with proper use of aria labels, focus management, and modal implementations. However, **three high-impact fixes** are recommended:

1. **Unlabeled sort/filter inputs in Dashboard** (affects user interaction)
2. **Mark all read button missing aria-label** in NotificationBell (affects screen reader users)
3. **Visibility picker lacks aria-labelledby** in ShareModal (ambiguous for radio groups)

These fixes improve WCAG 2.1 Level AA compliance for form controls and interactive elements.

## Top 10 Accessibility Fixes

### 1. **Unlabeled Collection Input Fields** (HIGH PRIORITY)
- **File:** `/home/user/VGC-Team-Report/src/app/dashboard/DashboardContent.tsx`
- **Lines:** 1088, 1095, 1102
- **Issue:** Three form inputs in "New Collection" section lack associated labels or aria-label attributes
- **WCAG Criterion:** 1.3.1 Info and Relationships (Level A)
- **User Impact:** Screen reader users cannot identify the purpose of collection name, description, and regulation inputs
- **Proposed Fix:**
```tsx
<label htmlFor="collection-name" className="sr-only">Collection name</label>
<input
  id="collection-name"
  aria-label="Collection name"
  type="text"
  value={newName}
  onChange={(e) => setNewName(e.target.value)}
  placeholder="Collection name"
  className="..."
/>
```

### 2. **Mark All Read Button Missing aria-label**
- **File:** `/home/user/VGC-Team-Report/src/components/ui/NotificationBell.tsx`
- **Line:** 93-99
- **Issue:** "Mark all read" button contains only text but lacks visible context for screen reader edge case when parent heading focus is lost
- **WCAG Criterion:** 2.5.3 Label in Name (Level A)
- **User Impact:** Voice control and voice input users may struggle to activate the button; screen readers may not announce context clearly
- **Proposed Fix:**
```tsx
<button
  type="button"
  onClick={() => { markAllRead(); }}
  aria-label="Mark all notifications as read"
  className="text-[10px] font-bold text-accent hover:underline cursor-pointer"
>
  Mark all read
</button>
```

### 3. **Visibility Picker Radio Group Missing Group Label**
- **File:** `/home/user/VGC-Team-Report/src/components/ui/ShareModal.tsx`
- **Line:** 651
- **Issue:** Radio button group for "Private | Unlisted | Public" has `role="radiogroup"` but lacks `aria-labelledby` or `aria-label` to associate the group with its label
- **WCAG Criterion:** 1.3.1 Info and Relationships (Level A)
- **User Impact:** Screen readers don't announce the purpose of the radio group; users don't understand they're choosing visibility levels
- **Proposed Fix:**
```tsx
<div className="grid grid-cols-3 gap-2" role="radiogroup" aria-labelledby="visibility-label">
<p id="visibility-label" className="text-xs font-bold text-text-tertiary uppercase tracking-widest mb-3">
  {t.shareModalVisibilityLabel}
</p>
```

### 6. **Theme Button Selector Missing aria-label on Active Button**
- **File:** `/home/user/VGC-Team-Report/src/components/layout/Navbar.tsx`
- **Line:** 593
- **Issue:** While aria-label is present, it relies on theme.label which may be cryptic (e.g., "Gen 9 Scarlet/Violet") without describing it's a toggle. Should clarify "selected" status

### 7. **Description Input in Feedback Form Missing htmlFor Association**
- **File:** `/home/user/VGC-Team-Report/src/app/feedback/FeedbackContent.tsx`
- **Lines:** 250-255
- **Issue:** Label for description textarea uses `htmlFor="feedback-description"` but textarea has matching `id` — this is correct, but aria-describedby could clarify character counter
- **WCAG Criterion:** 1.3.1 Info and Relationships (Level A)
- **User Impact:** Screen reader users may not know about the 2000-character limit until they reach it

### 8. **Embed Code Display Area Missing Copy Button aria-label Specificity**
- **File:** `/home/user/VGC-Team-Report/src/components/ui/ShareModal.tsx`
- **Line:** 575
- **Issue:** Copy button for embed code has `aria-label="Copy embed code"` but the div itself also has role="button" — creates redundant announcements for screen readers
- **WCAG Criterion:** 2.5.3 Label in Name (Level A)
- **User Impact:** Screen readers announce "button, Copy embed code, button" creating confusion
- **Proposed Fix:**
```tsx
<div
  onClick={handleCopyEmbed}
  role="button"
  tabIndex={0}
  aria-label="Copy embed code snippet"
  aria-describedby="embed-help"
  onKeyDown={(e) => { if (e.key === "Enter" || e.key === " ") { e.preventDefault(); handleCopyEmbed(); } }}
>
```

### 10. **Version Editor Badge Missing Accessible Text Alternative**
- **File:** `/home/user/VGC-Team-Report/src/components/ui/DiffNavigator.tsx`
- **Line:** 101-102
- **Issue:** Hidden on mobile; when visible, plain text "v{version} by {editorName}" lacks semantic structure for screen readers

- **User Impact:** Voice control users may struggle to parse the version info; semantic structure is ambiguous

```tsx
</span>
```

## Detailed Findings

- **NotificationBell** (line 52-59): Outside click handler correctly implemented

- **WhatsNewModal**: Complete focus trap + Escape handler + `role="dialog"`

### Form Accessibility Issues ⚠
- **DashboardContent.tsx**: 3 unlabeled inputs in collection creation (lines 1088, 1095, 1102)
- **DashboardContent.tsx**: Sort select missing aria-label (line 198)
- **Feedback forms**: All have proper labels with `htmlFor` attributes ✓

### Button & Icon Accessibility ✓
- **EditFab**: aria-label correctly describes mode toggle (line 24)
- **NotificationBell**: aria-label includes unread count (line 71)
- **DiffNavigator**: All icon buttons have aria-labels (lines 69, 90, 109)
- **Navbar**: Theme selector buttons have aria-labels (line 593)

### Color Contrast
- No hardcoded text-gray-{400,500} patterns found
- text-text-tertiary used extensively (custom CSS variable—needs verification in design tokens)
- Recommend spot-check of text-text-tertiary on white backgrounds: likely ~4.5:1 ratio (acceptable for AA)

### Keyboard Navigation ✓
- Tab order appears correct across major routes
- Modal focus traps properly implemented
- No keyboard-only interactions without proper ARIA roles
