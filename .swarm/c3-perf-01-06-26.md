## 7. Top 5 highest-leverage perf wins

| # | File | Change | Expected impact | conflict_risk |
|---|---|---|---|---|
| **1** | `sentry.client.config.ts` | Drop `replaysOnErrorSampleRate: 1.0` (or remove `replayIntegration`). Replays cost ~97 KB raw / ~50 KB gzip for every visitor before any error happens. | **~97 KB off initial JS** (Sentry Replay chunk eliminated from the rootMainFiles graph). Faster TTI on every route. | **LOW** (file not in changed-list) |
| **2** | `src/components/providers/ClarityProvider.tsx` | Convert `import Clarity from "@microsoft/clarity"` to a dynamic `await import("@microsoft/clarity")` gated on `hasAnalyticsConsent()` (mirroring PostHogProvider). | **~30–60 KB off initial JS**; defer until consent granted. | **LOW** |
| **3** | `src/lib/data/dex-subset.json` (or its `dex-subset.ts` wrapper) | The 340 KB JSON chunk is duplicated (2× 340 KB = 680 KB shipped) because it's imported both server-side and client-side. Move client consumers to `await import()` so it lands in a single async chunk loaded on demand; mark the server-only import with `import "server-only"`. | **~340 KB removed** from initial graph for routes that touch it (currently `/`, `/s/[id]`, `/explore`, `/dashboard`, `/champions/[pokemon]`). One of the biggest single wins. | **LOW** (file not changed) |
| **4** | `src/app/page.tsx` (imports of `Navbar` + `PasteInput`) — and `src/components/layout/Navbar.tsx` itself | Two sub-fixes: (a) `Navbar` (890 LOC) is statically imported in both `layout.tsx` and `page.tsx` — pick one (layout is enough) and lazy-mount any heavy menu/search panels with `dynamic({ ssr:true })`. (b) `PasteInput` (670 LOC, also pulls `motion`) is shown only when no team is loaded — wrap it in `dynamic(() => import(...), { ssr: false })`. | **~30–60 KB off `/` initial JS**, less work on hydrate; cuts motion import from `/` cold path. | **HIGH** (both files in changed-list — coordinate with other swarms) |
| **5** | `src/components/ui/ShareModal.tsx` + `src/lib/utils/export-report.ts` | The 485 KB async chunk merges 8 distinct modals because they're all `dynamic()` siblings in `page.tsx`. Add `webpackChunkName`/distinct module paths (or use `import(/* webpackChunkName: "share-modal" */ ...)` style) so ShareModal, CommentSection, OTSSheetModal, etc. each get their own chunk. Also split jspdf out of the 418 KB chunk (currently merged with html2canvas) by giving each its own dynamic import with a unique magic-comment chunk name. | Doesn't change *total* JS but **drops 300–400 KB from the first modal open** (user only pays for the modal they actually opened); export click no longer downloads 418 KB when only html2canvas is needed. | **HIGH** (both files in changed-list) |

### Honorable mentions

- **Remove `qrcode` from `package.json`** if confirmed unused (no `import` found in `src`). Verify against runtime — may be used via a dynamic string or by a transitive lib. ~50 KB install size.
- **Lazy-load `vanilla-cookieconsent`** after first paint instead of importing it eagerly in `CookieBanner.tsx`. ~30 KB raw deferred from initial bundle.
- **Reduce `motion` static importers** (12 files) — several (ChangelogContent, FeedbackContent, ExploreEmpty) use only fade/slide; CSS transitions or `motion/react-mini` could let tree-shaking eliminate motion-dom from those routes (~118 KB on routes that don't need full motion).
- **Polyfills (113 KB + 158 KB core-js)** — Next.js 16 defaults assume modern browsers; check `browserslist` to confirm we're not over-polyfilling.

## Notes / limitations

- Next.js 16 Turbopack build does not emit per-route First Load JS; sizes above are raw (not gzipped) and inferred from chunk fingerprinting. Real-user impact after gzip is roughly 30–35% of raw.
- depcheck reports no unused regular deps; verify `qrcode` manually before deleting.
- DB-related stderr during `generateStaticParams` is environment (missing `DATABASE_URL`), not a bundling problem.
