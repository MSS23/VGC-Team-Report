## 0. Methodology note (read before trusting the numbers)

**Next 16 + Turbopack no longer prints a First Load JS column.** The route table it emits has only
`Route (app) | Revalidate | Expire` — no sizes at all (build log lines 922–1020). So the sizes below are
**computed**, two independent ways that agree to the byte:

1. **From the prerendered HTML** — every `/_next/static/chunks/*.js` referenced by each
   `.next/server/app/**/*.html`, deduped, summed (raw + gzip).
2. **From the RSC manifests** — `.next/server/app/**/page_client-reference-manifest.js`
   (`clientModules[*].chunks`) unioned with `build-manifest.json`'s `rootMainFiles` + `polyfillFiles`.
   This also covers the dynamic (`ƒ`) routes that have no prerendered HTML — `/s/[id]`, `/embed/[id]`,
   `/q/[id]`, `/creator/[name]`.

Both methods produce identical numbers for the 18 static routes, so I trust the dynamic-route figures too.

**Polyfill caveat:** `static/chunks/0cz1d0mv5g_q7.js` (110.0 KB raw / 38.7 KB gz) is emitted with
`<script ... noModule="">`, so **modern browsers never download it**. It is included in the "First Load JS"
columns (Next's historical convention counts the shared runtime set) and subtracted in the
"Modern browser" column. **The modern-browser column is the one that matters for real users.**

## 2. Why each heavy route is heavy

Chunk→content attribution was done empirically: grep each of the 111 emitted chunks for payload
fingerprints (`nonstandardValues` for `dex-subset.json`, `Iron Bundle` for `pokemon.ts`,
`Kangaskhanite`+`Drought`+`mega-kangaskhan` for `mega-pokemon.ts`, `Zippy Zap` for the move tables,
`getFinalDamage` for `@smogon/calc`, `jsPDF`, `html2canvas`, `QRCode`, `motion-dom`, `cookieconsent`,
`__PosthogExtensions__`), then map each hit chunk back to the routes whose manifest references it.

### 3.1 `motion` — 114.6 KB raw / 37.5 KB gz on 7 routes, used for opacity+translate fades

`conflict_risk: true` on all 10 files.

First-load on `/dashboard`, `/dashboard/profile`, `/explore`, `/creator/[name]`,
`/champions/[pokemon]` (×80 SSG pages), `/feedback`, `/changelog`.

Importers and animation call-site counts:

| File | Call sites |
|---|---|
| `src/app/feedback/FeedbackContent.tsx` | 14 |
| `src/app/changelog/ChangelogContent.tsx` | 8 |
| `src/app/dashboard/profile/page.tsx` | 5 |
| `src/components/explore/ExploreFilters.tsx` | 5 |
| `src/components/ui/WhatsNewModal.tsx` | 5 |
| `src/app/champions/[pokemon]/MegaLandingContent.tsx` | 3 |
| `src/components/explore/ExploreContent.tsx` | 2 |
| `src/components/explore/ExploreEmpty.tsx` | 2 |
| `src/components/explore/ReportCard.tsx` | 2 |
| `src/components/social/CreatorProfile.tsx` | 2 |

What the 48 call sites actually animate (`grep` over all `initial`/`animate`/`whileInView`/`exit`/`transition` props):

```
10× animate={{ opacity: 1, y: 0 }}
 6× initial={{ opacity: 0, y: 12 }}
 3× initial={{ opacity: 0 }}   3× animate={{ opacity: 1 }}
 2× initial={{ opacity: 0, y: 16 }}
 1× initial={{ width: 0 }}   1× initial={{ scale: 0, rotate: -180 }}
 2× transition={{ type: "spring", ... }}     ← only two non-tween animations in the whole app
```

`experimental.optimizePackageImports: ["motion/react"]` is already on (`next.config.ts:19`) and it still
costs 37.5 KB gz, because tree-shaking cannot remove the `motion-dom` animation engine once `motion.div`
is referenced.

**(a) `next/dynamic`** does not help here — these are the page's own above-the-fold wrappers.
**(c) move behind a user action** is wrong for mount-time fades.
**The fix is (d): replace with CSS.** 46 of 48 call sites are pure opacity/transform tweens that CSS
keyframes + `prefers-reduced-motion` already cover (and the UI standards in `CLAUDE.md` mandate
"150–300ms transform/opacity animations, reduced-motion respected" — exactly CSS's wheelhouse).
Keep `motion` only for `WhatsNewModal` (`AnimatePresence` exit) and the two springs, loaded via
`next/dynamic` behind the modal open.

Intermediate option if a full CSS migration is too much: wrap in `LazyMotion` + `domAnimation` from
`motion/react` and swap `motion.div` → `m.div`. That keeps the API and drops the sync cost to the
~6 KB gz core, with the feature bundle loaded async.

- **Saved:** 37.5 KB gz / 114.6 KB raw off 7 routes (≈ 263 KB gz of aggregate transfer across them); ~12 % off `/dashboard`, `/explore`, `/feedback`, `/changelog`, and all 80 `/champions/*` SSG pages.
- **Files:** the 10 above + `next.config.ts` (drop the now-dead `optimizePackageImports` entry) + `package.json` (remove `motion`, if fully migrated).
- **Risk: medium.** 10 files, all on the main-changed list → merge conflicts likely. Visual regression risk on every animated surface. Needs `ui-checklist-reviewer` (reduced-motion, 150–300 ms) per `CLAUDE.md`. The `LazyMotion` variant is lower risk (≈2 lines per file) for a smaller win.

### 3.2 `vanilla-cookieconsent` — 17.9 KB gz (shared chunk) on **all 22** content routes

`conflict_risk: true` (`src/components/providers/CookieBanner.tsx`, `src/app/layout.tsx`, `src/components/ui/DeferredLayoutExtras.tsx`)

```
src/components/providers/CookieBanner.tsx:4  import * as CookieConsent from "vanilla-cookieconsent";
src/components/providers/CookieBanner.tsx:5  import "vanilla-cookieconsent/dist/cookieconsent.css";
```

`CookieBanner` is mounted unconditionally in the root layout (`src/app/layout.tsx:8`), and its only
work is inside `useEffect` — it renders nothing synchronously. The package is 24 KB JS + 32 KB CSS on
disk; the emitted shared chunk `0wna-yxkew_3p.js` is 46.6 KB raw / 17.9 KB gz (cookieconsent + the

**Fix (a): `next/dynamic` with `ssr:false`, inside the component that already exists for this.**
`src/components/ui/DeferredLayoutExtras.tsx` is literally commented *"None of these render anything
above the fold — loading them after hydration keeps their code out of every route's initial bundle"* and
already does this for `InstallPrompt`, `ConnectivityStatus`, `ServiceWorkerRegistration`,
`ChunkErrorReloader`. `CookieBanner` belongs in that list; it was missed.

- **Saved:** up to 17.9 KB gz off every route (the chunk also holds the posthog-react shim, so realistically **~12–14 KB gz**; measure after). Off 22 routes.
- **Files:** `src/components/ui/DeferredLayoutExtras.tsx` (add the dynamic entry), `src/app/layout.tsx` (drop the direct `CookieBanner` import/mount).
- **Risk: low.** One behavioural caveat: the banner appears a beat later (post-hydration). That is legally fine — consent is still obtained before analytics, because `PostHogProvider` already gates on `notifyConsentChange` — but it is a GDPR-adjacent surface, so it deserves a deliberate sign-off rather than a drive-by. The `open-cookie-settings` CustomEvent from `PageFooter` keeps working (the listener just registers later); worth a Cypress assertion.
