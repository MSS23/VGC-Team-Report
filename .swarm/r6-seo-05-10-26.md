## 1. Current SEO surface — what's good, what's missing

### 1.1 `src/app/sitemap.ts`

**Good:** `revalidate = 3600` so new public reports/creators get discovered without a deploy; Mega pages are generated from `getRegMBMegasWithSprites()` so the widest live regulation is covered and sprite-less Megas (which would render broken) are excluded; public shares and creator pages carry real `lastModified` from `updated_at`; DB failure degrades gracefully to the static list; total URL count (~11 static + 72 Megas + ≤5000 shares + ≤5000 creators ≈ 10k) is well inside the 50k/50MB limit.

**Missing / wrong:**
- **No `lastModified` on any static page or on any of the 72 `/champions/[pokemon]` pages.** These are the SEO-critical SSG pages and they are the ones Google most needs a crawl-scheduling signal for. Shares and creators have `lastModified`; the high-value pages do not.
- `changeFrequency` is set everywhere but is effectively ignored by Google (and has been for years). Harmless, not worth churn — but it is not doing the work the values imply (`/explore` "daily", Megas "weekly").
- `priority` is self-reported and ignored by Google. Also internally inconsistent: `/faq` and each individual Mega page both sit at 0.8, equal to the `/tools/ev-to-sp` money page.
- No `/tools` index URL — because `src/app/tools/` contains only `ev-to-sp`, so `/tools` is a 404. URL-trimming crawlers and users both hit a dead segment.

### 1.2 `public/robots.txt`

Correct and minimal (see §0). No `src/app/robots.ts` — the static file wins, which is fine. Sitemap is declared. No `Host`/`Crawl-delay` cruft.

### 1.3 Root `src/app/layout.tsx` metadata

**Good:** `metadataBase` is present (`new URL("https://pokemonvgcteamreport.com")`) so every relative `/opengraph-image` resolves absolutely; full OG + Twitter `summary_large_image` with two image candidates; `title.template = "%s | VGC Team Report"`; icons/manifest/appleWebApp complete; `alternates.canonical` set; `robots: { index: true, follow: true }`; `<html lang="en">`.

**Missing / risky:**
- **`alternates.canonical` on the root layout is inherited by every descendant route that does not set its own.** Verified every indexable route *does* override it (`/explore`, `/champions`, `/champions/[pokemon]`, `/faq`, `/tools/ev-to-sp`, `/tournaments`, `/changelog`, `/support`, `/privacy`, `/terms`, `/feedback`, `/s/[id]`, `/creator/[name]`). The only route without its own canonical is `/compare`, which is `noindex` — so impact today is nil. **But this is a loaded gun**: the next route added without `alternates.canonical` silently declares the homepage as its canonical and de-indexes itself. Worth a guard.
- **Three site-wide JSON-LD entities are emitted on every single URL** (`OrganizationJsonLd`, `WebSiteSchema`, and an inline `["WebApplication","SoftwareApplication"]` node). That means all 72 Mega pages and every `/s/[id]` share page each claim to *be* the software application / the website / the organization. Google's guidance is homepage-only for `WebSite` and `Organization`, and `SoftwareApplication` should sit on the page that describes the app. Diluted entity signals and a lot of duplicate nodes across ~10k URLs.
- No `hreflang` / `alternates.languages`. See §1.9.

### 1.4 `src/app/champions/[pokemon]/` — the SSG Mega guide pages (SEO-critical)

**Good — genuinely strong engineering here:**
- `generateStaticParams()` tracks the widest live regulation with a load-bearing comment about the VGC-258 regression, plus a regression test at `src/app/champions/[pokemon]/__tests__/generate-static-params.test.ts`.
- `regulationCopy()` **derives** legality from `getMegaRegulation(dataKey)` instead of asserting it, so M-B-only Megas never publish a false "legal in M-A" claim in prerendered HTML. This is the right instinct and rare.
- Per-page canonical, per-page OG/Twitter with a per-Mega `opengraph-image` route and descriptive `alt`.
- Internal linking fixed: the related-Megas window rotates by `selfIndex` instead of a fixed `.slice(0, 8)`, so link equity spreads across all 72 pages rather than piling onto 8.
- FAQ JSON-LD answers are all grounded in first-party data (stats, ability, stone, live team count) with an explicit comment refusing to hallucinate "best spread" claims — correct call, that would be structured-data spam.
- `alt={species}` present on the hero sprite.

**Missing / wrong:**
- **Titles are truncated in SERPs.** The in-file comment says "Keeping it under ~60 chars", but it forgot the root `title.template` suffix. Rendered: `Mega Charizard Y VGC Guide — SP Spreads, Movesets & Teams | VGC Team Report` = **75 chars**; `Mega Gardevoir …` = 73. Google truncates at ~580px / ~60 chars, so every one of the 72 pages loses its tail — including the `Teams` keyword. (By contrast `/tools/ev-to-sp` explicitly budgeted for the template. The Mega pages are the outlier.)
- **`FAQPage` JSON-LD with zero matching visible content.** The code comment at `MegaLandingContent.tsx` documents deliberately removing the visible FAQ while keeping the JSON-LD "for AI scrapers". Google's structured-data policy requires FAQ content to be visible on the page; invisible-only `FAQPage` is a hidden-content violation and a structured-data manual-action risk across 72 URLs. Either re-render the FAQ (it's already computed server-side — nearly free) or drop the `FAQPage` node.
- **Thin, near-duplicate content at scale.** Unique prose per page ≈ one `mega.description` sentence + ability + stone + "Legal in" line. Everything else is a stat bar component, a team grid that is frequently empty ("No public team reports featuring X yet"), and a boilerplate CTA. 72 near-identical templated pages with ~80 words of unique copy is the classic doorway/thin-content profile — and it is precisely where Pikalytics beats them (see §2).
- JSON-LD `@type` is a generic `WebPage`. The page is a species/stat reference; `Dataset` for the base-stat table or an `ItemList` of competitive teams would be a better type match and is derivable from data already in hand.
- `alt={species}` is only the raw species string (e.g. `Charizard-Mega-Y`) — no type/role context for image search.

### 1.5 JSON-LD / structured data coverage (`src/components/seo/JsonLd.tsx`)

**Good:** The `JsonLd` primitive escapes `<` → `<` to stop `</script>` injection from user-controlled `creatorName` — correctly reasoned and commented. Helper coverage is broad: `WebSite` + `SearchAction`, `Organization`, `HowTo`, `SportsEvent` (single node *or* `@graph` array, with `organizer`/`eventStatus`), `BreadcrumbList`, `FAQPage`, `ItemList`, `CollectionPage`, `ProfilePage`, `WebApplication`.

**Missing / wrong:**
- **`BreadcrumbJsonLd` and `BreadcrumbListJsonLd` are byte-identical duplicate implementations.** Both exist, both exported, both used (`/creator/[name]` uses the first; `/champions`, `/faq`, `/tools/ev-to-sp`, `/tournaments` use the second). Dead-weight duplication, guaranteed to drift.
- **Homepage emits `FAQPage` and `HowTo` with no visible counterpart.** `src/app/page.tsx:92-93` calls `<FAQPageJsonLd />` with no `items`, so it falls back to `DEFAULT_FAQ_ITEMS` — five Q&As that appear nowhere on the homepage. Same for `HOW_TO_STEPS`. Both are hidden-content violations, same class as the Mega pages.
- **Duplicate competing entities across two URLs.** `/` and `/faq` both emit a `FAQPage`, with overlapping questions in different wording. And `HowToSchema` **hardcodes** `name: "How to Create a VGC Team Report"`, so `/` and `/faq` ship two `HowTo` entities with the identical name at different URLs — they cannibalise each other.
- No `Article`/`BlogPosting` anywhere (no blog exists — VGC-227).
- No `Dataset` anywhere, despite the site owning exactly the kind of structured reference data (base stats, speed tiers, SP budgets, legality) that `Dataset` is for.
- No `BreadcrumbList` on `/explore` as a standalone node — it is nested inside `CollectionPage.breadcrumb`, which is valid but weaker than a top-level node for SERP breadcrumb display.
- No `BreadcrumbList` at all on `/s/[id]` (the single largest URL class on the site, ~5000 pages).

### 1.9 The format-rotation problem (biggest single finding)

**The live Pokémon Champions regulation is Reg M-C** — announced to run **9 Sep → 2 Dec 2026** (Serebii, Victory Road, game8, Vice all concur; Season M-6 of M-C ends 7 Oct 2026). Today is 5 Oct 2026.

The repo has **zero** M-C support. Verified by grep: the only occurrence of "M-C" anywhere in `src/` or `public/` is a comment in `src/app/champions/[pokemon]/__tests__/generate-static-params.test.ts:25` *predicting this exact failure* ("so the next rotation (M-C) can't silently repeat it"). It repeated anyway:

- `src/lib/data/tags.ts:9` — `REGULATIONS` stops at `"Reg M-B"`; `isChampionsFormat()` returns false for M-C.
- `src/lib/data/mega-pokemon.ts` — no `CHAMPIONS_REG_MC_*` set; `getRegMBMegasWithSprites()` is the widest getter, so `generateStaticParams()` and the sitemap both cap at the M-B Mega pool. M-C reportedly adds 24 new Pokémon/Megas → **~24 Mega landing pages that will never be prerendered, sitemapped or internally linked.**
- `src/lib/data/champions-dex.ts` — `CHAMPIONS_MB_DEX` is the widest dex; no M-C dex.
- `src/lib/validation/champions-legality.ts:143-145` — `const isMb = regulation === "Reg M-B"` binary; M-C teams validate against the wrong dex.
- Metadata/copy pinned to M-A/M-B on `/champions` ("Reg M-B & M-A Mega Teams"), all 72 Mega pages ("Regulation M-A and M-B"), `/tools/ev-to-sp` (M-A only), `public/llms.txt` (M-A only).

Meanwhile **Pikalytics already titles its Champions pages "… VGC 2026 Champions Reg M-C: Best Moves, Builds & Teams"** (e.g. `pikalytics.com/pokedex/championstournaments/Gardevoir-Mega`). Every "Reg M-C" / "Champions M-C" query is currently unwinnable here. This is not a keyword gap to be filled by a new page — it is the existing page cluster going stale on a ~12-week clock.

**Related content-accuracy flag (not strictly SEO, worth a ticket):** multiple sources state Reg M-B/M-C have **no restricted Pokémon**, while `src/lib/validation/champions-legality.ts:49` maintains a `RESTRICTED_BASE_NAMES` set enforcing a max-2 rule, and `CLAUDE.md` documents "restricted (max 2)". If the format genuinely has no restricteds, the validator is emitting false errors and the Mega pages' legality prose is wrong. Needs a human to confirm against the official ruleset before anyone changes code.

### 1.10 Internationalisation

`src/lib/i18n/` ships **7 locales** (en, es, fr, it, ja, ko, zh) as client-side runtime translations on a single URL set. There is no `alternates.languages`, no `hreflang`, no localised routing, and `<html lang="en">` is hardcoded regardless of the selected locale.

So: the translation *content* already exists and is paid for, but captures **zero** international search traffic — and the hardcoded `lang="en"` on translated content is also an a11y/SEO mismatch. Pikalytics by contrast serves `?l=fra`, `?l=ger`, `?l=ita` variants of the exact Mega pages this site competes on. This is the single largest piece of latent, already-funded SEO value in the repo. It is a real project (routing + metadata + hreflang matrix), not a tonight job.

## 4. Implementable tonight — ranked

Every item below was verified against the actual file. Risk is about blast radius, not difficulty.

### 1. Shorten the 72 Mega page titles so they survive SERP truncation
- **File:** `src/app/champions/[pokemon]/page.tsx`, the `title` in `generateMetadata` (~line 63).
- **Change:** `const title = \`${mega.displayName} VGC Guide — SP Spreads, Movesets & Teams\`;` renders at 73–75 chars once `"%s | VGC Team Report"` is applied. Either drop the suffix with `title: { absolute: title }`, or shorten the base to e.g. `` `${mega.displayName} VGC: SP Spreads & Movesets` `` (→ 58–62 chars with the suffix). Fix the stale "under ~60 chars" comment at the same time.
- **Risk: LOW.** Metadata-only, 72 pages, no runtime behaviour. Highest impact-per-line change available.

### 2. Resolve the three hidden-content structured-data violations
- **Files:** `src/app/page.tsx:92-93` (`<FAQPageJsonLd />` with no visible FAQ, `<HowToSchema steps={HOW_TO_STEPS} />` with no visible steps); `src/app/champions/[pokemon]/page.tsx` (`FAQPage` node) ↔ `src/app/champions/[pokemon]/MegaLandingContent.tsx` (visible FAQ removed, per the comment).
- **Change:** pick one per surface — either render the content visibly or remove the node. Recommended: **drop** both JSON-LD nodes from the homepage (`/faq` already carries a correct, visible-content `FAQPage` + `HowTo`, so nothing is lost and the duplicate-entity cannibalisation in #3 goes away too); **re-render** the visible FAQ on the Mega pages, where `faqItems` is already computed server-side and would add the unique on-page copy those thin pages badly need (§1.4).
- **Risk: LOW–MEDIUM.** Removal is low. Re-adding visible FAQ to the Mega pages touches a `.tsx` → run `ui-checklist-reviewer` per CLAUDE.md.

### 3. De-duplicate the two `HowTo` entities and the two breadcrumb helpers
- **File:** `src/components/seo/JsonLd.tsx`.
- **Change:** (a) `HowToSchema` hardcodes `name: "How to Create a VGC Team Report"`, so `/` and `/faq` publish two identically-named `HowTo`s at different URLs — make `name` a prop (mostly moot if #2 removes the homepage one). (b) `BreadcrumbJsonLd` and `BreadcrumbListJsonLd` are byte-identical; keep `BreadcrumbListJsonLd` (4 call sites) and repoint `src/app/creator/[name]/page.tsx` (1 call site), or re-export one as an alias.
