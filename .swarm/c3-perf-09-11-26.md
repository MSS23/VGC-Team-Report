## 2. Methodology (read before trusting the numbers)

**Next 16 + Turbopack prints no First Load JS table.** The emitted route table has only
`Route (app) | Revalidate | Expire` (build log lines 931–1020). There is also **no
`app-build-manifest.json`** in this build. So every size below is computed, two independent ways that
agree **to the byte**:

1. **From the prerendered HTML** — every `/_next/static/**.js` and `.css` referenced by each of the 98
   `.next/server/app/**/*.html` files, deduped, summed.
2. **From the RSC manifests** — `.next/server/app/**/page_client-reference-manifest.js`, unioned with
   `build-manifest.json`'s `rootMainFiles` + `polyfillFiles`. This also covers the dynamic (`ƒ`) routes
   that have no prerendered HTML (`/s/[id]`, `/embed/[id]`, `/q/[id]`, `/creator/[name]`).

The cross-check emitted **zero mismatches** for all static routes, so the dynamic-route figures are
trustworthy too.

Gzip is `gzip -9` / `zlib.gzipSync({level:9})` — they agree to ±0.1 KB; rounding differences of 0.1 KB
between tables are that.

**Polyfill caveat.** `static/chunks/0cz1d0mv5g_q7.js` (110.0 KB raw / 38.6 KB gz) is emitted with
`<script noModule>`, so **modern browsers never download it**. It is counted in the "First Load JS"
columns (Next's historical convention) and subtracted in the "modern" column. **The modern column is
the one that matters for real users.**

**Chunk→module attribution** is empirical: grep each of the 113 emitted chunks for payload
fingerprints (`nonstandardValues` for `dex-subset.json`; `Iron Bundle`/`Great Tusk`/`Protosynthesis`
for `pokemon.ts`; `mega-kangaskhan`/`dataKey` for `mega-pokemon.ts`; `Zippy Zap` for the move tables;
`getFinalDamage` for `@smogon/calc`; `_zod`/`ZodError`; `willChange` for `motion-dom`; `cc--`/`cc-main`/
`autoShow` for `vanilla-cookieconsent`; `clerk`; `parse5|domhandler|htmlparser2` for `cheerio`), then
map each hit chunk back to the routes whose manifest references it. Static import graphs were built
separately with a resolver that **skips `import type`** (type-only edges are erased at build time and
are the single biggest source of false positives here).

`3p4w3qh3m08ty.js` is `dex-subset.json` beyond doubt — the minified chunk still carries its own
generator metadata: `"schemaVersion":2`, `"nonstandardValues":[null,"Past","LGPE","Future","Custom","CAP"]`,
and the guard string ``dex-subset.json is schemaVersion ${a.schemaVersion}``. It is the **only** chunk in
the whole build containing `nonstandardValues`, and it is first-load on `/compare` and nowhere else.

### Why it is eager — and why the last report's line numbers no longer match

The 2026-10-26 report named `CompareContent.tsx:6` (`lookupPokemon` from `@/lib/data/pokemon`) and
`:21` (`mega-detect`). **Those imports are gone from the file.** Grepping for them today returns
nothing, and it would be easy to conclude the leak is fixed. **It is not.** The chain is now one hop
longer, through a 70-line utility:

```
app/compare/page.tsx (server)
  └─ components/compare/CompareContent.tsx        ← "use client"
       └─ lib/utils/effective-form.ts             ← resolveEffectiveForm, VGC-293
            ├─ lib/data/pokemon.ts                                      [239 KB src]
            │    └─ lib/data/pkmn-dex-fallback.ts
            │         └─ lib/data/dex-subset.ts
            │              └─ lib/data/dex-subset.json                  [127 KB src]
            └─ lib/utils/mega-detect.ts
                 └─ lib/data/mega-pokemon.ts                            [36 KB src]
```

`src/lib/utils/effective-form.ts` lines 1–2 are **module-scope value imports**:

```ts
import { lookupPokemon } from "@/lib/data/pokemon";
import { detectMegaFromItem, isMegaForm } from "@/lib/utils/mega-detect";
```

`CompareContent.tsx:19` then does `import { resolveEffectiveForm } from "@/lib/utils/effective-form"`.
That single line pulls 357 KB raw of static data into `/compare`'s critical path. This is exactly what
commit `b90cc48` on the unmerged branch means by "**actually** remove the dex data".

None of it is needed at first paint: `/compare` renders two empty paste boxes, and `resolveEffectiveForm`
cannot fire until a team has been pasted.

### The fix

In `src/components/compare/CompareContent.tsx`, replace the static `effective-form` import with
`await import("@/lib/utils/effective-form")` inside the paste handler (the handler becomes `async`, so
it needs a loading state so the first comparison does not render with empty stats). The identical
refactor already shipped on the homepage, so the pattern is proven.

**Then harden the guard, because the current one cannot catch this.**
`src/lib/__tests__/homepage-eager-imports.test.ts` is a **file-level** tripwire: it reads the 5 files in
`EAGER_HOMEPAGE_FILES` and string-matches their own import lines against `FORBIDDEN_STATIC_IMPORTS`.
Its own docstring concedes "It is a file-level tripwire, not a full graph analysis". Two gaps:

1. `components/compare/CompareContent.tsx` is not in `EAGER_HOMEPAGE_FILES` (rename it
   `EAGER_ENTRY_FILES` and add `app/compare/page.tsx` + `CompareContent.tsx`).
2. `@/lib/utils/effective-form` is not in `FORBIDDEN_STATIC_IMPORTS`, and **adding `CompareContent.tsx`
   to the list alone would still pass**, because the forbidden module is two hops away. The guard must
   either list `@/lib/utils/effective-form` explicitly or be upgraded to resolve transitively.

- **Saved:** **81.1 KB gz / 357.1 KB raw** off `/compare` — 337.1 → 256.0 KB gz, i.e. `/compare` drops
  from heaviest route on the site to within 6 KB of the `/faq` floor. 24 % of the route's gzip.
- **Files:** `src/components/compare/CompareContent.tsx`, `src/lib/__tests__/homepage-eager-imports.test.ts`.
- **Risk: low–medium.** One source file, no API or data change. Needs a Cypress pass on the compare
  flow for the new async boundary.

## 3.2 `/champions` ships `mega-pokemon.ts` to the client — **NEW (prior-report correction)**

The 2026-10-26 report stated that `/champions` reaches the data tables "only from **server**
components, so the data stays on the server — and the chunk evidence confirms no `dex-subset` chunk is
referenced by any of those routes' manifests." The `dex-subset` half is right. The `mega-pokemon` half
is wrong.

| Chunk | Raw | Gz | Payload | First-load on |
|---|---|---|---|---|
| `0q-0xfg6zjx4r.js` | 58.8 KB | 14.1 KB | `mega-pokemon.ts` + `ChampionsContent` + sample teams + Indy top cut | **`/champions` only** |

Evidence: the chunk contains `dataKey` ×88 and `mega-` ×102 against **85** `dataKey:` entries in
`src/lib/data/mega-pokemon.ts`, plus `Kangaskhanite` and `mega-kangaskhan` (the discriminating string
that the homepage's sample-paste false positives lack). The span between the first and last `dataKey`
is **51.8 KB of the 60.1 KB chunk and gzips to 12.5 KB of its 14.4 KB** — the Mega table *is* this chunk.

Cause — `src/app/champions/ChampionsContent.tsx` is `"use client"` and imports the table at module
scope (lines 14–23):

```ts
import {
  CHAMPIONS_REG_MB_ONLY_MEGAS, CHAMPIONS_REG_MC_ONLY_MEGAS,
  getRegMAMegas, getRegMCMegas, getMegaRegulation, hasMegaSprite,
  type ChampionsReg, type MegaPokemonEntry,
} from "@/lib/data/mega-pokemon";
```

Only the three functions are value imports; the two types are erased. They are used to build card
arrays (`getRegMCMegas().…`, `getRegMAMegas().map(toCard)`, `getMegaRegulation(m.dataKey)`), i.e. the
client imports 36 KB of source to compute a projection it renders once at mount.

### The fix

`src/app/champions/page.tsx` is **already a server component and already imports `getRegMCMegas`** (for
the `HUB_DESCRIPTION` metadata). Move the `toCard` projection up into it and pass the finished card
arrays to `ChampionsContent` as props. The client then needs no `mega-pokemon` import at all.

- **Saved:** 12.5 KB gz / 51.8 KB raw gross off `/champions`. The projected cards (~85 × name, dataKey,
  types, sprite flag, reg) land in the RSC flight payload instead — call it ~7 KB raw / ~2 KB gz — so
  **net ≈ 10 KB gz**, 262.9 → ~253 KB gz. Being explicit about the flight cost because the gross number
  overstates it.
- **Files:** `src/app/champions/page.tsx`, `src/app/champions/ChampionsContent.tsx`.
- **Risk: low.** Pure data-plumbing; no behaviour change. `/champions` is SEO-critical, so the rendered
  card markup must be byte-identical — worth a snapshot assertion.

## 6. `"use client"` components importing a large data module at module scope

The brief's item 4. Scanned every `"use client"` file in `src/`, resolving static import graphs with
`import type` edges excluded. **Two are on a first-load graph:**

| # | Client component | Eager module (module scope) | Route | Gz on first load | Defer by |
|---|---|---|---|---|---|
| 1 | `src/components/compare/CompareContent.tsx` :19 | `@/lib/utils/effective-form` → `pokemon.ts` + `dex-subset.json` + `mega-pokemon.ts` | `/compare` | **81.1 KB** | `await import()` in the paste handler (§3.1) |
| 2 | `src/app/champions/ChampionsContent.tsx` :14–23 | `@/lib/data/mega-pokemon` (direct) | `/champions` | **12.5 KB** | project to cards in the server `page.tsx` (§3.2) |

**Everything else that reaches a heavy data module is inside a `next/dynamic` subtree and is confirmed
lazy by chunk evidence** — `TeamReport`/`TeamOverview`/`PokemonCard`/`MatchupPlanSlide`/
`CommonModesSlide`/`DefensiveCoverageChart`/`InlinePokemonEditor`/`InlineDamageCalculator` all reach
`pokemon.ts`, `dex-subset.json`, `mega-pokemon.ts`, `moves.ts` and `move-names.ts`, but only through
chunks whose first-load count is 0. These are correct as written — **do not "fix" them.**

### The structural risk worth naming

`src/lib/utils/effective-form.ts` is a **70-line utility with two module-scope data imports**. It looks
cheap at the call site — `import { resolveEffectiveForm } from "@/lib/utils/effective-form"` is one
line — and it drags 357 KB raw / 81.1 KB gz behind it. Today only `CompareContent.tsx` imports it, so
the blast radius is one route. The same shape applies to `@/lib/utils/mega-detect`,
`@/lib/utils/effective-typing` and `@/lib/utils/speed-tier-form`.

The existing tripwire cannot catch any of this: it string-matches import lines in 5 named files against
a flat forbidden list, so a one-hop indirection through a small utility passes. **Either add the utility
wrappers to `FORBIDDEN_STATIC_IMPORTS`, or make the test resolve the graph transitively.** Without that,
this exact finding will recur — it already has once, which is why `b90cc48` is titled "*actually*
remove the dex data from `/compare`'s first load, **and harden the guard**".
