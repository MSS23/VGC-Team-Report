## Top 5 Wins (Recommended for Wave 2)

### 1. `/src/components/explore/ReportCard.tsx:319` — Like button tap target <44px
- **Issue**: Like/bookmark buttons use `min-h-[32px]` + `-mx-1` negative margins, reducing tap target to ~28px (below WCAG 44px minimum)
- **Risk**: Low (isolated to card reactions)
- **Patch**:
```tsx
// Line 319 (like button for signed-in users):
- className="inline-flex items-center gap-1 min-h-[32px] px-1 -mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"
+ className="inline-flex items-center gap-1 min-h-[44px] sm:min-h-[32px] px-2 sm:px-1 sm:-mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"

// Line 333 (like button for unsigned users — same pattern):
- className="inline-flex items-center gap-1 min-h-[32px] px-1 -mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"
+ className="inline-flex items-center gap-1 min-h-[44px] sm:min-h-[32px] px-2 sm:px-1 sm:-mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"

// Lines 348 & 356 (bookmark button — same fix):
- className="inline-flex items-center gap-0.5 min-h-[32px] px-1 -mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"
+ className="inline-flex items-center gap-0.5 min-h-[44px] sm:min-h-[32px] px-2 sm:px-1 sm:-mx-1 text-[10px] cursor-pointer hover:scale-110 active:scale-95 transition-transform"
```
- **Time**: 5 min (4 button instances)
- **Impact**: Eliminates mobile mis-taps on Explore page reactions

### 2. `/src/components/ui/ShareModal.tsx:295` — Missing background scroll lock
- **Issue**: Modal doesn't prevent background body scroll; users can scroll page while interacting with share options
- **Risk**: Low (focus trap already present; scroll lock is polish)
- **Patch**: Add useEffect hook after line 98 (existing modalRef useEffect):
```tsx
// After the existing focus-trap useEffect (line 183), add:
useEffect(() => {
  // Lock background scroll while modal is open
  const originalOverflow = document.body.style.overflow;
  document.body.style.overflow = "hidden";
  
  return () => {
    document.body.style.overflow = originalOverflow;
  };
}, []);
```
- **Time**: 3 min
- **Impact**: Prevents confusing scroll behavior on iOS Safari during share flow

### 3. `/src/components/explore/ExploreFilters.tsx:225` — Search input missing keyboard hints
- **Issue**: Search input uses generic `type="text"` instead of optimized `inputMode="search"`, preventing iOS from showing search key
- **Risk**: Low (usability, not functional)
- **Patch**:
```tsx
// Line 225-240 (search input element):
<input
  type="text"
  value={localQuery}
  onChange={(e) => setLocalQuery(e.target.value)}
  aria-label="Search team reports"
+ inputMode="search"
+ spellCheck="false"
+ autoCorrect="off"
  placeholder={...}
  className="..."
/>
```
- **Time**: 2 min
- **Impact**: Mobile keyboards show search action button instead of return; improves UX signal

### Key Findings
1. **Reaction tap targets**: Explore card like/bookmark buttons exploit negative margins to compress space; this backfires on mobile where every pixel matters.
2. **Modal scroll isolation**: ShareModal's portal + backdrop + fixed inset-0 trap focus correctly but don't lock background, causing scroll chaining on iOS.
3. **Keyboard optimization**: Low-hanging fruit — explore search and form inputs don't set `inputMode` or spellCheck, missing native mobile affordances.
