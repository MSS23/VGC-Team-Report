#### N-1 · Single-character key shortcuts cannot be disabled or remapped

**File:** `src/hooks/useSlideNavigation.ts:97-180` (bindings), `src/hooks/useSlideSystem.ts:96-98` (always enabled)
**WCAG:** **2.1.4 Character Key Shortcuts — Level A (new in WCAG 2.1)**
**Severity:** High

A `window`-level `keydown` listener binds unmodified single characters across the entire report viewer:

```
useSlideNavigation.ts:143  "d"/"D" → toggle dark mode
                    :146  "f"/"F" → toggle fullscreen
                    :149  "?"     → show help
                    :152  "p"/"P" → toggle presentation
                    :156  "e"/"E" → toggle creator/edit mode
                    :161  "h"/"H" → hide/show current slide
                    :166  "["     → move slide earlier
                    :170  "]"     → move slide later
                    :174  "1"-"9" → jump to slide
```

The only guard is `useSlideNavigation.ts:108-120`, which exempts `TEXTAREA / INPUT / SELECT / contenteditable` and roles `radio|slider|listbox|menu`. It does **not** exempt anything else, and the hook is enabled unconditionally once a report loads (`useSlideSystem.ts:98`, `enabled: !!analysis`). There is no settings toggle anywhere in the codebase.

2.1.4 requires one of: the shortcut can be turned off, it can be remapped to include a modifier, or it is active only while the relevant component has focus. None holds. Consequences: a speech-input user saying "delete" or "next" fires `e`/`h`/`d`; a screen-reader user in browse mode who types a first-letter navigation key silently toggles edit mode or reorders the creator's slides (`[` / `]` mutate saved state).

**Fix:** gate the letter/bracket/digit branches behind a focus check — only act when `document.activeElement` is `document.body` or is inside the slide region and carries `data-slide-navigation-ignore` — **and** add a persisted "Keyboard shortcuts" on/off switch (the Navbar menu already has a settings list at `src/components/layout/Navbar.tsx:744-925`). Arrow/Home/End can stay: they are navigation keys, not character keys, and are outside 2.1.4.

#### N-2 · Delete control is a `<span onClick>` nested inside a `<button>` — unreachable by keyboard

**File:** `src/components/report/MatchupPlanSlide.tsx:552-558`
**WCAG:** **2.1.1 Keyboard (A)**, 4.1.2 Name Role Value (A)
**Severity:** High

```tsx
{!isReadOnly && canDelete && (
  <span
    onClick={(e) => { e.stopPropagation(); onDelete(); }}
```

#### N-3 · The scrolling slide region is not keyboard-scrollable

**Files:** `src/app/page.tsx:1126-1141` (region), `src/hooks/useSlideNavigation.ts:127-136` (arrow keys)
**WCAG:** **2.1.1 Keyboard (A)**
**Severity:** High

The slide body is its own scroll container on ≥ sm:

```
src/app/page.tsx:1134
  … sm:h-[calc(100dvh-var(--nav-height)-var(--bottom-nav-height,3.5rem))] sm:overflow-y-auto sm:scrollbar-thin …
```

It has `role="region"` and `aria-label` (`page.tsx:1129-1132`) but **no `tabIndex`**, so a keyboard user cannot focus it, and `useSlideNavigation.ts:127-136` `preventDefault()`s ArrowUp/ArrowDown at the window level to change slides. Home/End are likewise consumed (`:135-142`). Net effect on desktop: content that overflows the fixed-height slide (long `SpeedTierChart` rows, long calc lists on `PokemonDetailSlide`, the `MatchupSheet` table) can only be reached by Tab-ing to an interactive descendant that happens to scroll into view. Slides whose overflow is plain text/SVG are simply unreachable.

**Fix:** add `tabIndex={0}` to the region div at `page.tsx:1128` (it already has an accessible name, so this is a legitimate focusable scroll container per the ARIA APG), and in `useSlideNavigation.ts` return early from the Arrow branch when `e.target` is — or is contained by — an element with `data-slide-scroll` that still has room to scroll (`scrollTop > 0` for Up, `scrollTop + clientHeight < scrollHeight` for Down). Slide changes then happen only at the ends of the scroll, which also matches the touch behaviour.

#### N-12 · The walkthrough swallows Enter and Space globally, so its own buttons cannot be activated

**File:** `src/components/ui/WalkthroughOverlay.tsx:62-75`
**WCAG:** 2.1.1 Keyboard (A), 3.2.2 On Input (A)
**Severity:** Medium

```tsx
const NAV_KEYS = new Set(["Escape", "Enter", " ", "ArrowRight", "ArrowDown", "ArrowLeft", "ArrowUp"]);
const handleKey = (e: KeyboardEvent) => {
  if (!NAV_KEYS.has(e.key)) return;
  e.preventDefault();
  e.stopImmediatePropagation();
  …
};
window.addEventListener("keydown", handleKey, { capture: true });
```

Because this listens in the **capture** phase on `window` and calls `stopImmediatePropagation()`, Enter and Space never reach any focused element while the tour is open. Escape is the only reliable exit. The tour also has no focus trap, so Tab wanders behind the 9998-z backdrop into the inert page.

**Fix:** skip the handler when `e.target` is inside `tooltipRef.current` (let the real buttons handle their own Enter/Space), and add a focus trap scoped to the tooltip.

#### N-16 · Skip-link target is not focusable

**Severity:** Low

`<a href="#main-content">` points at `<div id="main-content">{children}</div>`. #### N-18 · Framer Motion animations ignore `prefers-reduced-motion`

**WCAG:** 2.3.3 Animation from Interactions (AAA) — plus the project's own reduced-motion standard in `CLAUDE.md` / `ui-ux-pro-max`
**Severity:** Low

`globals.css:811-818` clamps CSS `animation-duration`/`transition-duration` to 0.01 ms under `prefers-reduced-motion: reduce`, which covers the `animate-fade-in` / `animate-slide-in-right` utilities. It does **not** affect Motion, which drives inline transforms from JS. Thirteen components animate through Motion and only one checks the preference:

* Honours it: `src/components/explore/ExploreFilters.tsx:6,130` (`useReducedMotion`).
* Does not: `src/components/input/PasteInput.tsx:253-264` (homepage sprite entrance), `:268-273` (title), `:288-295` (Champions banner); `src/components/explore/ReportCard.tsx:163-170`; `src/components/explore/SpotlightCard.tsx:99-104`; `src/components/explore/ExploreContent.tsx`; `src/components/explore/ExploreEmpty.tsx`; `src/app/champions/[pokemon]/MegaLandingContent.tsx`; `src/app/changelog/ChangelogContent.tsx`; `src/app/feedback/FeedbackContent.tsx`; `src/app/dashboard/profile/page.tsx`; `src/components/social/CreatorProfile.tsx`; `src/components/ui/WhatsNewModal.tsx`.

#### N-20 · `ThemePicker` swatches expose no selected state and no group name

**File:** `src/components/ui/ThemePicker.tsx:17-21` (label), `:44-59` (buttons)
