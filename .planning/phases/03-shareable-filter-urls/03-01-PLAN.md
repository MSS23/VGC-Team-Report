    - Test 3: Calling a setter updates the URL via replaceState

    - Test 5: Default values (sort="newest", searchCategory="all", empty strings, false) do NOT appear in URL

  <action>
    Create `src/hooks/useExploreUrlSync.ts` exporting a `useExploreUrlSync()` hook.

    The hook:
    1. On mount, reads `window.location.search` to parse initial filter values using URLSearchParams.
    2. Returns the same shape as ExploreContent's current state: `{ query, sort, searchCategory, regulation, eventType, archetype, species, placement, followingOnly }` plus setters for each (e.g., `setQuery`, `setSort`, etc.).
    3. Each setter updates React state AND calls `window.history.replaceState({}, "", newUrl)` with updated URLSearchParams. Use `replaceState` not `pushState` to avoid polluting history on every keystroke.
    4. Only include non-default params in the URL. Defaults: query="" sort="newest" searchCategory="all" regulation="" eventType="" archetype="" species="" placement="" followingOnly=false.
    5. URL param keys MUST match the existing API param keys used in fetchReports: `q`, `sort`, `searchType`, `regulation`, `eventType`, `archetype`, `species`, `placement`, `following` (value "1" for true).

    Implementation details:
    - Use `useState` for each filter, initialized from URL params on first render.
    - Create a single `updateUrl` helper that builds URLSearchParams from current state and calls replaceState.
    - Use `useEffect` that runs on every state change to sync state -> URL (debounce is NOT needed since replaceState is synchronous and cheap).
    - Import `SearchCategory` type from `@/components/explore/ExploreFilters`.
    - Export the return type as `ExploreUrlSyncResult` for downstream use.

    For the test file, use a lightweight approach: test the URL parsing/building logic by extracting pure functions `parseFiltersFromUrl(searchString: string)` and `buildUrlSearch(filters: FilterState)` and testing those directly. This avoids needing to mock window/React hooks in tests.
