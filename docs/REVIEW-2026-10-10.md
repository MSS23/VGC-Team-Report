# Review pass: 2026-10-10

## What the project does

This is a VGC team write-up tool. You paste a Showdown team and get a shareable, slide-style report: sets, notes, speed tiers, coverage, damage calcs, threat matrix and matchup plans. Around the reports sit a community layer (explore, comments, follows, collaborators) and SEO landing pages for Pokémon Champions. The product is mature and under active development (Reg M-C support, threat matrix, guest links and collab presence all landed in the last few weeks). Security and DB-cost hardening from `IMPROVEMENTS.md` is largely done.

## What changed

1. **Speed tiers: modifier order now matches the game.** `calcSpeed` floored Scarf/Booster, then paralysis, then Tailwind, each as a separate step. The game chains Scarf and Tailwind into one modifier and applies paralysis last. With odd speeds the old code was off by one, for example 101 Spe Scarf + Tailwind showed 302 instead of 303, and paralysis + Tailwind showed 100 instead of 101. In VGC those are speed-tie-deciding errors. The math moved to `calcBattleSpeed` in `src/lib/analysis/stat-calculator.ts`, with regression tests.
2. **SEO: removed the site-wide canonical and robots from `app/layout.tsx`.** The homepage now sets its own canonical in `app/page.tsx`. Verified in the build output: home, faq and ev-to-sp keep correct canonicals, `/compare` and 404 keep only `noindex`.
3. **`/s/<id>` returns a real 404 for missing or deleted reports.** It calls `notFound()` in both `generateMetadata` and the page, and uses `unstable_rethrow` so the existing DB-error fallbacks still work.
4. **Rewrote the README.** It replaces the create-next-app boilerplate with what the app is, the stack, minimum env vars, scripts and the deploy model.

### Verification

`npm run typecheck` passes. `npm test` passes: 60 files and 501 tests, 496 before plus 5 new. `next build` passes. `eslint` shows 36 errors before and after.
